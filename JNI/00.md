# Thread Communication in JNI — Simple Guide
### The Core Problem
```
┌─────────────────────────────────────────────────────────────┐
│                    THE PROBLEM                              │
│                                                             │
│  Java/Kotlin threads      ←──?──→      Native C++ threads   │
│  (Managed by ART)                      (Created by pthread) │
│                                                             │
│  • Have JNIEnv*                        • NO JNIEnv*         │
│  • Can call Java                       • Cannot call Java   │
│  • GC aware                            • GC unaware         │
│                                                             │
│  HOW DO THEY TALK TO EACH OTHER?                           │
└─────────────────────────────────────────────────────────────┘
```

## Understanding the Problem

When you have an Android app with NDK, you're dealing with **two different worlds**:

### Java/Kotlin World (Managed by ART)

- Threads created by `Thread()` or coroutines.
- Each thread automatically gets a `JNIEnv*` pointer.
- Garbage collector tracks all objects.
- Can freely call Java methods and access Java objects.

### Native C++ World

- Threads created by `pthread_create()`.
- **NO** automatic `JNIEnv*` — cannot call Java by default.
- GC doesn't know about these threads.
- Can only work with raw C/C++ data.

> **The challenge is:** How do these two worlds communicate?

---

## Solution 1: AttachCurrentThread (Native → Java)

### What is it?

When a native thread (created by `pthread`) needs to call Java code, it must first
**attach itself to the JVM**. This gives the thread a `JNIEnv*` pointer, allowing
it to interact with Java objects and methods.

### How it Works?
```
Native thread wants to call Java code:

┌─────────────────────────────────────────────────────────────┐
│                                                             │
│  Native Thread                         ART / JVM            │
│  (pthread)                                                  │
│      │                                                      │
│      │ ① AttachCurrentThread()                              │
│      │────────────────────────────────►│                    │
│      │                                 │ Register thread    │
│      │◄────────────────────────────────│ with ART           │
│      │         JNIEnv* received                             │
│      │                                                      │
│      │ ② Use JNIEnv* to call Java                          │
│      │────────────────────────────────►│                    │
│      │   env->CallVoidMethod(...)      │ Execute Java       │
│      │◄────────────────────────────────│ method             │
│      │                                                      │
│      │ ③ DetachCurrentThread()                              │
│      │────────────────────────────────►│                    │
│      │                                 │ Unregister thread  │
│      ×                                                      │
│   Thread exits                                              │
│                                                             │
└─────────────────────────────────────────────────────────────┘

```

### Step-by-Step Explanation

| Step | Action | Description |
|------|--------|-------------|
| **①** | `AttachCurrentThread()` | Native thread registers itself with ART. ART creates a `JNIEnv*` for this thread and starts tracking it for GC purposes. |
| **②** | Use `JNIEnv*` | Now the thread can call Java methods, access Java objects, create Java strings, etc. |
| **③** | `DetachCurrentThread()` | **CRITICAL:** Before the thread exits, it must detach. This tells ART to clean up resources. Forgetting this causes **memory leaks!** |

```cpp
// Global reference to JavaVM — stored once in JNI_OnLoad
JavaVM* g_jvm = nullptr;

// Store JavaVM when library loads
JNIEXPORT jint JNI_OnLoad(JavaVM* vm, void* reserved) {
    g_jvm = vm;  // Save for later use by native threads
    return JNI_VERSION_1_6;
}

// Function that runs on a native thread
void* nativeThreadFunc(void* arg) {
    JNIEnv* env;
    
    // ① ATTACH: Get JNIEnv* for this thread
    // Second parameter is thread name (optional)
    int result = g_jvm->AttachCurrentThread(&env, nullptr);
    if (result != JNI_OK) {
        // Failed to attach — cannot call Java
        return nullptr;
    }
    
    // ② USE: Now we can call Java methods!
    // Find the Java class
    jclass callbackClass = env->FindClass("com/example/MyCallback");
    
    // Get method ID for the callback method
    jmethodID onCompleteMethod = env->GetMethodID(
        callbackClass, 
        "onComplete",      // Method name
        "(I)V"             // Signature: takes int, returns void
    );
    
    // Call the Java method
    // (callbackObj must be a GlobalRef — explained later)
    env->CallVoidMethod(callbackObj, onCompleteMethod, 100);
    
    // ③ DETACH: Clean up before thread exits
    // NEVER forget this — causes memory leaks!
    g_jvm->DetachCurrentThread();
    
    return nullptr;
}

// Start the native thread from JNI
extern "C" JNIEXPORT void JNICALL
Java_com_example_MyClass_startNativeThread(JNIEnv* env, jobject thiz) {
    pthread_t thread;
    pthread_create(&thread, nullptr, nativeThreadFunc, nullptr);
    pthread_detach(thread);  // Let it run independently
}

```

### When to Use

- ✅ Native thread needs to **call back into Java** (progress updates, callbacks).
- ✅ Native thread needs to **access Java objects**.
- ✅ Native thread needs to **throw Java exceptions**.

### Pitfalls to Avoid

| Pitfall | Problem | Solution |
|---------|---------|----------|
| **Forgetting `DetachCurrentThread()`** | Memory leak, ART keeps tracking dead thread | Always detach in `finally` or destructor |
| **Using wrong `JNIEnv*`** | Crash — each thread has its own | Never share `JNIEnv*` between threads |
| **Attaching too frequently** | Performance overhead | Attach once, keep attached while needed |



## Solution 2: Shared Memory + Synchronization

### What is it?

Both Java and native threads can access the **same memory region**. They use
**locks (mutexes)** to prevent race conditions where both threads try to
read/write simultaneously.

### How it Works?
```
Both threads access shared data with locks:

┌───────────────────────────────────────────────────────────────┐
│                                                               │
│   Java Thread              Shared Memory           Native     │
│                                                    Thread     │
│       │                    ┌──────────┐               │       │
│       │     write          │  Data    │     read      │       │
│       │───────────────────►│  Buffer  │◄──────────────│       │
│       │                    │          │               │       │
│       │                    │  Mutex   │               │       │
│       │                    │  (Lock)  │               │       │
│       │                    └──────────┘               │       │
│       │                                               │       │
│   Uses                                            Uses        │
│   synchronized             pthread_mutex_lock()               │
│   or Lock                  pthread_mutex_unlock()             │
│                                                               │
└───────────────────────────────────────────────────────────────┘

```

### Step-by-Step Explanation

| Step | Java Side | Native Side |
|------|-----------|-------------|
| **1** | Acquire lock (`synchronized` or `ReentrantLock`) | `pthread_mutex_lock(&mutex)` |
| **2** | Read/write shared data | Read/write shared data |
| **3** | Release lock (automatic or `.unlock()`) | `pthread_mutex_unlock(&mutex)` |

### The Synchronization Flow
```
Timeline showing mutex protection:

Time    Java Thread                 Native Thread
────    ───────────                 ─────────────
  │
  │     ┌─ Lock mutex ──┐
  │     │ Write data    │           [Waiting for lock...]
  │     │ data = 42     │                   │
  │     └─ Unlock ──────┘                   │
  │                                         │
  │                             ┌─ Lock mutex ──┐
  │     [Waiting...]            │ Read data     │
  │           │                 │ x = data (42) │
  │           │                 └─ Unlock ──────┘
  │
  ▼
```

### Code Example
#### Native Side (C++):
```cpp
#include <pthread.h>
#include <jni.h>

// Shared data structure
struct SharedData {
    int frameCount;
    float audioLevel;
    bool isProcessing;
    pthread_mutex_t mutex;  // Protects all fields above
};

// Global shared data
SharedData g_sharedData;

// Initialize mutex (call once at startup)
void initSharedData() {
    g_sharedData.frameCount = 0;
    g_sharedData.audioLevel = 0.0f;
    g_sharedData.isProcessing = false;
    pthread_mutex_init(&g_sharedData.mutex, nullptr);
}

// Native thread writes data
void* processingThread(void* arg) {
    while (g_sharedData.isProcessing) {
        // Simulate processing work
        float newLevel = computeAudioLevel();
        
        // ── CRITICAL SECTION START ──
        pthread_mutex_lock(&g_sharedData.mutex);
        
        g_sharedData.frameCount++;
        g_sharedData.audioLevel = newLevel;
        
        pthread_mutex_unlock(&g_sharedData.mutex);
        // ── CRITICAL SECTION END ──
        
        usleep(16000);  // ~60fps
    }
    return nullptr;
}

// JNI function: Java reads the shared data
extern "C" JNIEXPORT jfloat JNICALL
Java_com_example_AudioProcessor_getAudioLevel(JNIEnv* env, jobject thiz) {
    float level;
    
    // ── CRITICAL SECTION START ──
    pthread_mutex_lock(&g_sharedData.mutex);
    
    level = g_sharedData.audioLevel;
    
    pthread_mutex_unlock(&g_sharedData.mutex);
    // ── CRITICAL SECTION END ──
    
    return level;
}

// JNI function: Java writes to shared data
extern "C" JNIEXPORT void JNICALL
Java_com_example_AudioProcessor_startProcessing(JNIEnv* env, jobject thiz) {
    pthread_mutex_lock(&g_sharedData.mutex);
    g_sharedData.isProcessing = true;
    pthread_mutex_unlock(&g_sharedData.mutex);
    
    // Start native processing thread
    pthread_t thread;
    pthread_create(&thread, nullptr, processingThread, nullptr);
    pthread_detach(thread);
}
```

## Solution 3: Message Queue Pattern

### What is it?

A **thread-safe queue** where one thread puts messages and another thread takes them.
This **decouples the threads** — they don't need to wait for each other.

### How it Works?
```
Producer-Consumer with queue:

┌───────────────────────────────────────────────────────────────┐
│                                                               │
│  Java Thread                                    Native Thread │
│  (Producer)                                    (Consumer)     │
│      │                                              │         │
│      │ push                ┌────────────┐     poll │         │
│      │───────────────────►│   Queue    │◄─────────│         │
│      │                    │  ┌─┬─┬─┬─┐ │          │         │
│      │                    │  │A│B│C│D│ │          │         │
│      │                    │  └─┴─┴─┴─┘ │          │         │
│      │   notify           │   Mutex +  │   wait   │         │
│      │───────────────────►│   CondVar  │◄─────────│         │
│      │                    └────────────┘          │         │
│                                                               │
└───────────────────────────────────────────────────────────────┘

```

### Step-by-Step Explanation

| Step | Producer (Java Thread) | Consumer (Native Thread) |
|------|----------------------|--------------------------|
| **1** | Creates a message/task | Waits for messages (`wait`) |
| **2** | Locks queue | — |
| **3** | Pushes message to queue | — |
| **4** | Unlocks queue + signals (`notify`) | Wakes up from `wait` |
| **5** | — | Locks queue |
| **6** | — | Pops message from queue |
| **7** | — | Unlocks queue |
| **8** | — | Processes message |

### The Queue Flow
```
Timeline:

Java Thread              Queue              Native Thread
───────────             ─────              ─────────────
    │                    [ ]                    │
    │                                      wait (sleeping)
    │ push(A)            [A]                    │
    │ notify ─────────────────────────────► wake up
    │                                      pop() → A
    │ push(B)            [B]               process(A)
    │ push(C)            [B,C]                  │
    │                                      pop() → B
    │                    [C]               process(B)
    │                                      pop() → C
    │                    [ ]               process(C)
    │                                      wait (sleeping)
    ▼                                          ▼
```

### Code Example
#### Message Structure:

``` cpp
// Message types
enum class MessageType {
    PROCESS_FRAME,
    STOP,
    UPDATE_CONFIG
};

struct Message {
    MessageType type;
    int frameId;
    void* data;
    size_t dataSize;
};
```

#### Thread-Safe Queue (C++):
``` cpp
#include <queue>
#include <mutex>
#include <condition_variable>

class MessageQueue {
private:
    std::queue<Message> queue;
    std::mutex mutex;
    std::condition_variable condVar;
    bool running = true;

public:
    // Producer calls this (can be called from any thread)
    void push(const Message& msg) {
        {
            std::lock_guard<std::mutex> lock(mutex);
            queue.push(msg);
        }
        // Wake up waiting consumer
        condVar.notify_one();
    }
    
    // Consumer calls this (blocks until message available)
    bool pop(Message& msg) {
        std::unique_lock<std::mutex> lock(mutex);
        
        // Wait until queue has items OR we're shutting down
        condVar.wait(lock, [this] { 
            return !queue.empty() || !running; 
        });
        
        if (!running && queue.empty()) {
            return false;  // Shutdown signal
        }
        
        msg = queue.front();
        queue.pop();
        return true;
    }
    
    void shutdown() {
        {
            std::lock_guard<std::mutex> lock(mutex);
            running = false;
        }
        condVar.notify_all();  // Wake up all waiting threads
    }
};

// Global queue
MessageQueue g_messageQueue;

```

#### Consumer Thread (Native):
``` cpp
void* consumerThread(void* arg) {
    JNIEnv* env;
    g_jvm->AttachCurrentThread(&env, nullptr);
    
    Message msg;
    while (g_messageQueue.pop(msg)) {  // Blocks until message available
        switch (msg.type) {
            case MessageType::PROCESS_FRAME:
                processFrame(msg.frameId, msg.data, msg.dataSize);
                break;
                
            case MessageType::UPDATE_CONFIG:
                updateConfiguration(msg.data);
                break;
                
            case MessageType::STOP:
                goto cleanup;  // Exit loop
        }
    }
    
cleanup:
    g_jvm->DetachCurrentThread();
    return nullptr;
}
```
#### JNI Interface (Producer):
``` cpp
// Java calls this to add work to the queue
extern "C" JNIEXPORT void JNICALL
Java_com_example_Processor_submitFrame(
    JNIEnv* env, jobject thiz, 
    jint frameId, jbyteArray frameData
) {
    // Copy Java array to native memory
    jsize len = env->GetArrayLength(frameData);
    jbyte* data = new jbyte[len];
    env->GetByteArrayRegion(frameData, 0, len, data);
    
    // Create message
    Message msg;
    msg.type = MessageType::PROCESS_FRAME;
    msg.frameId = frameId;
    msg.data = data;
    msg.dataSize = len;
    
    // Push to queue (non-blocking for Java thread)
    g_messageQueue.push(msg);
}
```

### When to Use

- ✅ **Asynchronous processing** — Java doesn't wait for native to finish.
- ✅ **Work distribution** — multiple items queued, processed in order.
- ✅ **Decoupled architecture** — producer and consumer work independently.

### Lock-Free Queues

For **ultra-low latency** (audio, games), consider **lock-free queues**:
``` cpp
#include <atomic>

// Single-producer, single-consumer lock-free queue
template<typename T, size_t Size>
class LockFreeQueue {
    T buffer[Size];
    std::atomic<size_t> head{0};
    std::atomic<size_t> tail{0};
    
public:
    bool push(const T& item) {
        size_t currentTail = tail.load(std::memory_order_relaxed);
        size_t nextTail = (currentTail + 1) % Size;
        
        if (nextTail == head.load(std::memory_order_acquire)) {
            return false;  // Queue full
        }
        
        buffer[currentTail] = item;
        tail.store(nextTail, std::memory_order_release);
        return true;
    }
    
    bool pop(T& item) {
        size_t currentHead = head.load(std::memory_order_relaxed);
        
        if (currentHead == tail.load(std::memory_order_acquire)) {
            return false;  // Queue empty
        }
        
        item = buffer[currentHead];
        head.store((currentHead + 1) % Size, std::memory_order_release);
        return true;
    }
};

```

## Solution 4: Android Handler + Looper

### What is it?

Android's **Handler** and **Looper** mechanism allows posting messages/runnables to a
specific thread's message queue. Native threads can use this to **safely update the UI**
(which must happen on the main thread).

### How it Works?
``` 
Native thread posts to Java Handler:

┌───────────────────────────────────────────────────────────────┐
│                                                               │
│   Native Thread                              Main Thread      │
│        │                                     (UI Thread)      │
│        │                                          │           │
│        │  ① AttachCurrentThread()                 │           │
│        │                                          │           │
│        │  ② Get Handler reference                 │           │
│        │                                          │           │
│        │  ③ handler.post(Runnable)                │           │
│        │─────────────────────────────────────────►│           │
│        │                                   ┌──────┴──────┐   │
│        │                                   │   Looper    │   │
│        │                                   │  ┌───────┐  │   │
│        │                                   │  │Message│  │   │
│        │                                   │  │ Queue │  │   │
│        │                                   │  └───────┘  │   │
│        │                                   └──────┬──────┘   │
│        │                                          │           │
│        │                              ④ Runnable executes    │
│        │                                 on UI thread        │
│                                                               │
└───────────────────────────────────────────────────────────────┘
```

### Understanding Android's Threading Model
``` 
┌─────────────────────────────────────────────────────────────────┐
│                    ANDROID MAIN THREAD                          │
│                                                                 │
│  Looper.loop() runs continuously:                               │
│                                                                 │
│  while (true) {                                                 │
│      Message msg = messageQueue.next();  // Blocks if empty    │
│      msg.target.dispatchMessage(msg);    // Execute message    │
│  }                                                              │
│                                                                 │
│  ┌─────────────────────────────────────────────────────────┐   │
│  │                  MESSAGE QUEUE                           │   │
│  │                                                          │   │
│  │   ┌─────┐   ┌─────┐   ┌─────┐   ┌─────┐   ┌─────┐      │   │
│  │   │ Msg │──►│ Msg │──►│ Msg │──►│ Msg │──►│ Msg │      │   │
│  │   │  1  │   │  2  │   │  3  │   │  4  │   │  5  │      │   │
│  │   └─────┘   └─────┘   └─────┘   └─────┘   └─────┘      │   │
│  │      ▲                                                   │   │
│  │      │                                                   │   │
│  │   Handler.post() adds messages here                     │   │
│  └─────────────────────────────────────────────────────────┘   │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### Step-by-Step Explanation

| Step | Description |
|------|-------------|
| **①** | Native thread attaches to JVM to get `JNIEnv*`. |
| **②** | Gets a reference to the `Handler` (passed from Java, stored as `GlobalRef`). |
| **③** | Creates a `Runnable` and posts it via `Handler.post()`. |
| **④** | Main thread's `Looper` picks up the message and executes the `Runnable`. |

### Code Example

**Java/Kotlin Side:**


``` cpp
    env->DeleteGlobalRef(g_processor);
```

### When to Use

- ✅ **UI updates from native threads** — the primary use case.
- ✅ **Callback to specific thread** — not just main thread.

### Why Not Just Call Java Methods Directly?
```
❌ WRONG: Calling UI methods from native thread

Native Thread                          Main Thread (UI)
     │                                       │
     │ env->CallVoidMethod(                  │
     │     textView, setTextMethod, str)     │
     │──────────────X CRASH! ────────────────│
     │                                       │
     │ Android UI is NOT thread-safe!        │
     │ Only main thread can touch UI.        │

Native Thread                          Main Thread (UI)
     │                                       │
     │ handler.post(Runnable)                │

     │                                  Run on main thread:
     │                                  textView.setText(str)
     │                                  ✅ Safe!
```

## Solution 5: Pipe / File Descriptor

### What is it?

A **pipe** is an operating system mechanism for **inter-process communication (IPC)**
that also works between threads. Data written to one end can be read from the other
end. It's a low-level, efficient way to transfer data.

### How it Works?
```
Low-level communication via pipe:

┌───────────────────────────────────────────────────────────────┐
│                                                               │
│   Java Thread                                  Native Thread  │
│       │                                             │         │
│       │                    ┌──────────┐             │         │
│       │     write()        │   Pipe   │    read()   │         │
│       │───────────────────►│  fd[0]───┼────────────►│         │
│       │                    │  fd[1]   │             │         │
│       │                    └──────────┘             │         │
│       │                                             │         │
│       │              (Kernel managed)               │         │
│       │              Blocking or non-blocking       │         │
│                                                               │
└───────────────────────────────────────────────────────────────┘

```
### Understanding Pipes
```
┌─────────────────────────────────────────────────────────────────┐
│                         PIPE INTERNALS                          │
│                                                                 │
│   fd[0] ─────────────────────────────────────────► fd[1]       │
│   (Read end)          Kernel Buffer           (Write end)       │
│                                                                 │
│   ┌─────────────────────────────────────────────────────────┐  │
│   │                    KERNEL BUFFER                         │  │
│   │                                                          │  │
│   │   ┌────┬────┬────┬────┬────┬────┬────┬────┬────┐       │  │
│   │   │ D  │ A  │ T  │ A  │    │    │    │    │    │       │  │
│   │   └────┴────┴────┴────┴────┴────┴────┴────┴────┘       │  │
│   │     ▲                               ▲                   │  │
│   │   Read position               Write position            │  │
│   │                                                          │  │
│   └─────────────────────────────────────────────────────────┘  │
│                                                                 │
│   • write(fd[1], data, len) → copies data to kernel buffer     │
│   • read(fd[0], buf, len)   → copies data from kernel buffer   │
│   • Blocking: read() waits if buffer empty                      │
│   • Blocking: write() waits if buffer full                      │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### Code Example
#### Native Side (Create and Use Pipe):
``` cpp
#include <unistd.h>  // pipe, read, write
#include <fcntl.h>   // fcntl for non-blocking

// Pipe file descriptors
int g_pipeFd[2];  // [0]=read end, [1]=write end

// Message structure for pipe
struct PipeMessage {
    int type;
    int dataSize;
    // Variable-length data follows...
};

// Initialize pipe
extern "C" JNIEXPORT jint JNICALL
Java_com_example_PipeComm_initPipe(JNIEnv* env, jobject thiz) {
    if (pipe(g_pipeFd) == -1) {
        return -1;  // Failed to create pipe
    }
    
    // Optional: Make read end non-blocking
    int flags = fcntl(g_pipeFd[0], F_GETFL, 0);
    fcntl(g_pipeFd[0], F_SETFL, flags | O_NONBLOCK);
    
    return 0;  // Success
}

// Return read file descriptor to Java (for FileInputStream)
extern "C" JNIEXPORT jint JNICALL
Java_com_example_PipeComm_getReadFd(JNIEnv* env, jobject thiz) {
    return g_pipeFd[0];
}

// Native thread writes to pipe
void* producerThread(void* arg) {
    for (int i = 0; i < 100; i++) {
        PipeMessage msg;
        msg.type = 1;  // Data message
        msg.dataSize = sizeof(int);
        
        // Write header
        write(g_pipeFd[1], &msg, sizeof(PipeMessage));
        
        // Write data
        int data = i * 10;
        write(g_pipeFd[1], &data, sizeof(int));
        
        usleep(100000);  // 100ms
    }
    
    // Send end message
    PipeMessage endMsg;
    endMsg.type = 0;  // End signal
    endMsg.dataSize = 0;
    write(g_pipeFd[1], &endMsg, sizeof(PipeMessage));
    
    return nullptr;
}

// Start producer thread
extern "C" JNIEXPORT void JNICALL
Java_com_example_PipeComm_startProducer(JNIEnv* env, jobject thiz) {
    pthread_t thread;
    pthread_create(&thread, nullptr, producerThread, nullptr);
    pthread_detach(thread);
}

// Cleanup
extern "C" JNIEXPORT void JNICALL
Java_com_example_PipeComm_closePipe(JNIEnv* env, jobject thiz) {
    close(g_pipeFd[0]);
    close(g_pipeFd[1]);
}

```

#### Java Side (Read from Pipe):
``` java
class PipeComm {
    private external fun initPipe(): Int
    private external fun getReadFd(): Int
    private external fun startProducer()
    private external fun closePipe()
    
    fun start() {
        if (initPipe() != 0) {
            throw RuntimeException("Failed to create pipe")
        }
        
        // Start native producer
        startProducer()
        
        // Read from pipe in Java thread
        thread {
            val fd = getReadFd()
            val fis = FileInputStream(FileDescriptor().apply {
                // Use reflection or ParcelFileDescriptor to set fd
            })
            
            val headerBuffer = ByteArray(8)  // type(4) + dataSize(4)
            
            while (true) {
                // Read header
                fis.read(headerBuffer)
                val type = ByteBuffer.wrap(headerBuffer, 0, 4)
                    .order(ByteOrder.LITTLE_ENDIAN).int
                val dataSize = ByteBuffer.wrap(headerBuffer, 4, 4)
                    .order(ByteOrder.LITTLE_ENDIAN).int
                
                if (type == 0) break  // End signal
                
                // Read data
                val dataBuffer = ByteArray(dataSize)
                fis.read(dataBuffer)
                val value = ByteBuffer.wrap(dataBuffer)
                    .order(ByteOrder.LITTLE_ENDIAN).int
                
                Log.d("PipeComm", "Received: $value")
            }
            
            fis.close()
            closePipe()
        }
    }
    
    companion object {
        init { System.loadLibrary("pipecomm") }
    }
}
```

### When to Use

- ✅ **Large data transfer** — streaming audio/video data.
- ✅ **Existing pipe-based code** — porting from Linux/Unix.
- ✅ **Non-JNI communication** — minimal Java involvement.

### Pros and Cons

| Pros | Cons |
|------|------|
| Very low overhead | Lower level, more code |
| Kernel-managed buffering | No built-in message framing |
| Works with `select`/`poll`/`epoll` | Must handle partial reads/writes |
| Unidirectional (simple model) | Need two pipes for bidirectional |

## Solution 6: ALooper (Android Native Looper)

### What is it?

Android provides a native event loop mechanism called **ALooper**. It's similar to
Java's `Handler`/`Looper` but works entirely in **native code**. Great for
**native-to-native communication** without touching Java.

### How it Works
```
Native-to-native with Android's native event loop:

┌───────────────────────────────────────────────────────────────┐
│                                                               │
│   Native Thread 1                          Native Thread 2    │
│   (Producer)                               (Consumer)         │
│        │                                        │             │
│        │                   ┌───────────┐        │             │
│        │   ALooper_wake()  │  ALooper  │  ALooper_pollOnce()  │
│        │──────────────────►│           │◄───────│             │
│        │                   │  Event    │        │             │
│        │                   │   Queue   │        │             │
│        │                   └───────────┘        │             │
│        │                                        │             │
│        │              (No JNI needed!)          │             │
│                                                               │
└───────────────────────────────────────────────────────────────┘
```
### Understanding ALooper
```
┌─────────────────────────────────────────────────────────────────┐
│                       ALOOPER MECHANISM                         │
│                                                                 │
│   ALooper is built on top of Linux epoll                       │
│                                                                 │
│   ┌─────────────────────────────────────────────────────────┐  │
│   │                    CONSUMER THREAD                       │  │
│   │                                                          │  │
│   │   looper = ALooper_prepare(0)                            │  │
│   │                                                          │  │
│   │   while (running) {                                      │  │
│   │       int result = ALooper_pollOnce(                     │  │
│   │           -1,          // timeout: -1 = wait forever     │  │
│   │           &outFd,      // triggered file descriptor      │  │
│   │           &outEvents,  // events (ALOOPER_EVENT_INPUT)   │  │
│   │           &outData     // user data                      │  │
│   │       );                                                 │  │
│   │                                                          │  │
│   │       if (result == ALOOPER_POLL_CALLBACK) {             │  │
│   │           // Callback was invoked                         │  │
│   │       }                                                  │  │
│   │   }                                                      │  │
│   └─────────────────────────────────────────────────────────┘  │
│                                                                 │
│   ┌─────────────────────────────────────────────────────────┐  │
│   │                   PRODUCER THREAD                        │  │
│   │                                                          │  │
│   │   // Add file descriptor to looper                       │  │
│   │   ALooper_addFd(looper, pipe_fd, ALOOPER_POLL_CALLBACK,  │  │
│   │                 ALOOPER_EVENT_INPUT, callback, userData); │  │
│   │                                                          │  │
│   │   // Write to pipe to trigger callback                   │  │
│   │   write(pipe_fd, data, len);                             │  │
│   │                                                          │  │
│   │   // Or simply wake the looper                           │  │
│   │   ALooper_wake(looper);                                  │  │
│   └─────────────────────────────────────────────────────────┘  │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### Code Example
``` cpp
#include <android/looper.h>
#include <unistd.h>

// Global looper reference
ALooper* g_looper = nullptr;
int g_pipeFd[2];

// Callback when data is available on pipe
int looperCallback(int fd, int events, void* data) {
    if (events & ALOOPER_EVENT_INPUT) {
        char buffer[256];
        ssize_t len = read(fd, buffer, sizeof(buffer) - 1);
        if (len > 0) {
            buffer[len] = '\0';
            __android_log_print(ANDROID_LOG_INFO, "ALooper", 
                "Received: %s", buffer);
        }
    }
    return 1;  // Continue listening (0 = remove fd from looper)
}

// Consumer thread with ALooper
void* consumerThread(void* arg) {
    // Prepare looper for this thread
    g_looper = ALooper_prepare(ALOOPER_PREPARE_ALLOW_NON_CALLBACKS);
    
    // Create pipe for communication
    pipe(g_pipeFd);
    
    // Add pipe read end to looper
    ALooper_addFd(
        g_looper,
        g_pipeFd[0],                    // File descriptor to monitor
        ALOOPER_POLL_CALLBACK,          // Identifier
        ALOOPER_EVENT_INPUT,            // Events to watch
        looperCallback,                 // Callback function
        nullptr                         // User data
    );
    
    // Event loop
    while (true) {
        int result = ALooper_pollOnce(
            -1,        // Infinite timeout
            nullptr,   // outFd
            nullptr,   // outEvents
            nullptr    // outData
        );
        
        if (result == ALOOPER_POLL_ERROR) {
            break;
        }
    }
    
    // Cleanup
    ALooper_removeFd(g_looper, g_pipeFd[0]);
    close(g_pipeFd[0]);
    close(g_pipeFd[1]);
    
    return nullptr;
}

// Producer thread sends messages
void* producerThread(void* arg) {
    // Wait for consumer to set up
    while (g_looper == nullptr) {
        usleep(10000);
    }
    
    for (int i = 0; i < 10; i++) {
        char msg[64];
        snprintf(msg, sizeof(msg), "Message %d", i);
        
        // Write to pipe — triggers looperCallback in consumer
        write(g_pipeFd[1], msg, strlen(msg));
        
        sleep(1);
    }
    
    return nullptr;
}

// JNI entry point
extern "C" JNIEXPORT void JNICALL
Java_com_example_ALooperDemo_start(JNIEnv* env, jobject thiz) {
    pthread_t consumer, producer;
    pthread_create(&consumer, nullptr, consumerThread, nullptr);
    pthread_create(&producer, nullptr, producerThread, nullptr);
}
```

### When to Use

- ✅ **Pure native communication** — no Java involvement.
- ✅ **Event-driven native code** — sensors, file watchers.
- ✅ **Integration with Android native APIs** — `ASensor`, `AInputQueue`.

### Rule Details
#### Rule 1: JNIEnv* is Thread-Local
```
┌─────────────────────────────────────────────────────────────┐
│                                                             │
│   Thread A                         Thread B                 │
│   ┌─────────────┐                  ┌─────────────┐         │
│   │ JNIEnv* envA│                  │ JNIEnv* envB│         │
│   │ (valid here)│                  │ (valid here)│         │
│   └─────────────┘                  └─────────────┘         │
│         │                                │                  │
│         │    ❌ NEVER DO THIS:           │                  │
│         │    envA used in Thread B       │                  │
│         └──────────X────────────────────►│                  │
│                    CRASH!                                   │
│                                                             │
│   ✅ CORRECT: Each thread gets its own JNIEnv*             │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```
#### Rule 3: GlobalRef vs LocalRef
``` cpp
// ❌ WRONG: Local reference used across threads
jobject g_callback;  // Global variable

void jniMethod(JNIEnv* env, jobject callback) {
    g_callback = callback;  // LocalRef! Invalid in other threads
}

void* nativeThread(void*) {
    // g_callback is INVALID here — undefined behavior / crash
    env->CallVoidMethod(g_callback, method);  // 💥
}

// ✅ CORRECT: Use GlobalRef for cross-thread objects
jobject g_callback;

void jniMethod(JNIEnv* env, jobject callback) {
    g_callback = env->NewGlobalRef(callback);  // GlobalRef! Safe
}

void* nativeThread(void*) {
    JNIEnv* env;
    g_jvm->AttachCurrentThread(&env, nullptr);
    
    // g_callback is valid here
    env->CallVoidMethod(g_callback, method);  // ✅ Works!
    
    g_jvm->DetachCurrentThread();
}

void cleanup(JNIEnv* env) {
    env->DeleteGlobalRef(g_callback);  // Don't forget to clean up!
    g_callback = nullptr;
}
```

### RAII Wrapper for Attach/Detach
``` cpp
// Automatically detaches when object goes out of scope
class JNIThreadAttacher {
    JavaVM* jvm;
    JNIEnv* env;
    bool attached;
    
public:
    JNIThreadAttacher(JavaVM* vm) : jvm(vm), env(nullptr), attached(false) {
        int status = jvm->GetEnv((void**)&env, JNI_VERSION_1_6);
        
        if (status == JNI_EDETACHED) {
            if (jvm->AttachCurrentThread(&env, nullptr) == JNI_OK) {
                attached = true;  // We attached it, we must detach
            }
        }
        // If already attached, env is valid, attached remains false
    }
    
    ~JNIThreadAttacher() {
        if (attached) {
            jvm->DetachCurrentThread();
        }
    }
    
    JNIEnv* getEnv() { return env; }
};

// Usage — automatic cleanup!
void* nativeThread(void*) {
    JNIThreadAttacher attacher(g_jvm);
    JNIEnv* env = attacher.getEnv();
    
    if (env) {
        // Use env safely...
        env->CallVoidMethod(...);
    }
    
    // Destructor automatically calls DetachCurrentThread() if needed
    return nullptr;
}
```
