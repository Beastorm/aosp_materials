# How Kernel Uses Device Tree — Simple & Short

## One Line Answer

```
DT     = Hardware Menu Card
Kernel = Waiter who reads it and serves
Drivers = Chefs who cook specific dishes
```

---

## Big Picture

```
BOOTLOADER
    │
    │  "Hey Kernel, here is the hardware list (DTB)"
    │  Passes DTB address in CPU register (x3)
    ▼
KERNEL
    │
    ├── Step 1: READ the DTB
    ├── Step 2: UNDERSTAND what hardware exists
    ├── Step 3: FIND driver for each hardware
    └── Step 4: INITIALIZE each hardware via driver
```

---

## Step 1: Kernel Reads DTB

```
BEFORE:                        AFTER:
[binary bytes]      →→→       /
0xd00dfeed                    ├── cpus
0x00005000                    │   └── cpu@0
...                           ├── memory
                              └── soc
                                  ├── uart@14000000
                                  ├── i2c@15000000
                                  └── gpio@13000000

Function: unflatten_device_tree()
```

---

## Step 2: Kernel Creates Devices from DT Nodes

```
DT NODE:                    KERNEL DEVICE:
uart@14000000 {    →→→     platform_device
    compatible =            name: "14000000.serial"
      "example,uart";       has: registers, IRQ info
    reg = <0x14000000>;     linked to: DT node
    status = "okay";
};

SKIP if status = "disabled"  ← No device created

Function: of_platform_populate()
```

---

## Step 3: Kernel Matches Device to Driver

```
DEVICE has:                DRIVER has:
compatible =               of_match_table = {
 "example,uart"              "example,uart"  ← MATCH!
                           }

Kernel compares → MATCH FOUND → call probe()

  device.compatible == driver.compatible
               │
           MATCHED!
```

---

## Step 4: Driver `probe()` Reads DT Properties

```
DT:                          DRIVER reads:
reg = <0x14000000 0x100>  →  base address to access HW
interrupts = <0 33 4>     →  which IRQ line to use
clocks = <&clk 10>        →  which clock to enable
status = "okay"           →  device is enabled

After reading → Driver initializes hardware
After init   → Hardware is READY TO USE
```

---

## Complete Flow

```
1. BOOTLOADER loads DTB file
        │
        ▼
2. KERNEL gets DTB address (x3 register)
        │
        ▼
3. KERNEL reads DTB → makes tree in memory
        │
        ▼
4. KERNEL walks tree → creates device for each "okay" node
        │
        ▼
5. DRIVER registers (has of_match_table)
        │
        ▼
6. KERNEL matches device ↔ driver by compatible string
        │
        ▼
7. DRIVER probe() called → reads DT → inits hardware
        │
        ▼
8. HARDWARE IS READY ✅
        │
        ▼
9. /proc/device-tree/ exposed → userspace can read DT
```

---

## What Kernel Reads from DT — Key Properties

```
PROPERTY          KERNEL USES IT FOR
─────────────────────────────────────────────────
compatible      → Find matching driver
reg             → Hardware register address
interrupts      → Which IRQ line device uses
clocks          → Which clock to enable
status          → Should I enable this device?
memory/reg      → How much RAM exists
chosen/bootargs → Kernel command line
```

## After Boot — Kernel Still Uses DT

```bash
# DT exposed at /proc/device-tree/

$ cat /proc/device-tree/model
  → "My Phone v1"

$ cat /proc/device-tree/chosen/bootargs
  → "console=ttyS0 androidboot.hardware=myphone"
```

Init process reads this to set system properties. HALs read this to know hardware config.

## One Slide Summary

```
┌─────────────────────────────────────────────────────────┐
│                                                         │
│  DTB file                                               │
│    │  bootloader passes address                         │
│    ▼                                                    │
│  Kernel reads DTB                                       │
│    │  creates device for each "okay" DT node            │
│    ▼                                                    │
│  Device + Driver MATCHED by compatible string           │
│    │  probe() called                                    │
│    ▼                                                    │
│  Driver reads reg, irq, clocks from DT                 │
│    │  initializes hardware                              │
│    ▼                                                    │
│  Hardware READY ✅                                      │
│                                                         │
│  KEY RULE:                                              │
│  status = "okay"     → device created, driver probed   │
│  status = "disabled" → device SKIPPED entirely         │
│                                                         │
└─────────────────────────────────────────────────────────┘
```
