## 1. What is hidl-gen?

`hidl-gen` is the AOSP tool that takes your `.hal` interface definition and generates all the C++ boilerplate needed for Binder IPC. You **do not copy generated files** to your implementation location. Instead, hidl-gen produces two distinct categories of output — **glue files** and **scaffold files** — which serve different purposes and live in different places.

---

## 2. Glue Files vs Scaffold Files

### 🔧 Glue Files — "The Plumbing"

Glue files are **auto-generated code that handles Binder IPC communication**. They serialize/deserialize arguments across process boundaries. You never touch them — they are rebuilt from `.hal` every time.

Think of them as the **electrical wiring inside your wall** — standardized, always there, you just plug into it.

**Example — given this `.hal`:**

```java
// ICamera.hal
interface ICamera {
    takePicture() generates (bool success);
};
```

**hidl-gen produces these glue files automatically:**

```cpp
// ICamera.h — pure abstract interface
struct ICamera : public IBase {
    virtual Return<bool> takePicture() = 0;   // pure virtual, no body
};

// BnHwCamera.h — Binder Native (server-side wiring)
// Deserializes the Binder parcel, calls your implementation
struct BnHwCamera : BnInterface<ICamera> {
    ::android::status_t onTransact(uint32_t code, const Parcel& data, ...);
};

// BpHwCamera.h — Binder Proxy (client-side wiring)
// Serializes arguments into a Binder parcel, sends across process
struct BpHwCamera : BpInterface<ICamera> {
    Return<bool> takePicture() override;
};
```

| Rule | Detail |
|------|--------|
| Edit? | ❌ Never |
| Rebuilt? | ✅ Every build from `.hal` |
| Lives in? | `out/soong/.intermediates/...` (build output) |
| In git? | ❌ No |

---

### 🏗️ Scaffold Files — "The Empty House"

Scaffold files are the **starting template for your implementation**. hidl-gen generates them once as a skeleton with `TODO` stubs. You own and fill them in.

Think of them as a **house with walls and roof already built** — the structure is there, you furnish the inside.

**hidl-gen generates this scaffold:**

```cpp
// Camera.h — your implementation class header
struct Camera : public ICamera {
    Return<bool> takePicture() override;   // stub — you implement this
};

// Camera.cpp — your implementation body
Return<bool> Camera::takePicture() {
    // TODO implement
    return false;
}

// service.cpp — HAL service entry point
int main() {
    Camera* camera = new Camera();
    camera->registerAsService();
}
```

**After you fill it in:**

```cpp
// Camera.cpp — your real implementation
Return<bool> Camera::takePicture() {
    int fd = open("/dev/video0", O_RDWR);
    ioctl(fd, VIDIOC_STREAMON, ...);
    // capture frame, save to buffer...
    return true;
}
```

| Rule | Detail |
|------|--------|
| Edit? | ✅ Always |
| Rebuilt? | ❌ Written once, maintained by you |
| Lives in? | `hardware/interfaces/.../default/` or `vendor/...` |
| In git? | ✅ Yes |

---

### Summary Comparison

| | Glue Files | Scaffold Files |
|---|---|---|
| **Analogy** | Electrical wiring in the wall | Empty room with marked spots |
| **You edit?** | ❌ Never | ✅ Always |
| **Generated by** | `hidl-gen` at build time | `hidl-gen` once (scaffold only) |
| **Source of truth** | `.hal` file | Your `.cpp/.h` files |
| **In git repo?** | ❌ No | ✅ Yes |
| **Compiled into** | `android.hardware.camera@1.0.so` | `camera@1.0-service` binary |

## 3. How Glue and Scaffold Connect

Even though they live in different places, they are stitched together through **three binding points**.

### Binding Point 1 — C++ Inheritance

Your scaffold class inherits from the glue's abstract interface:

```cpp
// Glue (ICamera.h) defines the contract
struct ICamera : public IBase {
    virtual Return<bool> takePicture() = 0;   // pure virtual
};

// Scaffold (Camera.h) fulfills the contract
#include <android/hardware/camera/1.0/ICamera.h>  // includes glue

struct Camera : public ICamera {        // YOUR class inherits glue
    Return<bool> takePicture() override; // you provide the body
};
```

### Binding Point 2 — Android.bp `shared_libs`

```json
cc_binary {
    name: "android.hardware.camera@1.0-service",
    srcs: ["Camera.cpp", "service.cpp"],   // your scaffold

    shared_libs: [
        "android.hardware.camera@1.0",     // ← links against glue .so
        "libhidlbase",
        "libutils",
    ],
}
```

This one line does two things:
- Adds the glue's generated header path to compiler include search path
- Adds `-landroid.hardware.camera@1.0` at link stage

### Binding Point 3 — Service Registration

```cpp
// service.cpp
Camera* cam = new Camera();        // your implementation object
cam->registerAsService("default"); // BnHwCamera wraps it automatically
                                   // registers with HwServiceManager
```

### Runtime Call Flow

```
CLIENT PROCESS                        SERVER PROCESS (your HAL)
──────────────────                    ───────────────────────────

sp<ICamera> cam =                     Camera::takePicture() {
  ICamera::getService();                 ioctl(fd, VIDIOC_...);
                                         return true;
cam->takePicture();                    }
      │                                        ▲
      ▼                                        │
 BpHwCamera::takePicture()            BnHwCamera::onTransact()
  [GLUE — proxy]                       [GLUE — native]
  serialize args                        deserialize args
  send over Binder ──────────────────►  call Camera::takePicture()
  wait for result  ◄──────────────────  return result
```

### Layer Diagram

```
┌─────────────────────────────────────────────┐
│         CLIENT (framework / app)            │
│   cam->takePicture()                        │
└────────────────────┬────────────────────────┘
                     │ calls
┌────────────────────▼────────────────────────┐
│     BpHwCamera  (GLUE — proxy)              │  packages args into Binder parcel
│     auto-generated, in ICamera@1.0.so       │
└────────────────────┬────────────────────────┘
                     │ Binder IPC (crosses process boundary)
┌────────────────────▼────────────────────────┐
│     BnHwCamera  (GLUE — native)             │  unpacks parcel, dispatches call
│     auto-generated, in ICamera@1.0.so       │
└────────────────────┬────────────────────────┘
                     │ virtual dispatch (C++ vtable)
┌────────────────────▼────────────────────────┐
│     Camera : public ICamera                 │  YOUR scaffold implementation
│     Camera.cpp — your real HAL code         │
└────────────────────┬────────────────────────┘
                     │ direct calls
┌────────────────────▼────────────────────────┐
│     /dev/video0  (kernel driver)            │
└─────────────────────────────────────────────┘
```

## 4. Physical Locations in the Tree

### Glue Files — Build Output (never in source repo)

```
out/soong/.intermediates/
└── hardware/interfaces/camera/1.0/
    ├── android.hardware.camera@1.0_genc++/
    │   └── gen/android/hardware/camera/1.0/
    │       ├── ICamera.cpp
    │       └── ICameraAll.cpp
    │
    └── android.hardware.camera@1.0_genc++_headers/
        └── gen/android/hardware/camera/1.0/
            ├── ICamera.h          ← glue header
            ├── BnHwCamera.h       ← glue header
            ├── BpHwCamera.h       ← glue header
            └── BsCamera.h         ← glue header
```

Source of truth for glue (what lives in repo):
```
hardware/interfaces/camera/1.0/
    ├── ICamera.hal      ← only this is committed to git
    └── Android.bp       ← generated by update-makefiles.sh
```

### Scaffold Files — Source Tree (in repo, owned by you)

```
hardware/interfaces/camera/1.0/default/
    ├── Camera.h          ← your scaffold (in repo)
    ├── Camera.cpp        ← your scaffold (in repo)
    ├── service.cpp       ← your scaffold (in repo)
    └── Android.bp        ← build file (in repo)
```

Or for vendor-specific HALs:
```
vendor/<company>/hardware/camera/
    ├── Camera.h
    ├── Camera.cpp
    ├── service.cpp
    └── Android.bp
```

## 5. Step-by-Step Implementation

### Step 1 — Write Your `.hal` Interface

```
hardware/interfaces/camera/1.0/ICamera.hal
```

```java
package android.hardware.camera@1.0;

interface ICamera {
    takePicture() generates (bool success);
    setZoom(int32_t level) generates (bool success);
};
```

---

### Step 2 — Run `update-makefiles.sh`

Generates `Android.bp` for the interface library:

```bash
$ ./hardware/interfaces/update-makefiles.sh
```

Result:
```
hardware/interfaces/camera/1.0/
    ├── ICamera.hal       ← you wrote this
    └── Android.bp        ← auto-generated (hidl_interface target)
```

---

### Step 3 — Run `hidl-gen` to Generate Scaffold

```bash
$ hidl-gen -o hardware/interfaces/camera/1.0/default \
           -Lc++-impl \
           -randroid.hardware:hardware/interfaces \
           android.hardware.camera@1.0
```

Result:
```
hardware/interfaces/camera/1.0/default/
    ├── Camera.h        ← scaffold (TODO stubs)
    ├── Camera.cpp      ← scaffold (TODO stubs)
    └── Android.bp      ← scaffold build file
```

---

### Step 4 — Fill In Your Implementation

```cpp
// Camera.cpp — BEFORE (generated scaffold)
Return<bool> Camera::takePicture() {
    // TODO implement
    return false;
}

// Camera.cpp — AFTER (your real implementation)
Return<bool> Camera::takePicture() {
    int fd = open("/dev/video0", O_RDWR);
    if (fd < 0) return false;
    ioctl(fd, VIDIOC_STREAMON, ...);
    close(fd);
    return true;
}
```

---

### Step 5 — Verify `Android.bp`

```json
cc_binary {
    name: "android.hardware.camera@1.0-service",
    relative_install_path: "hw",
    init_rc: ["android.hardware.camera@1.0-service.rc"],

    srcs: [
        "Camera.cpp",
        "service.cpp",
    ],

    shared_libs: [
        "android.hardware.camera@1.0",   // glue library
        "libhidlbase",
        "libutils",
        "liblog",
    ],
}
```

---

### Step 6 — Write the `init.rc` File

```
# android.hardware.camera@1.0-service.rc

service vendor.camera-hal-1-0 /vendor/bin/hw/android.hardware.camera@1.0-service
    class hal
    user cameraserver
    group camera
```

---

### Step 7 — Register in `manifest.xml`

```xml
<!-- device/<company>/<device>/manifest.xml -->

<hal format="hidl">
    <name>android.hardware.camera</name>
    <transport>hwbinder</transport>
    <version>1.0</version>
    <interface>
        <name>ICamera</name>
        <instance>default</instance>
    </interface>
</hal>
```

---

### Step 8 — Build

```bash
$ source build/envsetup.sh
$ lunch <your_target>
$ make android.hardware.camera@1.0-service
```

---

### Step 9 — Verify on Device

```bash
# Check service is registered with HwServiceManager
$ adb shell lshal | grep camera

# Check process is running
$ adb shell ps -A | grep camera
```

### All Steps at a Glance

```
Step 1  →  Write ICamera.hal
Step 2  →  update-makefiles.sh        (generates Android.bp for .hal)
Step 3  →  hidl-gen -Lc++-impl        (generates scaffold: Camera.h/cpp, service.cpp)
Step 4  →  Fill in Camera.cpp         (your real hardware code)
Step 5  →  Fix Android.bp             (verify srcs + shared_libs)
Step 6  →  Write .rc file             (service startup config)

Step 9  →  lshal / ps verify          (confirm running)
```
