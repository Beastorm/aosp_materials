## 1. What is HAL (Hardware Abstraction Layer)?

The Hardware Abstraction Layer (HAL) defines a standard interface for hardware vendors to implement. It allows the Android framework to be agnostic of lower-level driver implementations.

```
┌─────────────────────────────────┐
│       Android Framework         │
│    (Java/Kotlin APIs)           │
├─────────────────────────────────┤
│       HAL Interface             │
│  (Standard contract between     │
│   framework and hardware)       │
├─────────────────────────────────┤
│    Vendor Implementation        │
│   (Hardware-specific code)      │
├─────────────────────────────────┤
│     Linux Kernel / Drivers      │
└─────────────────────────────────┘
```

> Reference: source.android.com/docs/core/architecture/hal

## 2. HAL Evolution Over the Years

### Timeline of HAL Architecture Changes

```
Android Version    HAL Type              Key Change
─────────────────────────────────────────────────────────
1.0 - 7.x         Legacy/Conventional   In-process, dlopen()
8.0 (Oreo)        Treble (HIDL)         Binderized HALs
10 (Q)            HIDL + AIDL HALs      AIDL HALs introduced
11 (R)            AIDL preferred        AIDL stable for HALs
13 (T)            AIDL mandatory        New HALs must use AIDL
14 (U)            AIDL only             HIDL deprecated
```

### Phase 1: Legacy HAL (Pre-Android 8.0)

Legacy HALs were shared libraries (`.so`) loaded directly into the calling process.

```c
// hardware/libhardware/include/hardware/hardware.h

typedef struct hw_module_t {
    uint32_t tag;                // HARDWARE_MODULE_TAG
    uint16_t module_api_version;
    uint16_t hal_api_version;
    const char *id;              // e.g., "camera", "audio"
    const char *name;
    const char *author;
    struct hw_module_methods_t *methods;
    void *dso;                   // handle to shared library
    uint32_t reserved[32-7];
} hw_module_t;

typedef struct hw_module_methods_t {
    int (*open)(const struct hw_module_t* module,
                const char* id,
                struct hw_device_t** device);
} hw_module_methods_t;

typedef struct hw_device_t {
    uint32_t tag;                // HARDWARE_DEVICE_TAG
    uint32_t version;
    struct hw_module_t* module;
    int (*close)(struct hw_device_t* device);
} hw_device_t;
```

**Example: Legacy Vibrator HAL**

```c
// hardware/libhardware/modules/vibrator/vibrator.c

static int vibrator_open(const hw_module_t* module, const char* id,
                         hw_device_t** device) {
    vibrator_device_t *vibradev = calloc(1, sizeof(vibrator_device_t));

    vibradev->common.tag = HARDWARE_DEVICE_TAG;
    vibradev->common.module = (hw_module_t *) module;
    vibradev->common.close = vibrator_close;
    vibradev->vibrator_on = vibrator_on;
    vibradev->vibrator_off = vibrator_off;

    *device = (hw_device_t *) vibradev;
    return 0;
}

static struct hw_module_methods_t vibrator_module_methods = {
    .open = vibrator_open,
};

struct hw_module_t HAL_MODULE_INFO_SYM = {
    .tag = HARDWARE_MODULE_TAG,
    .id = VIBRATOR_HARDWARE_MODULE_ID,
    .name = "Default vibrator HAL",
    .methods = &vibrator_module_methods,
};
```

**Problems with Legacy HAL:**
- Loaded into framework process (crash affects framework)
- No clear vendor/framework separation
- OTA updates required vendor cooperation
- No versioning enforcement

---

### Phase 2: Project Treble and HIDL (Android 8.0+)

Project Treble separated the vendor implementation from the Android OS framework.

```
Before Treble:                    After Treble:
┌──────────────┐                 ┌──────────────┐
│  Framework   │                 │  Framework   │
│  + HAL code  │                 ├──────────────┤
│  (monolithic)│                 │ HIDL/Binder  │  ← Stable interface
├──────────────┤                 ├──────────────┤
│    Kernel    │                 │   Vendor     │  ← Can update independently
├──────────────┤                 ├──────────────┤
│   Hardware   │                 │    Kernel    │
└──────────────┘                 ├──────────────┤
                                 │   Hardware   │
                                 └──────────────┘
```

## 3. What is HIDL (HAL Interface Definition Language)?

HIDL is an interface description language (IDL) used to specify the interface between a HAL and its users. It was introduced in Android 8.0 to support Project Treble.

> Reference: source.android.com/docs/core/architecture/hidl

### HIDL File Structure

```
hardware/interfaces/
├── audio/
│   ├── 2.0/
│   │   ├── IDevice.hal
│   │   ├── IDevicesFactory.hal
│   │   ├── IStream.hal
│   │   ├── types.hal
│   │   └── Android.bp
│   └── 4.0/
├── camera/
│   ├── device/
│   │   └── 3.2/
│   └── provider/
│       └── 2.4/
├── vibrator/
│   ├── 1.0/
│   │   ├── IVibrator.hal
│   │   ├── types.hal
│   │   └── Android.bp
│   └── 1.1/
└── ...
```

### HIDL Naming Convention

```
// Fully Qualified Name (FQN)
android.hardware.vibrator@1.0::IVibrator

// Format:
// PACKAGE@MAJOR.MINOR::TYPE

// Examples:
android.hardware.camera.device@3.4::ICameraDeviceSession
android.hardware.audio@6.0::IDevice
android.hardware.power@1.3::IPower
android.hardware.health@2.1::IHealth
```

## 5. HAL Types (Binderized vs Passthrough)

### 5.1 Binderized HAL

HAL runs in its **own process**, communicating via Binder IPC.

```
┌──────────────┐          ┌──────────────┐
│  Framework   │  Binder  │  HAL Process │
│  Process     │◄────────►│  (Vendor)    │
│              │   IPC    │              │
└──────────────┘          └──────────────┘
```

```cpp
// hardware/interfaces/vibrator/1.0/default/service.cpp

#include <android/hardware/vibrator/1.0/IVibrator.h>
#include <hidl/LegacySupport.h>

using android::hardware::vibrator::V1_0::IVibrator;
using android::hardware::defaultPassthroughServiceImplementation;

int main() {
    return defaultPassthroughServiceImplementation<IVibrator>();
}
```

**VINTF Manifest entry:**

```xml
<!-- /vendor/etc/vintf/manifest.xml -->
<hal format="hidl">
    <name>android.hardware.vibrator</name>
    <transport>hwbinder</transport>
    <version>1.0</version>
    <interface>
        <name>IVibrator</name>
        <instance>default</instance>
    </interface>
</hal>
```

---

### 5.2 Passthrough HAL

HAL runs in the **same process** as the caller (for backward compatibility).

```
┌────────────────────────────────┐
│  Framework Process             │
│  ┌──────────────────────────┐  │
│  │  HAL Implementation      │  │
│  │  (loaded via dlopen)     │  │
│  └──────────────────────────┘  │
└────────────────────────────────┘
```

```cpp
sp<IVibrator> vibrator = IVibrator::getService(true /* getStub */);
// true = passthrough mode, loads .so directly
```

**Passthrough entry point:**

```cpp
extern "C" IVibrator* HIDL_FETCH_IVibrator(const char* /* name */) {
    return new Vibrator();
}
```

---

### 5.3 Same-Process HAL (SP-HAL)

Special HALs that **must** run in the same process (e.g., OpenGL, Vulkan, gralloc).

```
Same-process HALs (always passthrough):
- android.hardware.graphics.mapper
- android.hardware.graphics.allocator
- android.hardware.renderscript
- EGL / GLES / Vulkan implementations
```

---

### 5.4 Comparison Table

```
Feature              Binderized          Passthrough         Same-Process
─────────────────────────────────────────────────────────────────────────
Process isolation    Yes                 No                  No
Performance          IPC overhead        Direct call         Direct call
Crash isolation      Yes                 No                  No
Mandatory for        Most HALs           Legacy compat       Graphics
Transport            hwbinder            passthrough         passthrough
```

```cpp
public:

    Return<void> powerHint(PowerHint hint, int32_t data) override;
    Return<void> setFeature(Feature feature, bool activate) override;

```

```cpp
// hardware/interfaces/power/1.0/default/Power.cpp
#include "Power.h"
#include <android-base/logging.h>

namespace android::hardware::power::V1_0::implementation {

Return<void> Power::setInteractive(bool interactive) {
    LOG(INFO) << "setInteractive: " << interactive;
    set_interactive(interactive ? 1 : 0);
    return Void();
}

Return<void> Power::powerHint(PowerHint hint, int32_t data) {
    switch (hint) {
        case PowerHint::INTERACTION:
            power_hint_interaction(data);
            break;
        case PowerHint::LAUNCH:
            power_hint_launch(data);
            break;
        default:
            break;
    }
    return Void();
}

Return<void> Power::setFeature(Feature feature, bool activate) {
    switch (feature) {
        case Feature::POWER_FEATURE_DOUBLE_TAP_TO_WAKE:
            set_dt2w(activate);
            break;
    }
    return Void();
}

Return<void> Power::getPlatformLowPowerStats(
        getPlatformLowPowerStats_cb _hidl_cb) {
    hidl_vec<PowerStatePlatformSleepState> states;
    // Populate from /sys/power/...
    _hidl_cb(states, Status::SUCCESS);
    return Void();
}

}  // namespace
```

### 6.7 Client-Side Usage

```cpp
#include <android/hardware/power/1.0/IPower.h>

using android::hardware::power::V1_0::IPower;
using android::hardware::power::V1_0::PowerHint;

void usePowerHAL() {
    sp<IPower> power = IPower::getService();
    if (power == nullptr) {
        ALOGE("Failed to get Power HAL");
        return;
    }

    power->setInteractive(true);
    power->powerHint(PowerHint::INTERACTION, 500);

    power->getPlatformLowPowerStats(
        [](const hidl_vec<PowerStatePlatformSleepState>& states,
           Status status) {
            if (status == Status::SUCCESS) {
                for (const auto& state : states) {
                    ALOGI("Sleep state: %s, residency: %u ms",
                          state.name.c_str(),
                          state.residencyInMsecSinceBoot);
                }
            }
        });
}
```

## 7. HIDL Interface Versioning

### 7.1 Minor Version Update (Extension)

```hidl
// hardware/interfaces/vibrator/1.0/IVibrator.hal
package android.hardware.vibrator@1.0;

interface IVibrator {
    on(uint32_t timeoutMs)         generates (Status status);

// hardware/interfaces/vibrator/1.1/IVibrator.hal
package android.hardware.vibrator@1.1;

import @1.0::IVibrator;

interface IVibrator extends @1.0::IVibrator {
    // New methods added in 1.1
    perform_1_1(Effect_1_1 effect, EffectStrength strength)
        generates (Status status, uint32_t lengthMs);
};
```

### 7.2 Casting Between Versions

```cpp
#include <android/hardware/vibrator/1.0/IVibrator.h>
#include <android/hardware/vibrator/1.1/IVibrator.h>

using V1_0 = android::hardware::vibrator::V1_0;
using V1_1 = android::hardware::vibrator::V1_1;

void useVibrator() {
    // Try to get 1.1 first
    sp<V1_1::IVibrator> vibrator_1_1 = V1_1::IVibrator::getService();

    if (vibrator_1_1 != nullptr) {
        vibrator_1_1->perform_1_1(V1_1::Effect_1_1::HEAVY_CLICK,
                                   EffectStrength::STRONG);
    } else {
        sp<V1_0::IVibrator> vibrator_1_0 = V1_0::IVibrator::getService();
        if (vibrator_1_0 != nullptr) {
            vibrator_1_0->on(100);
        }
    }

    // castFrom for runtime checking
    sp<V1_0::IVibrator> base = V1_0::IVibrator::getService();
    sp<V1_1::IVibrator> extended = V1_1::IVibrator::castFrom(base);

    if (extended != nullptr) {
        // 1.1 is supported
    }
}
```

```cpp
// Vibrator.cpp
#include "Vibrator.h"
#include <android-base/logging.h>
#include <thread>

namespace aidl::android::hardware::vibrator {

ndk::ScopedAStatus Vibrator::getCapabilities(int32_t* _aidl_return) {
    *_aidl_return = IVibrator::CAP_ON_CALLBACK
                  | IVibrator::CAP_PERFORM_CALLBACK
                  | IVibrator::CAP_AMPLITUDE_CONTROL
                  | IVibrator::CAP_COMPOSE_EFFECTS;
    return ndk::ScopedAStatus::ok();
}

ndk::ScopedAStatus Vibrator::on(int32_t timeoutMs,
        const std::shared_ptr<IVibratorCallback>& callback) {
    LOG(INFO) << "Vibrator on for " << timeoutMs << "ms";

    if (callback != nullptr) {
        std::thread([=] {
            usleep(timeoutMs * 1000);
            callback->onComplete();
        }).detach();
    }
    return ndk::ScopedAStatus::ok();
}

ndk::ScopedAStatus Vibrator::setAmplitude(float amplitude) {
    if (amplitude <= 0.0f || amplitude > 1.0f) {
        return ndk::ScopedAStatus::fromExceptionCode(EX_ILLEGAL_ARGUMENT);
    }
    return ndk::ScopedAStatus::ok();
}

ndk::ScopedAStatus Vibrator::perform(Effect effect, EffectStrength strength,
        const std::shared_ptr<IVibratorCallback>& callback,
        int32_t* _aidl_return) {
    int32_t durationMs = 0;
    switch (effect) {
        case Effect::CLICK:        durationMs = 10;  break;
        case Effect::DOUBLE_CLICK: durationMs = 20;  break;
        case Effect::HEAVY_CLICK:  durationMs = 15;  break;
        default:
            return ndk::ScopedAStatus::fromExceptionCode(
                EX_UNSUPPORTED_OPERATION);
    }

    *_aidl_return = durationMs;

    if (callback != nullptr) {
        std::thread([=] {
            usleep(durationMs * 1000);
            callback->onComplete();
        }).detach();
    }
    return ndk::ScopedAStatus::ok();
}

}  // namespace
```

## 10. HIDL vs AIDL for HALs Comparison

```
Feature                    HIDL                      AIDL (Stable)
──────────────────────────────────────────────────────────────────────
File extension             .hal                      .aidl
Introduced                 Android 8.0               Android 11 (for HALs)
Transport                  hwbinder                  binder / vndbinder
Return style               generates()               return value + exceptions
Versioning                 @major.minor               Version integers
Status                     Deprecated (Android 14)    Active/Preferred
Enum backing type          Always specified           @Backing annotation
Struct                     struct keyword             parcelable keyword
Null safety                Not supported              @nullable annotation
Union                      safe_union                 union keyword
Error handling             Status enum return         ScopedAStatus/exceptions
Annotation                 Limited                    @VintfStability, etc.
```

### AIDL-specific features not in HIDL

```aidl
    }
```

## 12. HwBinder and Transport Mechanism

```
┌─────────────────────────────────────────────────────┐
│                    Framework                         │
│  ┌──────────────┐                                   │
│  │  Client Proxy │  (auto-generated BpXxx)          │
│  └──────┬───────┘                                   │
│         │                                            │
├─────────┼────────────────────────────────────────────┤
│         │  hwbinder IPC                              │
│         │  /dev/hwbinder                             │
│         │  (separate from /dev/binder)               │
├─────────┼────────────────────────────────────────────┤
│  ┌──────▼───────┐                                   │
│  │  Server Stub  │  (auto-generated BnXxx)          │
│  └──────┬───────┘                                   │
│  ┌──────▼───────┐                                   │
│  │ Implementation│  (Vendor code)                   │
│  └──────────────┘                                   │
│                     Vendor                           │
└─────────────────────────────────────────────────────┘
```

### Binder Domains in Android

```
/dev/binder       - Framework IPC (apps ↔ system_server)
/dev/hwbinder     - HAL IPC (framework ↔ HAL, HIDL)
/dev/vndbinder    - Vendor IPC (vendor ↔ vendor, AIDL HALs)
```

> Since Android 11, AIDL HALs use `/dev/binder` or `/dev/vndbinder` depending on configuration.

## 13. Code Generation (hidl-gen)

When you define `.hal` files, the `hidl-gen` tool generates:

```
Input: IFoo.hal
       types.hal

Output (auto-generated):
├── IFoo.h          # Interface header (abstract)
├── BpHwFoo.h       # Binder proxy (client-side)
├── BnHwFoo.h       # Binder native (server-side stub)
├── BsFoo.h         # Passthrough wrapper
├── FooAll.cpp      # Marshaling/unmarshaling code
└── types.h         # Types header
```

### Generation Commands

```bash
# Generate C++ sources from .hal files
hidl-gen -o output_dir \
    -L c++-sources \
    -r android.hardware:hardware/interfaces \
    android.hardware.vibrator@1.0

# Generate C++ headers
hidl-gen -o output_dir \
    -L c++-headers \
    -r android.hardware:hardware/interfaces \

# Generate Java source
hidl-gen -o output_dir \
    -L java \
    -r android.hardware:hardware/interfaces \
```

## 16. Migration: HIDL to AIDL

### Key Differences

```
HIDL                              →    AIDL
─────────────────────────────────────────────────────────
package a.b.c@1.0;                →    package a.b.c;
import a.b.c@1.0::IFoo;          →    import a.b.c.IFoo;
interface IFoo extends @1.0::IBar →    interface IFoo  (no extends)
vec<T>                            →    T[]
handle                            →    ParcelFileDescriptor
fmq_sync<T>                      →    (FMQ through separate lib)
bitfield<T>                       →    int (with const flags)
safe_union                        →    union

Return<void>                      →    ndk::ScopedAStatus
```
