## 1. What is HAL?

The **Hardware Abstraction Layer (HAL)** defines a standard interface for hardware vendors to implement, allowing the Android framework to remain agnostic of lower-level driver implementations.

```
┌─────────────────────────────────┐
│       Android Framework         │
│    (Java/Kotlin APIs)           │
├─────────────────────────────────┤
│       HAL Interface             │
│  (Standard contract between     │
│   framework and hardware)       │
├─────────────────────────────────┤
│    Vendor Implementation        │
│   (Hardware-specific code)      │
├─────────────────────────────────┤
│     Linux Kernel / Drivers      │
└─────────────────────────────────┘
```

> Reference: [source.android.com/docs/core/architecture/hal](https://source.android.com/docs/core/architecture/hal)

---

## 2. HAL Evolution Timeline

| Android Version | HAL Type | Key Change |
|---|---|---|
| 1.0 – 7.x | Legacy/Conventional | In-process, `dlopen()` |
| 8.0 (Oreo) | Treble / HIDL | Binderized HALs, Project Treble |
| 10 (Q) | HIDL + AIDL | AIDL HALs introduced |
| 11 (R) | AIDL preferred | Stable AIDL for HALs |
| 13 (T) | AIDL mandatory | All new HALs must use AIDL |
| 14 (U) | AIDL only | HIDL **deprecated** |

### Before vs After Treble

```
Before Treble:                    After Treble:
┌──────────────┐                 ┌──────────────┐
│  Framework   │                 │  Framework   │
│  + HAL code  │                 ├──────────────┤
│  (monolithic)│                 │ HIDL/Binder  │  ← Stable interface
├──────────────┤                 ├──────────────┤
│    Kernel    │                 │   Vendor     │  ← Updates independently
├──────────────┤                 ├──────────────┤
│   Hardware   │                 │    Kernel    │
└──────────────┘                 ├──────────────┤
                                 │   Hardware   │
                                 └──────────────┘
```

## 3. Legacy HAL

Legacy HALs were **shared libraries (`.so`)** loaded directly into the calling process via `dlopen()`.

### What a Legacy HAL Process Looks Like

```
┌─────────────────────────────────────────────────┐
│           system_server PROCESS                  │
│   ┌─────────────────┐                           │
│   │  Framework Code │                           │
│   └────────┬────────┘                           │
│            │  dlopen()                           │
│            ▼                                     │
│   ┌─────────────────┐                           │
│   │  HAL .so file   │  ← NOT a separate process │
│   │  libvibrator.so │    Just a shared library   │
│   └─────────────────┘                           │
└─────────────────────────────────────────────────┘
```

### Core Structs

```c
// hardware/libhardware/include/hardware/hardware.h

typedef struct hw_module_t {
    uint32_t tag;                // HARDWARE_MODULE_TAG
    uint16_t module_api_version;
    const char *id;              // e.g., "camera", "audio"
    const char *name;
    struct hw_module_methods_t *methods;
    void *dso;                   // handle to shared library
} hw_module_t;

typedef struct hw_module_methods_t {
    int (*open)(const struct hw_module_t* module,
                const char* id,
                struct hw_device_t** device);
} hw_module_methods_t;

typedef struct hw_device_t {
    uint32_t tag;                // HARDWARE_DEVICE_TAG
    uint32_t version;
    struct hw_module_t* module;
    int (*close)(struct hw_device_t* device);
} hw_device_t;
```

### Example: Legacy Vibrator HAL

```c
static int vibrator_open(const hw_module_t* module, const char* id,
                         hw_device_t** device) {
    vibrator_device_t *vibradev = calloc(1, sizeof(vibrator_device_t));
    vibradev->common.tag    = HARDWARE_DEVICE_TAG;
    vibradev->common.module = (hw_module_t *) module;
    vibradev->common.close  = vibrator_close;
    vibradev->vibrator_on   = vibrator_on;
    vibradev->vibrator_off  = vibrator_off;
    *device = (hw_device_t *) vibradev;
    return 0;
}

struct hw_module_t HAL_MODULE_INFO_SYM = {
    .tag     = HARDWARE_MODULE_TAG,
    .id      = VIBRATOR_HARDWARE_MODULE_ID,
    .name    = "Default vibrator HAL",
    .methods = &vibrator_module_methods,
};
```

### Problems with Legacy HAL

| Problem | Impact |
|---|---|
| Loaded into framework process | Camera crash → system_server crash → reboot |
| No vendor/framework separation | OTA update requires vendor cooperation |
| No versioning enforcement | ABI breaks silently |

## 4. HIDL

**HIDL (HAL Interface Definition Language)** is an IDL introduced in Android 8.0 to support Project Treble. It specifies a typed, versioned interface between a HAL and its users.

> Reference: [source.android.com/docs/core/architecture/hidl](https://source.android.com/docs/core/architecture/hidl)

---

### 4.1 File Structure & Naming

```
hardware/interfaces/
├── audio/
│   ├── 2.0/
│   │   ├── IDevice.hal
│   │   ├── types.hal
│   │   └── Android.bp
│   └── 4.0/
├── camera/
│   └── device/3.2/
├── vibrator/
│   ├── 1.0/
│   │   ├── IVibrator.hal
│   │   ├── types.hal
│   │   └── Android.bp
│   └── 1.1/
└── ...
```

**Fully Qualified Name (FQN) format:** `PACKAGE@MAJOR.MINOR::TYPE`

```
android.hardware.vibrator@1.0::IVibrator
android.hardware.camera.device@3.4::ICameraDeviceSession
android.hardware.audio@6.0::IDevice
```

### 4.3 Architecture Deep Dive

#### Interface Definition

```hidl
// hardware/interfaces/power/1.0/IPower.hal
package android.hardware.power@1.0;

interface IPower {
    setInteractive(bool interactive);
    powerHint(PowerHint hint, int32_t data);
    setFeature(Feature feature, bool activate);
    getPlatformLowPowerStats()
        generates (vec<PowerStatePlatformSleepState> states, Status status);
};
```

#### Default Implementation

```cpp
// Power.h
class Power : public IPower {
public:
    Return<void> setInteractive(bool interactive) override;
    Return<void> powerHint(PowerHint hint, int32_t data) override;
    Return<void> getPlatformLowPowerStats(
        getPlatformLowPowerStats_cb _hidl_cb) override;
};

// Power.cpp
Return<void> Power::setInteractive(bool interactive) {
    set_interactive(interactive ? 1 : 0);
    return Void();
}

Return<void> Power::getPlatformLowPowerStats(
        getPlatformLowPowerStats_cb _hidl_cb) {
    hidl_vec<PowerStatePlatformSleepState> states;
    // populate from /sys/power/...
    _hidl_cb(states, Status::SUCCESS);
    return Void();
}
```

#### Service Registration

```cpp
// service.cpp
int main() {
    configureRpcThreadpool(1, true);

    sp<IPower> power = new Power();
    android::status_t status = power->registerAsService();
    if (status != android::OK) return 1;

    joinRpcThreadpool();
    return 1;
}
```


### 4.4 Interface Versioning

#### Minor Version Extension

```hidl
// 1.0/IVibrator.hal
interface IVibrator {
    on(uint32_t timeoutMs)         generates (Status status);
    off()                           generates (Status status);
    setAmplitude(uint8_t amplitude) generates (Status status);
};

// 1.1/IVibrator.hal
interface IVibrator extends @1.0::IVibrator {
    perform_1_1(Effect_1_1 effect, EffectStrength strength)
        generates (Status status, uint32_t lengthMs);
};
```

#### Runtime Version Casting

```cpp
// Try 1.1 first, fall back to 1.0
sp<V1_1::IVibrator> v1_1 = V1_1::IVibrator::getService();
if (v1_1 != nullptr) {
    v1_1->perform_1_1(V1_1::Effect_1_1::HEAVY_CLICK, EffectStrength::STRONG);
} else {
    sp<V1_0::IVibrator> v1_0 = V1_0::IVibrator::getService();
    if (v1_0 != nullptr) v1_0->on(100);
}

// Runtime cast
sp<V1_0::IVibrator> base     = V1_0::IVibrator::getService();
sp<V1_1::IVibrator> extended = V1_1::IVibrator::castFrom(base);
if (extended != nullptr) { /* 1.1 supported */ }
```

## 5. HAL Types

### Binderized HAL — Separate Process

```
┌──────────────┐          ┌──────────────┐
│  Framework   │  Binder  │  HAL Daemon  │
│  Process     │◄────────►│  /vendor/bin │
└──────────────┘   IPC    └──────────────┘
```

VINTF manifest entry:

```xml
<hal format="hidl">
    <name>android.hardware.vibrator</name>
    <transport>hwbinder</transport>
    <version>1.0</version>
    <interface>
        <name>IVibrator</name>
        <instance>default</instance>
    </interface>
</hal>
```

### Passthrough HAL — Same Process (Compatibility Mode)

```
┌────────────────────────────────┐
│  Calling Process               │
│  ┌──────────────────────────┐  │
│  │  HAL impl (via dlopen)   │  │
│  └──────────────────────────┘  │
└────────────────────────────────┘
```

```cpp
// Request passthrough explicitly
sp<IVibrator> vibrator = IVibrator::getService(true /* getStub */);

// Passthrough entry point in vendor .so
extern "C" IVibrator* HIDL_FETCH_IVibrator(const char*) {
    return new Vibrator();
}
```

### Same-Process HAL (SP-HAL)

Always passthrough — performance-critical paths that **cannot** afford IPC overhead:

```
android.hardware.graphics.mapper
android.hardware.graphics.allocator
EGL / GLES / Vulkan implementations
```

### Comparison Table

| Feature | Binderized | Passthrough | Same-Process |
|---|---|---|---|
| Process isolation | ✅ Yes | ❌ No | ❌ No |
| Crash isolation | ✅ Yes | ❌ No | ❌ No |
| Performance | IPC overhead | Direct call | Direct call |
| Transport | hwbinder | passthrough | passthrough |
| Use case | Most HALs | Legacy compat | Graphics |

## 7. AIDL for HALs

From Android 13, **all new HALs must use AIDL**. HIDL is deprecated as of Android 14.

> Reference: [source.android.com/docs/core/architecture/aidl/aidl-hals](https://source.android.com/docs/core/architecture/aidl/aidl-hals)

### Interface Definition

```aidl
// android/hardware/vibrator/IVibrator.aidl
package android.hardware.vibrator;

@VintfStability
interface IVibrator {
    const int CAP_ON_CALLBACK      = 1 << 0;
    const int CAP_AMPLITUDE_CONTROL = 1 << 2;
    const int CAP_COMPOSE_EFFECTS  = 1 << 5;

    int  getCapabilities();
    void on(in int timeoutMs, in IVibratorCallback callback);
    void off();
    void setAmplitude(in float amplitude);
    int  perform(in Effect effect, in EffectStrength strength,
                 in IVibratorCallback callback);
    void compose(in CompositeEffect[] composite,
                 in IVibratorCallback callback);
}
```

### Types

```aidl
@VintfStability
@Backing(type="int")
enum Effect {
    CLICK = 0, DOUBLE_CLICK = 1, TICK = 2,
    THUD = 3,  POP = 4,          HEAVY_CLICK = 5,
}

@VintfStability
parcelable CompositeEffect {
    int delayMs;
    CompositePrimitive primitive;
    float scale;
}
```

### Implementation

```cpp
// Vibrator.h
class Vibrator : public BnVibrator {
public:
    ndk::ScopedAStatus getCapabilities(int32_t* _aidl_return) override;
    ndk::ScopedAStatus on(int32_t timeoutMs,
        const std::shared_ptr<IVibratorCallback>& callback) override;
    ndk::ScopedAStatus off() override;
    ndk::ScopedAStatus setAmplitude(float amplitude) override;
    ndk::ScopedAStatus perform(Effect effect, EffectStrength strength,
        const std::shared_ptr<IVibratorCallback>& callback,
        int32_t* _aidl_return) override;
};

// Vibrator.cpp
ndk::ScopedAStatus Vibrator::setAmplitude(float amplitude) {
    if (amplitude <= 0.0f || amplitude > 1.0f)
        return ndk::ScopedAStatus::fromExceptionCode(EX_ILLEGAL_ARGUMENT);
    return ndk::ScopedAStatus::ok();
}

ndk::ScopedAStatus Vibrator::perform(Effect effect, EffectStrength strength,
        const std::shared_ptr<IVibratorCallback>& callback,
        int32_t* _aidl_return) {
    int32_t durationMs = 0;
    switch (effect) {
        case Effect::CLICK:        durationMs = 10; break;
        case Effect::HEAVY_CLICK:  durationMs = 15; break;
        default:
            return ndk::ScopedAStatus::fromExceptionCode(EX_UNSUPPORTED_OPERATION);
    }
    *_aidl_return = durationMs;
    if (callback)
        std::thread([=] { usleep(durationMs * 1000); callback->onComplete(); }).detach();
    return ndk::ScopedAStatus::ok();
}
```

### Service Registration

```cpp
int main() {
    ABinderProcess_setThreadPoolMaxThreadCount(0);

    auto vibrator = ndk::SharedRefBase::make<Vibrator>();
    const std::string instance = std::string(Vibrator::descriptor) + "/default";

    binder_status_t status =
        AServiceManager_addService(vibrator->asBinder().get(), instance.c_str());
    CHECK_EQ(status, STATUS_OK);

    ABinderProcess_joinThreadPool();
    return EXIT_FAILURE;
}
```

## 8. HIDL vs AIDL Comparison

| Feature | HIDL | AIDL (Stable) |
|---|---|---|
| File extension | `.hal` | `.aidl` |
| Introduced | Android 8.0 | Android 11 (for HALs) |
| Transport | hwbinder | binder / vndbinder |
| Return style | `generates()` | return value + exceptions |
| Versioning | `@major.minor` | version integers |
| Status | **Deprecated (Android 14)** | Active / Preferred |
| Struct keyword | `struct` | `parcelable` |
| Null safety | Not supported | `@nullable` annotation |
| Union | `safe_union` | `union` |
| Error handling | Status enum return | `ScopedAStatus` / exceptions |
| Pointer type | `sp<IFoo>` | `std::shared_ptr<IFoo>` |
| String type | `hidl_string` | `std::string` |
| Vector type | `hidl_vec<T>` / `vec<T>` | `std::vector<T>` / `T[]` |
| File descriptor | `handle` | `ParcelFileDescriptor` |

### AIDL-Only Features

```aidl
// @nullable — not in HIDL
interface IFoo { @nullable Bar getBar(); }

// Nested types
@VintfStability
interface IFoo {
    @VintfStability
    parcelable Bar { int x; int y; }
    Bar getBar();
}

// Constants in interface
@VintfStability
interface IFoo {
    const int MAX_SIZE    = 256;
    const String NAME     = "default";
}

// ParcelFileDescriptor replaces handle
interface IFoo { ParcelFileDescriptor openFile(in String path); }
```

## 9. HwBinder and Transport Mechanism

### Binder Domains

| Device | Purpose |
|---|---|
| `/dev/binder` | Framework IPC (apps ↔ system_server) |
| `/dev/hwbinder` | HAL IPC (framework ↔ HIDL HAL) |
| `/dev/vndbinder` | Vendor IPC (vendor ↔ vendor, AIDL HALs) |

### Transport Architecture

```
┌─────────────────────────────────────────────────────┐
│                    Framework                         │
│  ┌──────────────┐                                   │
│  │  Client Proxy │  (auto-generated BpXxx)          │
│  └──────┬───────┘                                   │
├─────────┼────────────────────────────────────────────┤
│         │  hwbinder IPC  (/dev/hwbinder)             │
├─────────┼────────────────────────────────────────────┤
│  ┌──────▼───────┐                                   │
│  │  Server Stub  │  (auto-generated BnXxx)          │
│  └──────┬───────┘                                   │
│  ┌──────▼───────┐                                   │
│  │ Implementation│  (Vendor code)                   │
│  └──────────────┘                                   │
│                     Vendor                           │
└─────────────────────────────────────────────────────┘
```

## 10. Code Generation

`hidl-gen` auto-generates from `.hal` files:

| Generated File | Purpose |
|---|---|
| `IFoo.h` | Interface header (abstract) |
| `BpHwFoo.h` | Binder proxy (client-side) |
| `BnHwFoo.h` | Binder native stub (server-side) |
| `BsFoo.h` | Passthrough wrapper |
| `FooAll.cpp` | Marshaling / unmarshaling code |
| `types.h` | Types header |

```bash
# Generate C++ sources
hidl-gen -o output_dir -L c++-sources \
    -r android.hardware:hardware/interfaces \
    android.hardware.vibrator@1.0

# Generate C++ headers
hidl-gen -o output_dir -L c++-headers \
    -r android.hardware:hardware/interfaces \
    android.hardware.vibrator@1.0

# Generate implementation scaffold
hidl-gen -o hardware/interfaces/vibrator/1.0/default \
    -L c++-impl \
    -r android.hardware:hardware/interfaces \
    android.hardware.vibrator@1.0
```

### Android.bp for HIDL Interface Library

```
hidl_interface {
    name: "android.hardware.vibrator@1.0",
    root: "android.hardware",
    srcs: ["IVibrator.hal", "types.hal"],
    interfaces: ["android.hidl.base@1.0"],
    gen_java: true,
}
```

```cpp
    ndk::ScopedAStatus turnOff(LedColor color) override;
```

```cpp
// Led.cpp (key methods)
ndk::ScopedAStatus Led::setLed(LedColor color, int brightness) {
    if (!isValidColor(color))
        return ndk::ScopedAStatus::fromExceptionCodeWithMessage(
            EX_ILLEGAL_ARGUMENT, "Invalid LED color");
    if (!isValidBrightness(brightness))
        return ndk::ScopedAStatus::fromExceptionCodeWithMessage(
            EX_ILLEGAL_ARGUMENT, "Brightness must be 0–255");

    std::lock_guard<std::mutex> lock(mLock);
    stopBlinking(color);

    if (!writeBrightness(color, brightness))
        return ndk::ScopedAStatus::fromServiceSpecificError(
            -1, "Failed to write sysfs");

    mLedStates[color] = { brightness, false };
    return ndk::ScopedAStatus::ok();
}

bool Led::writeBrightness(LedColor color, int brightness) {
    auto it = kLedSysfsPaths.find(color);
    if (it == kLedSysfsPaths.end()) return false;
    return android::base::WriteStringToFile(
        std::to_string(brightness) + "\n", it->second);
}

void Led::blinkThread(LedColor color, int onMs, int offMs, int count) {
    int remaining = count;
    while (!mBlinkStop[color].load()) {
        writeBrightness(color, 255);
        std::this_thread::sleep_for(std::chrono::milliseconds(onMs));
        if (mBlinkStop[color].load()) break;
        writeBrightness(color, 0);
        std::this_thread::sleep_for(std::chrono::milliseconds(offMs));
        if (count != -1 && --remaining <= 0) break;
    }
}
```

## 15. Service Registries & Binder Domains

### Overview

```
┌─────────────────────────────────────────────────────────────────┐
│                      AOSP IPC Ecosystem                         │
│                                                                 │
│  ┌─────────────┐  ┌──────────────────┐  ┌──────────────────┐  │
│  │servicemanager│  │hwservicemanager  │  │vndservicemanager │  │
│  │             │  │                  │  │                  │  │
│  │ /dev/binder │  │ /dev/hwbinder    │  │ /dev/vndbinder   │  │
│  │             │  │                  │  │                  │  │
│  │ Apps ↔      │  │ Framework ↔ HAL  │  │ Vendor ↔ Vendor  │  │
│  │ Framework   │  │ (HIDL)           │  │ services         │  │
│  └─────────────┘  └──────────────────┘  └──────────────────┘  │
└─────────────────────────────────────────────────────────────────┘
```

### Why Three Binder Domains?

**Security** — Each domain has distinct SELinux rules. Apps cannot accidentally talk to vendor HALs.

**Performance** — Independent thread pools; HAL calls don't starve app IPC.

**Treble compliance** — Clear partition boundary enforced at the kernel level.

## 17. Binder Internals Deep Dive

### Transaction Data Structure

```cpp
struct binder_transaction_data {
    union {
        __u32 handle;       // target's handle in caller's space
        binder_uintptr_t ptr;
    } target;

    __u32 code;             // which method to call
    __u32 flags;            // oneway flag, etc.

    pid_t sender_pid;       // set by KERNEL — cannot be forged
    uid_t sender_euid;      // set by KERNEL — cannot be forged

    binder_size_t data_size;
    binder_size_t offsets_size;
};
```

### Handle Translation

```
Process A                  Kernel                  Process B
┌──────────┐              ┌────────┐              ┌──────────┐
│ IBinder  │              │ Binder │              │ IBinder  │
│ handle=5 │──────────────│ driver │──────────────│ handle=3 │
│          │   send ref   │ global │   new handle │          │
└──────────┘              │ table  │              └──────────┘

Each process sees a DIFFERENT handle for the same object.
Kernel maintains the global reference table and ref-counts.
Processes cannot guess each other's handles → secure by design.
```

### Thread Pool

```cpp
// Start thread pool:
ProcessState::self()->startThreadPool();
// Threads block in ioctl(BC_ENTER_LOOPER), waiting for calls

// Configure max threads:
ProcessState::self()->setThreadPoolMaxThreadCount(15);
// Kernel spawns new threads up to max when all are busy

// Main thread also serves:
IPCThreadState::self()->joinThreadPool();
```

### Full Transaction Flow

```
USER SPACE                            KERNEL
─────────────────────────────────────────────────────

Process A (Client)
  BpFoo::bar(args)
       │
       │  ioctl(BINDER_WRITE_READ)     ──────────────►  Binder Driver
       │  {target: handle, code: BAR,                   copies data to
       │   data: serialized args}                        Process B's buffer
       │
       │  BLOCKS waiting                                 wakes Process B thread
       │
       │◄─────────────────────────────────────────────  reply arrives
  return value

Process B (Server) — binder thread wakes up:
  BnFoo::onTransact()
    → deserialize args
    → Foo::bar(arg1, arg2)    // actual implementation
    → serialize result
    → ioctl reply
```
