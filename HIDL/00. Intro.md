## 1. What is HAL (Hardware Abstraction Layer)?

The Hardware Abstraction Layer (HAL) defines a standard interface for hardware vendors to implement. It allows the Android framework to be agnostic of lower-level driver implementations.

```
┌─────────────────────────────────┐
│       Android Framework         │
│    (Java/Kotlin APIs)           │
├─────────────────────────────────┤
│       HAL Interface             │
│  (Standard contract between     │
│   framework and hardware)       │
├─────────────────────────────────┤
│    Vendor Implementation        │
│   (Hardware-specific code)      │
├─────────────────────────────────┤
│     Linux Kernel / Drivers      │
└─────────────────────────────────┘
```

> Reference: source.android.com/docs/core/architecture/hal

## 2. HAL Evolution Over the Years

### Timeline of HAL Architecture Changes

```
Android Version    HAL Type              Key Change
─────────────────────────────────────────────────────────
1.0 - 7.x         Legacy/Conventional   In-process, dlopen()
8.0 (Oreo)        Treble (HIDL)         Binderized HALs
10 (Q)            HIDL + AIDL HALs      AIDL HALs introduced
11 (R)            AIDL preferred        AIDL stable for HALs
13 (T)            AIDL mandatory        New HALs must use AIDL
14 (U)            AIDL only             HIDL deprecated
```

### Phase 1: Legacy HAL (Pre-Android 8.0)

Legacy HALs were shared libraries (`.so`) loaded directly into the calling process.

```c
// hardware/libhardware/include/hardware/hardware.h

typedef struct hw_module_t {
    uint32_t tag;                // HARDWARE_MODULE_TAG
    uint16_t module_api_version;
    uint16_t hal_api_version;
    const char *id;              // e.g., "camera", "audio"
    const char *name;
    const char *author;
    struct hw_module_methods_t *methods;
    void *dso;                   // handle to shared library
    uint32_t reserved[32-7];
} hw_module_t;

typedef struct hw_module_methods_t {
    int (*open)(const struct hw_module_t* module,
                const char* id,
                struct hw_device_t** device);
} hw_module_methods_t;

typedef struct hw_device_t {
    uint32_t tag;                // HARDWARE_DEVICE_TAG
    uint32_t version;
    struct hw_module_t* module;
    int (*close)(struct hw_device_t* device);
} hw_device_t;
```

**Example: Legacy Vibrator HAL**

```c
// hardware/libhardware/modules/vibrator/vibrator.c

static int vibrator_open(const hw_module_t* module, const char* id,
                         hw_device_t** device) {
    vibrator_device_t *vibradev = calloc(1, sizeof(vibrator_device_t));

    vibradev->common.tag = HARDWARE_DEVICE_TAG;
    vibradev->common.module = (hw_module_t *) module;
    vibradev->common.close = vibrator_close;
    vibradev->vibrator_on = vibrator_on;
    vibradev->vibrator_off = vibrator_off;

    *device = (hw_device_t *) vibradev;
    return 0;
}

static struct hw_module_methods_t vibrator_module_methods = {
    .open = vibrator_open,
};

struct hw_module_t HAL_MODULE_INFO_SYM = {
    .tag = HARDWARE_MODULE_TAG,
    .id = VIBRATOR_HARDWARE_MODULE_ID,
    .name = "Default vibrator HAL",
    .methods = &vibrator_module_methods,
};
```

**Problems with Legacy HAL:**
- Loaded into framework process (crash affects framework)
- No clear vendor/framework separation
- OTA updates required vendor cooperation
- No versioning enforcement

---

### Phase 2: Project Treble and HIDL (Android 8.0+)

Project Treble separated the vendor implementation from the Android OS framework.

```
Before Treble:                    After Treble:
┌──────────────┐                 ┌──────────────┐
│  Framework   │                 │  Framework   │
│  + HAL code  │                 ├──────────────┤
│  (monolithic)│                 │ HIDL/Binder  │  ← Stable interface
├──────────────┤                 ├──────────────┤
│    Kernel    │                 │   Vendor     │  ← Can update independently
├──────────────┤                 ├──────────────┤
│   Hardware   │                 │    Kernel    │
└──────────────┘                 ├──────────────┤
                                 │   Hardware   │
                                 └──────────────┘
```

## 3. What is HIDL (HAL Interface Definition Language)?

HIDL is an interface description language (IDL) used to specify the interface between a HAL and its users. It was introduced in Android 8.0 to support Project Treble.

> Reference: source.android.com/docs/core/architecture/hidl

### HIDL File Structure

```
hardware/interfaces/
├── audio/
│   ├── 2.0/
│   │   ├── IDevice.hal
│   │   ├── IDevicesFactory.hal
│   │   ├── IStream.hal
│   │   ├── types.hal
│   │   └── Android.bp
│   └── 4.0/
├── camera/
│   ├── device/
│   │   └── 3.2/
│   └── provider/
│       └── 2.4/
├── vibrator/
│   ├── 1.0/
│   │   ├── IVibrator.hal
│   │   ├── types.hal
│   │   └── Android.bp
│   └── 1.1/
└── ...
```

### HIDL Naming Convention

```
// Fully Qualified Name (FQN)
android.hardware.vibrator@1.0::IVibrator

// Format:
// PACKAGE@MAJOR.MINOR::TYPE

// Examples:
android.hardware.camera.device@3.4::ICameraDeviceSession
android.hardware.audio@6.0::IDevice
android.hardware.power@1.3::IPower
android.hardware.health@2.1::IHealth
```

## 5. HAL Types (Binderized vs Passthrough)

### 5.1 Binderized HAL

HAL runs in its **own process**, communicating via Binder IPC.

```
┌──────────────┐          ┌──────────────┐
│  Framework   │  Binder  │  HAL Process │
│  Process     │◄────────►│  (Vendor)    │
│              │   IPC    │              │
└──────────────┘          └──────────────┘
```

```cpp
// hardware/interfaces/vibrator/1.0/default/service.cpp

#include <android/hardware/vibrator/1.0/IVibrator.h>
#include <hidl/LegacySupport.h>

using android::hardware::vibrator::V1_0::IVibrator;
using android::hardware::defaultPassthroughServiceImplementation;

int main() {
    return defaultPassthroughServiceImplementation<IVibrator>();
}
```

**VINTF Manifest entry:**

```xml
<!-- /vendor/etc/vintf/manifest.xml -->
<hal format="hidl">
    <name>android.hardware.vibrator</name>
    <transport>hwbinder</transport>
    <version>1.0</version>
    <interface>
        <name>IVibrator</name>
        <instance>default</instance>
    </interface>
</hal>
```

---

### 5.2 Passthrough HAL

HAL runs in the **same process** as the caller (for backward compatibility).

```
┌────────────────────────────────┐
│  Framework Process             │
│  ┌──────────────────────────┐  │
│  │  HAL Implementation      │  │
│  │  (loaded via dlopen)     │  │
│  └──────────────────────────┘  │
└────────────────────────────────┘
```

```cpp
sp<IVibrator> vibrator = IVibrator::getService(true /* getStub */);
// true = passthrough mode, loads .so directly
```

**Passthrough entry point:**

```cpp
extern "C" IVibrator* HIDL_FETCH_IVibrator(const char* /* name */) {
    return new Vibrator();
}
```

---

### 5.3 Same-Process HAL (SP-HAL)

Special HALs that **must** run in the same process (e.g., OpenGL, Vulkan, gralloc).

```
Same-process HALs (always passthrough):
- android.hardware.graphics.mapper
- android.hardware.graphics.allocator
- android.hardware.renderscript
- EGL / GLES / Vulkan implementations
```

---

### 5.4 Comparison Table

```
Feature              Binderized          Passthrough         Same-Process
─────────────────────────────────────────────────────────────────────────
Process isolation    Yes                 No                  No
Performance          IPC overhead        Direct call         Direct call
Crash isolation      Yes                 No                  No
Mandatory for        Most HALs           Legacy compat       Graphics
Transport            hwbinder            passthrough         passthrough
```

```cpp
// hardware/interfaces/power/1.0/default/Power.cpp
#include "Power.h"
#include <android-base/logging.h>

namespace android::hardware::power::V1_0::implementation {

Return<void> Power::setInteractive(bool interactive) {
    LOG(INFO) << "setInteractive: " << interactive;
    set_interactive(interactive ? 1 : 0);
    return Void();
}

Return<void> Power::powerHint(PowerHint hint, int32_t data) {
    switch (hint) {
        case PowerHint::INTERACTION:
            power_hint_interaction(data);
            break;
        case PowerHint::LAUNCH:
            power_hint_launch(data);
            break;
        default:
            break;
    }
    return Void();
}

Return<void> Power::setFeature(Feature feature, bool activate) {
    switch (feature) {
        case Feature::POWER_FEATURE_DOUBLE_TAP_TO_WAKE:
            set_dt2w(activate);
            break;
    }
    return Void();
}

Return<void> Power::getPlatformLowPowerStats(
        getPlatformLowPowerStats_cb _hidl_cb) {
    hidl_vec<PowerStatePlatformSleepState> states;
    // Populate from /sys/power/...
    _hidl_cb(states, Status::SUCCESS);
    return Void();
}

}  // namespace
```

### 6.7 Client-Side Usage

```cpp
#include <android/hardware/power/1.0/IPower.h>

using android::hardware::power::V1_0::IPower;
using android::hardware::power::V1_0::PowerHint;

void usePowerHAL() {
    sp<IPower> power = IPower::getService();
    if (power == nullptr) {
        ALOGE("Failed to get Power HAL");
        return;
    }

    power->setInteractive(true);
    power->powerHint(PowerHint::INTERACTION, 500);

    power->getPlatformLowPowerStats(
        [](const hidl_vec<PowerStatePlatformSleepState>& states,
           Status status) {
            if (status == Status::SUCCESS) {
                for (const auto& state : states) {
                    ALOGI("Sleep state: %s, residency: %u ms",
                          state.name.c_str(),
                          state.residencyInMsecSinceBoot);
                }
            }
        });
}
```

## 7. HIDL Interface Versioning

### 7.1 Minor Version Update (Extension)

```hidl
// hardware/interfaces/vibrator/1.0/IVibrator.hal
package android.hardware.vibrator@1.0;

interface IVibrator {
    on(uint32_t timeoutMs)         generates (Status status);

    // New methods added in 1.1

        generates (Status status, uint32_t lengthMs);
};
```

### 7.2 Casting Between Versions

```cpp
#include <android/hardware/vibrator/1.0/IVibrator.h>
#include <android/hardware/vibrator/1.1/IVibrator.h>

using V1_0 = android::hardware::vibrator::V1_0;
using V1_1 = android::hardware::vibrator::V1_1;

void useVibrator() {
    // Try to get 1.1 first
    sp<V1_1::IVibrator> vibrator_1_1 = V1_1::IVibrator::getService();

    if (vibrator_1_1 != nullptr) {
        vibrator_1_1->perform_1_1(V1_1::Effect_1_1::HEAVY_CLICK,
                                   EffectStrength::STRONG);
    } else {
        sp<V1_0::IVibrator> vibrator_1_0 = V1_0::IVibrator::getService();
        if (vibrator_1_0 != nullptr) {
            vibrator_1_0->on(100);
        }
    }

    // castFrom for runtime checking
    sp<V1_0::IVibrator> base = V1_0::IVibrator::getService();
    sp<V1_1::IVibrator> extended = V1_1::IVibrator::castFrom(base);

    if (extended != nullptr) {
        // 1.1 is supported
    }
}
```

```cpp
// Vibrator.cpp
#include "Vibrator.h"
#include <android-base/logging.h>
#include <thread>

namespace aidl::android::hardware::vibrator {

ndk::ScopedAStatus Vibrator::getCapabilities(int32_t* _aidl_return) {
    *_aidl_return = IVibrator::CAP_ON_CALLBACK
                  | IVibrator::CAP_PERFORM_CALLBACK
                  | IVibrator::CAP_AMPLITUDE_CONTROL
                  | IVibrator::CAP_COMPOSE_EFFECTS;
    return ndk::ScopedAStatus::ok();
}

ndk::ScopedAStatus Vibrator::on(int32_t timeoutMs,
        const std::shared_ptr<IVibratorCallback>& callback) {
    LOG(INFO) << "Vibrator on for " << timeoutMs << "ms";

    if (callback != nullptr) {
        std::thread([=] {
            usleep(timeoutMs * 1000);
            callback->onComplete();
        }).detach();
    }
    return ndk::ScopedAStatus::ok();
}

ndk::ScopedAStatus Vibrator::setAmplitude(float amplitude) {
    if (amplitude <= 0.0f || amplitude > 1.0f) {
        return ndk::ScopedAStatus::fromExceptionCode(EX_ILLEGAL_ARGUMENT);
    }
    return ndk::ScopedAStatus::ok();
}

ndk::ScopedAStatus Vibrator::perform(Effect effect, EffectStrength strength,
        const std::shared_ptr<IVibratorCallback>& callback,
        int32_t* _aidl_return) {
    int32_t durationMs = 0;
    switch (effect) {
        case Effect::CLICK:        durationMs = 10;  break;
        case Effect::DOUBLE_CLICK: durationMs = 20;  break;
        case Effect::HEAVY_CLICK:  durationMs = 15;  break;
        default:
            return ndk::ScopedAStatus::fromExceptionCode(
                EX_UNSUPPORTED_OPERATION);
    }

    *_aidl_return = durationMs;

    if (callback != nullptr) {
        std::thread([=] {
            usleep(durationMs * 1000);
            callback->onComplete();
        }).detach();
    }
    return ndk::ScopedAStatus::ok();
}

}  // namespace
```

### Binder Domains in Android


# What Exactly is a HAL? Process, Library, or What?

> The answer is: **it depends on the HAL type**. HAL has evolved and can exist in different forms.

---

## Simple Answer First

```
Legacy HAL  → Just a .so library loaded into framework process
HIDL HAL    → A separate process (daemon) OR a .so (passthrough)
AIDL HAL    → A separate process (daemon)
```

---

## 1. Legacy HAL (Pre-Android 8.0) — It's Just a Library

```
┌─────────────────────────────────────────────────┐
│           system_server PROCESS                  │
│                                                  │
│   ┌─────────────────┐                           │
│   │  Framework Code │                           │
│   │  (Java/Native)  │                           │
│   └────────┬────────┘                           │
│            │  dlopen()                           │
│            │  loads .so file                     │
│            ▼                                     │
│   ┌─────────────────┐                           │
│   │  HAL .so file   │  ← NOT a separate process │
│   │  libvibrator.so │    Just a shared library   │
│   │  libcamera.so   │    running INSIDE          │
│   │  libaudio.so    │    system_server           │
│   └─────────────────┘                           │
└─────────────────────────────────────────────────┘
```

```c
// How framework loaded legacy HAL

hw_module_t* module;
hw_device_t* device;

// This does dlopen() internally on the .so file
// NO new process is created
int err = hw_get_module(VIBRATOR_HARDWARE_MODULE_ID, &module);

// Open the device (still in same process)
module->methods->open(module, VIBRATOR_DEVICE_ID, &device);
```

```

# The HAL .so was mapped into system_server memory

/system/lib64/libhardware.so

/vendor/lib64/hw/camera.msm8996.so     ← Camera HAL inside system_server
/vendor/lib64/hw/audio.primary.msm8996.so
```

### Problem With This Approach

```
┌─────────────────────────────────────┐
│         system_server               │
│                                     │
│   Framework + HAL in SAME process   │
│                                     │
│   If camera HAL crashes  ────────► ENTIRE system_server crashes
│   If audio HAL has bug   ────────► Phone reboots
│   If vendor updates HAL  ────────► Must update whole system
│                                     │
└─────────────────────────────────────┘
```

### Inside the HAL Process

```cpp
// This is what runs inside the HAL process
int main() {
    // 1. Configure binder thread pool
    configureRpcThreadpool(1, true);

    // 2. Create HAL implementation object
    sp<IVibrator> vibrator = new Vibrator();
    //   ↑ This object lives in the HAL process

    // 3. Register with hwservicemanager
    vibrator->registerAsService("default");
    //  Tells hwservicemanager:
    //  "I am android.hardware.vibrator@1.0::IVibrator/default"

    // 4. Block forever, waiting for incoming calls
    joinRpcThreadpool();
}
```

## 6. Why Separate Process? Benefits

```
Problem With Same Process:          Solution With Separate Process:
──────────────────────────          ───────────────────────────────
Camera HAL crashes                  Only camera HAL process dies
→ system_server crashes             framework keeps running
→ Phone reboots                     → restart just HAL daemon

Vendor updates HAL                  Update vendor partition only
→ Must update whole system image    → No system partition change needed
→ OTA required                      → Treble compliance!

HAL has security bug                HAL process has limited permissions
→ Affects entire system_server      → SELinux isolates the damage
→ Huge attack surface               → Smaller blast radius
```

### Quick Mental Model

```
Legacy HAL  = Plugin/DLL loaded into your app
              (like a browser extension in same process)

Binderized  = Microservice running separately
HAL         = (like a REST API call to another server)

Passthrough = Same as legacy but with HIDL interface wrapper
HAL         = (backward compatibility mode)

SP-HAL      = Must be plugin (performance-critical graphics)
              (like GPU drivers — can't afford IPC overhead)
```

> **Modern HALs ARE separate processes (daemons)**, but legacy HALs were just libraries loaded into the calling process.

## Step 3: Implement the HAL

### 3.1 Header File

```cpp
// hardware/interfaces/led/aidl/default/Led.h

#pragma once

#include <aidl/android/hardware/led/BnLed.h>
#include <aidl/android/hardware/led/LedColor.h>
#include <aidl/android/hardware/led/LedInfo.h>
#include <aidl/android/hardware/led/LedState.h>

#include <map>
#include <mutex>
#include <string>
#include <thread>
#include <atomic>

namespace aidl::android::hardware::led {

// Sysfs paths for LED control
static const std::map<LedColor, std::string> kLedSysfsPaths = {
    {LedColor::RED,   "/sys/class/leds/red/brightness"},
    {LedColor::GREEN, "/sys/class/leds/green/brightness"},
    {LedColor::BLUE,  "/sys/class/leds/blue/brightness"},
    {LedColor::WHITE, "/sys/class/leds/white/brightness"},
};

// Internal state tracking
struct LedStateInternal {
    int brightness = 0;
    bool isBlinking = false;
};

class Led : public BnLed {
  public:
    Led();
    ~Led();

    // ILed interface methods
    ndk::ScopedAStatus setLed(LedColor color, int brightness) override;
    ndk::ScopedAStatus turnOff(LedColor color) override;
    ndk::ScopedAStatus turnOffAll() override;
    ndk::ScopedAStatus getLedState(LedColor color,
                                    LedInfo* _aidl_return) override;
    ndk::ScopedAStatus getAllLedStates(
        std::vector<LedInfo>* _aidl_return) override;
    ndk::ScopedAStatus blinkLed(LedColor color, int onMs,
                                 int offMs, int count) override;

  private:
    bool writeBrightness(LedColor color, int brightness);
    int  readBrightness(LedColor color);
    bool isValidBrightness(int brightness);
    bool isValidColor(LedColor color);
    void stopBlinking(LedColor color);
    void blinkThread(LedColor color, int onMs, int offMs, int count);

    std::mutex mLock;
    std::map<LedColor, LedStateInternal>      mLedStates;
    std::map<LedColor, std::thread>           mBlinkThreads;
    std::map<LedColor, std::atomic<bool>>     mBlinkStop;
};

}  // namespace
```

### 3.2 Implementation File

```cpp
// hardware/interfaces/led/aidl/default/Led.cpp

#define LOG_TAG "android.hardware.led-service"

#include "Led.h"
#include <android-base/file.h>
#include <android-base/logging.h>
#include <android-base/strings.h>

namespace aidl::android::hardware::led {

// ─── Constructor / Destructor ─────────────────────────────────────

Led::Led() {
    LOG(INFO) << "LED HAL initializing";

    for (const auto& [color, path] : kLedSysfsPaths) {
        mLedStates[color] = LedStateInternal{};
        mBlinkStop[color].store(false);

        int current = readBrightness(color);
        mLedStates[color].brightness = current;

        LOG(INFO) << "LED " << static_cast<int>(color)
                  << " initial brightness: " << current;
    }
}

Led::~Led() {
    for (auto& [color, _] : kLedSysfsPaths) {
        stopBlinking(color);
    }
    for (const auto& [color, path] : kLedSysfsPaths) {
        writeBrightness(color, 0);
    }
}

// ─── ILed Interface Implementation ───────────────────────────────

ndk::ScopedAStatus Led::setLed(LedColor color, int brightness) {
    LOG(DEBUG) << "setLed: color=" << static_cast<int>(color)
               << " brightness=" << brightness;

    if (!isValidColor(color)) {
        return ndk::ScopedAStatus::fromExceptionCodeWithMessage(
            EX_ILLEGAL_ARGUMENT, "Invalid LED color");
    }
    if (!isValidBrightness(brightness)) {
        return ndk::ScopedAStatus::fromExceptionCodeWithMessage(
            EX_ILLEGAL_ARGUMENT, "Brightness must be between 0 and 255");
    }

    std::lock_guard<std::mutex> lock(mLock);
    stopBlinking(color);

    if (!writeBrightness(color, brightness)) {
        return ndk::ScopedAStatus::fromServiceSpecificError(
            -1, "Failed to write to sysfs");
    }

    mLedStates[color].brightness = brightness;
    mLedStates[color].isBlinking = false;
    return ndk::ScopedAStatus::ok();
}

ndk::ScopedAStatus Led::turnOff(LedColor color) {
    if (!isValidColor(color)) {
        return ndk::ScopedAStatus::fromExceptionCodeWithMessage(
            EX_ILLEGAL_ARGUMENT, "Invalid LED color");
    }

    std::lock_guard<std::mutex> lock(mLock);
    stopBlinking(color);

    if (!writeBrightness(color, 0)) {
        return ndk::ScopedAStatus::fromServiceSpecificError(
            -1, "Failed to write to sysfs");
    }

    mLedStates[color].brightness = 0;
    mLedStates[color].isBlinking = false;
    return ndk::ScopedAStatus::ok();
}

ndk::ScopedAStatus Led::turnOffAll() {
    std::lock_guard<std::mutex> lock(mLock);

    for (const auto& [color, path] : kLedSysfsPaths) {
        stopBlinking(color);
        writeBrightness(color, 0);
        mLedStates[color].brightness = 0;
        mLedStates[color].isBlinking = false;
    }
    return ndk::ScopedAStatus::ok();
}

ndk::ScopedAStatus Led::getLedState(LedColor color,
                                     LedInfo* _aidl_return) {
    if (!isValidColor(color)) {
        return ndk::ScopedAStatus::fromExceptionCodeWithMessage(
            EX_ILLEGAL_ARGUMENT, "Invalid LED color");
    }

    std::lock_guard<std::mutex> lock(mLock);
    const auto& state = mLedStates[color];

    LedInfo info;
    info.color          = color;
    info.state          = (state.brightness > 0) ? LedState::ON : LedState::OFF;
    info.brightnessLevel = state.brightness;

    *_aidl_return = info;
    return ndk::ScopedAStatus::ok();
}

ndk::ScopedAStatus Led::getAllLedStates(
        std::vector<LedInfo>* _aidl_return) {
    std::lock_guard<std::mutex> lock(mLock);
    std::vector<LedInfo> result;

    for (const auto& [color, path] : kLedSysfsPaths) {
        const auto& state = mLedStates[color];

        LedInfo info;
        info.color           = color;
        info.state           = (state.brightness > 0)
                                  ? LedState::ON : LedState::OFF;
        info.brightnessLevel = state.brightness;
        result.push_back(info);
    }

    *_aidl_return = result;
    return ndk::ScopedAStatus::ok();
}

ndk::ScopedAStatus Led::blinkLed(LedColor color, int onMs,
                                   int offMs, int count) {
    if (!isValidColor(color)) {
        return ndk::ScopedAStatus::fromExceptionCodeWithMessage(
            EX_ILLEGAL_ARGUMENT, "Invalid LED color");
    }
    if (onMs <= 0 || offMs <= 0) {
        return ndk::ScopedAStatus::fromExceptionCodeWithMessage(
            EX_ILLEGAL_ARGUMENT, "onMs and offMs must be positive");
    }

    std::lock_guard<std::mutex> lock(mLock);
    stopBlinking(color);

    mBlinkStop[color].store(false);
    mBlinkThreads[color] = std::thread(
        &Led::blinkThread, this, color, onMs, offMs, count);

    mLedStates[color].isBlinking = true;
    return ndk::ScopedAStatus::ok();
}

// ─── Private Helpers ──────────────────────────────────────────────

bool Led::writeBrightness(LedColor color, int brightness) {
    auto it = kLedSysfsPaths.find(color);
    if (it == kLedSysfsPaths.end()) return false;

    std::string value = std::to_string(brightness) + "\n";
    if (!::android::base::WriteStringToFile(value, it->second)) {
        LOG(ERROR) << "Failed to write " << brightness
                   << " to " << it->second
                   << " errno=" << errno;
        return false;
    }
    return true;
}

int Led::readBrightness(LedColor color) {
    auto it = kLedSysfsPaths.find(color);
    if (it == kLedSysfsPaths.end()) return 0;

    std::string content;
    if (!::android::base::ReadFileToString(it->second, &content)) return 0;

    content = ::android::base::Trim(content);
    try { return std::stoi(content); }
    catch (...) { return 0; }
}

bool Led::isValidBrightness(int brightness) {
    return brightness >= 0 && brightness <= 255;
}

bool Led::isValidColor(LedColor color) {
    return kLedSysfsPaths.find(color) != kLedSysfsPaths.end();
}

void Led::stopBlinking(LedColor color) {
    mBlinkStop[color].store(true);

    if (mBlinkThreads.count(color) && mBlinkThreads[color].joinable()) {
        mLock.unlock();
        mBlinkThreads[color].join();
        mLock.lock();
        mBlinkThreads.erase(color);
    }
}

void Led::blinkThread(LedColor color, int onMs, int offMs, int count) {
    int remaining = count;  // -1 = infinite

    while (!mBlinkStop[color].load()) {
        writeBrightness(color, 255);
        std::this_thread::sleep_for(std::chrono::milliseconds(onMs));

        if (mBlinkStop[color].load()) break;

        writeBrightness(color, 0);
        std::this_thread::sleep_for(std::chrono::milliseconds(offMs));

        if (count != -1) {
            if (--remaining <= 0) break;
        }
    }
}

}  // namespace
```

## Step 4: Write the Service Entry Point

```cpp
// hardware/interfaces/led/aidl/default/service.cpp

#define LOG_TAG "android.hardware.led-service"

#include <android-base/logging.h>
#include <android/binder_manager.h>
#include <android/binder_process.h>
#include "Led.h"

using aidl::android::hardware::led::Led;

int main() {
    ::android::base::InitLogging(nullptr,
        ::android::base::KernelLogger);

    LOG(INFO) << "LED HAL service starting";

    // 0 = only the main thread handles requests
    ABinderProcess_setThreadPoolMaxThreadCount(0);

    // Create HAL implementation
    std::shared_ptr<Led> led = ndk::SharedRefBase::make<Led>();

    // Service instance name: <descriptor>/default
    const std::string instance =
        std::string(Led::descriptor) + "/default";

    LOG(INFO) << "Registering service: " << instance;

    // Register with servicemanager
    binder_status_t status =
        AServiceManager_addService(
            led->asBinder().get(),
            instance.c_str());

    if (status != STATUS_OK) {
        LOG(ERROR) << "Failed to register LED HAL: " << status;
        return EXIT_FAILURE;
    }

    LOG(INFO) << "LED HAL service registered successfully";

    // Block forever, handling incoming binder calls
    ABinderProcess_joinThreadPool();

    return EXIT_FAILURE;  // should never reach
}
```

## 1. Binder Driver Types

### Three Binder Domains

```
/dev/binder      /dev/hwbinder    /dev/vndbinder
     │                │                 │
     ▼                ▼                 ▼
┌─────────┐     ┌──────────┐     ┌──────────────┐
│ Regular │     │ Hardware │     │   Vendor     │
│ Binder  │     │ Binder   │     │   Binder     │
│         │     │          │     │              │
│ Apps ↔  │     │Framework │     │ Vendor proc  │
│ System  │     │  ↔ HAL   │     │ ↔ Vendor proc│
└─────────┘     └──────────┘     └──────────────┘
     │                │                 │
     ▼                ▼                 ▼
servicemanager  hwservicemanager  vndservicemanager
```

### Why Three Separate Binder Domains?

```
SECURITY:
─────────
Each domain has different SELinux rules
Apps CANNOT accidentally talk to vendor HALs
Vendor code CANNOT interfere with framework IPC

QUOTA/PERFORMANCE:
──────────────────
Each domain has its own thread pool
HAL calls don't starve app IPC calls
Independent binder ref counting

TREBLE COMPLIANCE:
──────────────────
Clear boundary between system and vendor
/dev/binder    → system partition code
/dev/hwbinder  → vendor HAL code (HIDL)
/dev/vndbinder → vendor code (AIDL HALs)
```

```cpp
// frameworks/native/cmds/servicemanager/ServiceManager.cpp

std::map<std::string, Service> mNameToService;

// Called by system_server during boot:
Status ServiceManager::addService(const std::string& name,
                                   const sp<IBinder>& binder, ...) {
    // 1. SELinux check
    if (!mAccess->canAdd(ctx, name)) {
        return Status::fromExceptionCode(Status::EX_SECURITY);
    }
    // 2. Store the binder reference
    mNameToService[name] = Service { .binder = binder, ... };
    return Status::ok();
}

// Called by clients:
sp<IBinder> ServiceManager::checkService(const std::string& name) {
    // 1. SELinux check
    if (!mAccess->canFind(ctx, name)) return nullptr;

    // 2. Return the binder reference
    auto it = mNameToService.find(name);
    if (it == mNameToService.end()) return nullptr;
    return it->second.binder;
}

// Blocks until service appears (used during boot):
sp<IBinder> ServiceManager::waitForService(const std::string& name);
```

```cpp
std::map<std::string,          // "android.hardware.vibrator@1.0"
    std::map<std::string,      // "IVibrator"
        std::map<std::string,  // "default"
            sp<IBase>>>>       // actual HAL binder
mServiceMap;

// HAL registers itself:
Return<bool> ServiceManager::add(const hidl_string& fqName,
                                  const sp<IBase>& service) {
    FQName fq(fqName);

    // SELinux check
    if (!mAcl.canAdd(fqName, getBinderCallingContext()))
        return false;

    // Store + notify waiting clients
    mServiceMap[fq.package()][fq.name()]["default"] = service;
    sendRegistrationNotifications(fqName);
    return true;
}

// Framework gets service:
Return<sp<IBase>> ServiceManager::get(
        const hidl_string& fqName, const hidl_string& name) {
    auto it = mServiceMap.find(fqName);
    if (it == mServiceMap.end()) return nullptr;

    auto instanceIt = it->second.find(name);
    if (instanceIt == it->second.end()) return nullptr;
    return instanceIt->second;
}
```

```
│  BUT can't use /dev/binder (framework ↔ app)        │
│  AND can't use /dev/hwbinder (framework ↔ HIDL HAL) │
│                                                     │
│  Solution: /dev/vndbinder + vndservicemanager       │
└─────────────────────────────────────────────────────┘

Examples:
• Vendor daemon A ↔ Vendor daemon B
• AIDL HAL implementations (vendor side)
• Qualcomm-specific services
• MediaTek-specific services
```

### vndservicemanager Source

```cpp
// frameworks/native/cmds/servicemanager/main.cpp
// Same code as servicemanager — different device!

int main(int argc, char** argv) {
    // KEY DIFFERENCE: uses /dev/vndbinder
    sp<ProcessState> ps =
        ProcessState::initWithDriver(
            argc == 2 ? argv[1] : "/dev/vndbinder");
    //                              ↑ vndbinder!

    sp<ServiceManager> manager =
        sp<ServiceManager>::make(std::make_unique<Access>());

    sp<Looper> looper = Looper::prepare(false);
    BinderCallback::setupTo(looper);
    ClientCallbackCallback::setupTo(looper, manager);

    while (true) {
        looper->pollAll(-1);
    }
}
```

## 7. Deep Dive: How Binder Works

### Binder Architecture

```
USER SPACE                    KERNEL SPACE
──────────────────────────────────────────────────────

Process A (Client)            Binder Driver
┌────────────────┐           ┌──────────────────────┐
│                │           │                      │
│  BpFoo::bar()  │           │  /dev/binder         │
│       │        │  ioctl()  │                      │
│       └────────┼──────────►│  binder_transaction  │
│                │           │  {                   │
│   BLOCKS       │           │    target: handle 42 │
│   waiting      │           │    code: METHOD_BAR  │
│                │           │    data: [arg1, arg2]│
│                │           │  }                   │
│                │           │                      │
│                │           │  Copies data to      │
│                │◄──────────│  Process B's memory  │
│  Returns       │  ioctl()  │  (mmap optimization) │
└────────────────┘           └──────────────────────┘
                                        │
                                        │ wake up
                                        ▼
Process B (Server)
┌────────────────────────────────────────────────────┐
│  Binder thread pool (waiting in ioctl)             │
│  ┌──────────────────────────────────────────────┐  │
│  │  Thread 1: WAIT → receives transaction       │  │
│  │     → BnFoo::onTransact()                    │  │
│  │     → deserialize args                       │  │
│  │     → call actual Foo::bar(arg1, arg2)        │  │
│  │     → serialize result                       │  │
│  │     → send reply via ioctl                   │  │
│  └──────────────────────────────────────────────┘  │
│  ┌──────────────────────────────────────────────┐  │
│  │  Thread 2: WAIT (available for next call)    │  │
│  └──────────────────────────────────────────────┘  │
└────────────────────────────────────────────────────┘
```

### Binder Transaction Data Flow

```cpp
struct binder_transaction_data {
    union {
        __u32 handle;           // target's handle in caller's space
        binder_uintptr_t ptr;   // target's pointer in server space
    } target;

    binder_uintptr_t cookie;
    __u32 code;                 // method code (which method to call)
    __u32 flags;                // oneway, etc.

    pid_t sender_pid;           // caller's PID — set by KERNEL!
    uid_t sender_euid;          // caller's UID — set by KERNEL!
    // ↑ Cannot be forged! Kernel sets these from actual process info

    binder_size_t data_size;
    binder_size_t offsets_size; // where IBinder objects are in data

    union {
        struct {
            binder_uintptr_t buffer;   // ptr to data
            binder_uintptr_t offsets;  // ptr to object offsets
        } ptr;
        __u8 buf[8];
    } data;
};
```

### Handle Translation (Critical Concept)

```
This is how binder "passes" objects between processes:

Process A                  Kernel                  Process B
┌──────────┐              ┌────────┐              ┌──────────┐
│ IBinder  │              │ Binder │              │ IBinder  │
│ handle=5 │──────────────│ driver │──────────────│ handle=3 │
│          │   send ref   │        │   create ref │          │
└──────────┘              │ Global │              └──────────┘
                          │ ref    │
                          │ table: │
                          │ {      │
                          │  obj=X │
                          │  A→5   │
                          │  B→3   │
                          │ }      │
                          └────────┘

• Each process sees a DIFFERENT handle for the same object
• Kernel maintains the global reference table
• When you "send" a binder, kernel creates new handle
  in recipient's handle space
• Processes can't guess each other's handles → secure
• Ref counting done by kernel — object lives as long as
  someone holds a reference
```

### Binder Thread Pool

```cpp
// ProcessState.cpp manages binder threads

// Starting thread pool:
ProcessState::self()->startThreadPool();
// Creates threads that block in ioctl(BC_ENTER_LOOPER)

// Joining (main thread also serves):
IPCThreadState::self()->joinThreadPool();

// Max threads:
ProcessState::self()->setThreadPoolMaxThreadCount(15);
// Default is 15 binder threads
// Kernel can spawn new threads up to max when busy

// Thread pool in action:
Thread 1: ioctl(BINDER_WRITE_READ) → BLOCKS
Thread 2: ioctl(BINDER_WRITE_READ) → BLOCKS
Thread 3: ioctl(BINDER_WRITE_READ) → RECEIVES call
           → executes method
           → replies
           → blocks again
```

## 8. Service Discovery Flow

### Complete Flow: App Getting Camera Service

```
1. App calls:
   CameraManager cm = context.getSystemService(Context.CAMERA_SERVICE);
         │
         ▼
2. Context looks up "camera" in servicemanager
   IBinder b = ServiceManager.getService("camera");
         │
         ▼
3. servicemanager returns binder reference to
   CameraService (running in cameraserver process)
         │
         ▼
4. App wraps in proxy:
   ICameraService cs = ICameraService.Stub.asInterface(b);
         │
         ▼
5. App calls cs.getCameraList()
   → Serialized and sent over /dev/binder
         │
         ▼
6. CameraService receives call
   → Internally gets Camera HAL:
   sp<provider::V2_4::ICameraProvider> provider =
       provider::V2_4::ICameraProvider::getService("legacy/0");
   // ↑ Goes to hwservicemanager over /dev/hwbinder
         │
         ▼
7. hwservicemanager returns binder to
   Camera HAL process (camera.provider@2.4-service)
         │
         ▼
8. CameraService calls HAL:
   provider->getCameraIdList(...)
   → Over /dev/hwbinder to HAL process
         │
         ▼
9. Camera HAL reads from kernel driver
   → /dev/video0 (V4L2) or proprietary driver
   → Returns camera list
         │
         ▼
10. Returns all the way back to app


Full path:
App → /dev/binder → servicemanager
App → /dev/binder → CameraService (system_server or cameraserver)
CameraService → /dev/hwbinder → hwservicemanager
CameraService → /dev/hwbinder → Camera HAL
Camera HAL → ioctl → kernel camera driver
```
