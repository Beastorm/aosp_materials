# Pipe IPC in Android

## What is a Pipe?

A Pipe is the simplest form of IPC — it's like a one-way water pipe where data flows from one end to another.

```
┌──────────┐                        ┌──────────┐
│          │   ════════════════►     │          │
│ Process A│       PIPE (Data)      │ Process B│
│ (Writer) │   ════════════════►     │ (Reader) │
│          │                        │          │
└──────────┘                        └──────────┘
     ▲                                    ▲
  Write End                           Read End
  (fd[1])                             (fd[0])
```

## 1. Anonymous (Unnamed) Pipe

### How It Works — Step by Step

```
Step 1: Process creates a pipe
  Process A (Parent)
  fd[0] = Read End
  fd[1] = Write End
  fd[0]═══════fd[1]

Step 2: fork() creates child process
  Parent Process              Child Process
  fd[0] (read)               fd[0] (read)
  fd[1] (write)              fd[1] (write)
         └──────────┬───────────────┘
                    │  Shared Pipe

Step 3: Close unused ends
  Parent Process              Child Process
  fd[0] ✗ CLOSED             fd[0] ✓ READ
  fd[1] ✓ WRITE              fd[1] ✗ CLOSED
       │    ══════════════►        │
            Data flows one direction
```

### Native Code Example (C/C++)

```c
#include <unistd.h>
#include <stdio.h>
#include <string.h>
#include <sys/wait.h>

int main() {
    int fd[2];      // fd[0] = read end, fd[1] = write end
    pid_t pid;
    char buffer[100];

    if (pipe(fd) == -1) { perror("pipe failed"); return 1; }

    pid = fork();

    if (pid > 0) {
        // ===== PARENT PROCESS (Writer) =====
        close(fd[0]);
        const char *message = "Hello from Parent!";
        write(fd[1], message, strlen(message) + 1);
        printf("Parent: Sent message\n");
        close(fd[1]);
        wait(NULL);

    } else if (pid == 0) {
        // ===== CHILD PROCESS (Reader) =====
        close(fd[1]);
        read(fd[0], buffer, sizeof(buffer));
        printf("Child: Received '%s'\n", buffer);
        close(fd[0]);
    }
    return 0;
}
```

## 2. Bidirectional Communication (Two Pipes)

```
    Parent Process                          Child Process
    ┌────────────────┐                     ┌────────────────┐
    │  Write fd1[1]  │ ══ Pipe 1 ════════► │  Read fd1[0]   │
    │  Read  fd2[0]  │ ◄══ Pipe 2 ════════ │  Write fd2[1]  │
    └────────────────┘                     └────────────────┘
```

```c
int pipe1[2];  // Parent → Child
int pipe2[2];  // Child → Parent
char buffer[100];

pipe(pipe1); pipe(pipe2);
pid_t pid = fork();

if (pid > 0) {
    // PARENT
    close(pipe1[0]); close(pipe2[1]);

    write(pipe1[1], "What's your PID?", 17);

    read(pipe2[0], buffer, sizeof(buffer));
    printf("Parent received: %s\n", buffer);

    close(pipe1[1]); close(pipe2[0]);
    wait(NULL);

} else {
    // CHILD
    close(pipe1[1]); close(pipe2[0]);

    read(pipe1[0], buffer, sizeof(buffer));
    printf("Child received: %s\n", buffer);

    char reply[50];
    sprintf(reply, "My PID is %d", getpid());
    write(pipe2[1], reply, strlen(reply) + 1);

    close(pipe1[0]); close(pipe2[1]);
}
```

## 3. Named Pipe (FIFO)

Named pipes have a file path so unrelated processes can communicate.

```
    ┌─────────────────┐                    ┌─────────────────┐
    │   Process A     │                    │   Process B     │
    │   (Writer)      │                    │   (Reader)      │
    │ open("/tmp/     │                    │ open("/tmp/     │
    │   myfifo",      │                    │   myfifo",      │
    │   O_WRONLY)     │                    │   O_RDONLY)     │
    └────────┬────────┘                    └────────┬────────┘
             │         /tmp/myfifo                   │
             │    ┌─────────────────┐               │
             └───►│  Named Pipe     │◄──────────────┘
                  │  (FIFO file)    │
                  └─────────────────┘
Note: Exists in filesystem but data stays in KERNEL MEMORY (not on disk)
```

```c
// ===== Process A: Writer =====
mkfifo("/data/local/tmp/myfifo", 0666);
int fd = open("/data/local/tmp/myfifo", O_WRONLY);
const char *msg = "Hello via Named Pipe!";
write(fd, msg, strlen(msg) + 1);
close(fd);

// ===== Process B: Reader =====
char buffer[100];
int fd = open("/data/local/tmp/myfifo", O_RDONLY);
read(fd, buffer, sizeof(buffer));
printf("Received: %s\n", buffer);
close(fd);
```

## 4. Pipe in Android Java/Kotlin (ParcelFileDescriptor)

```
┌──────────────────────────────────────────────────────┐
│                Android Framework                      │
│                                                      │
│  ParcelFileDescriptor.createPipe()                   │
│  Returns: ParcelFileDescriptor[2]                    │
│     [0] = Read End                                   │
│     [1] = Write End                                  │
│                      │                               │
│                      ▼                               │
│          Linux Kernel pipe() (native impl)           │
└──────────────────────────────────────────────────────┘
```

### Pipe between Service and Activity

```kotlin
// ===== Service (Writer) =====
class MyService : Service() {

    override fun onBind(intent: Intent): IBinder = MyBinder()

    inner class MyBinder : Binder() {
        fun getDataPipe(): ParcelFileDescriptor {
            val pipe    = ParcelFileDescriptor.createPipe()
            val readEnd = pipe[0]
            val writeEnd = pipe[1]

            Thread {
                val output = ParcelFileDescriptor.AutoCloseOutputStream(writeEnd)
                output.write("Hello from Service!".toByteArray())
                output.close()
            }.start()

            return readEnd
        }
    }
}
```

```kotlin
// ===== Activity (Reader) =====
class MainActivity : AppCompatActivity() {

    private val connection = object : ServiceConnection {
        override fun onServiceConnected(name: ComponentName, binder: IBinder) {
            val myService = binder as MyService.MyBinder
            val readEnd   = myService.getDataPipe()

            Thread {
                val input = ParcelFileDescriptor.AutoCloseInputStream(readEnd)
                val data  = input.bufferedReader().readText()
                Log.d("Pipe", "Received: $data")
                input.close()
            }.start()
        }
        override fun onServiceDisconnected(name: ComponentName) {}
    }

    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        bindService(Intent(this, MyService::class.java), connection, BIND_AUTO_CREATE)
    }
}
```

## 5. ContentProvider with Pipe

```
┌──────────────┐         ┌───────────────────┐        ┌────────────────┐
│  App A       │         │   ContentProvider  │        │  File/Network  │
│  (Client)    │         │   (in App B)       │        │  Resource      │
│              │         │                    │        │                │
│  resolver.   │────────►│  openFile() {      │───────►│ Read large    │
│  openFile    │         │    createPipe()    │        │ file/stream   │
│  Descriptor()│◄────────│    return readEnd  │◄───────│               │
│  Read stream │  Pipe   │    write writeEnd  │  Data  │               │
└──────────────┘         └───────────────────┘        └────────────────┘
```

```kotlin
class MyContentProvider : ContentProvider() {

    override fun openFile(uri: Uri, mode: String): ParcelFileDescriptor? {
        val pipe     = ParcelFileDescriptor.createPipe()
        val readEnd  = pipe[0]
        val writeEnd = pipe[1]

        Thread {
            val output = ParcelFileDescriptor.AutoCloseOutputStream(writeEnd)
            try {
                val file = File(context?.filesDir, "large_data.json")
                file.inputStream().use { it.copyTo(output) }
            } finally {
                output.close()
            }
        }.start()

        return readEnd
    }
}
```

## 6. `createReliablePipe()` — Error Detection

```
Regular Pipe:                      Reliable Pipe:
Writer crashes →                   Writer crashes →
Reader gets EOF (silent)           Reader gets IOException with error message
```

```kotlin
val pipe     = ParcelFileDescriptor.createReliablePipe()
val readEnd  = pipe[0]
val writeEnd = pipe[1]

// Writer signals errors
try {
    val output = ParcelFileDescriptor.AutoCloseOutputStream(writeEnd)
    // ... write data ...
    output.close()
} catch (e: Exception) {
    writeEnd.closeWithError("Write failed: ${e.message}")
}

// Reader detects errors
try {
    val input = ParcelFileDescriptor.AutoCloseInputStream(readEnd)
    val data  = input.bufferedReader().readText()
    input.close()
    readEnd.checkError()  // Throws if writer signaled error
} catch (e: IOException) {
    Log.e("Pipe", "Writer had error: ${e.message}")
}
```

## 7. Pipe Data Flow in Kernel

```
          User Space                    Kernel Space
    ┌──────────────────┐         ┌─────────────────────────┐
    │  Process A       │         │   Pipe Buffer (64KB)    │
    │  write(fd) ──────┼────────►│   ┌─┬─┬─┬─┬─┬─┬─┬─┐   │
    │                  │  copy   │   │D│A│T│A│ │ │ │ │   │
    └──────────────────┘  from   │   └─┴─┴─┴─┴─┴─┴─┴─┘   │
                         user    │         │ copy to user  │
    ┌──────────────────┐         │         ▼               │
    │  Process B       │         │   ┌─┬─┬─┬─┬─┬─┬─┬─┐   │
    │  read(fd) ◄──────┼─────────│   │D│A│T│A│ │ │ │ │   │
    └──────────────────┘         │   └─┴─┴─┴─┴─┴─┴─┴─┘   │
                                 └─────────────────────────┘

⚠️ Data is COPIED TWICE:
   1. User → Kernel (write)
   2. Kernel → User (read)
   Compare with Binder: Only 1 copy!
```

---

## 8. Blocking Behavior

```
Scenario 1: BUFFER EMPTY
  Reader calls read() → BLOCKED, waiting for data
  Writer calls write() → Reader UNBLOCKED, returns data

Scenario 2: BUFFER FULL (64KB)
  Writer calls write() → BLOCKED, buffer full
  Reader calls read() → Frees space → Writer UNBLOCKED

Scenario 3: PIPE CLOSED
  Writer calls close(fd[1]) ✗
  Reader calls read(fd[0]) → Returns 0 (EOF) → "No more data"
```

## 9. Complete Example: Inter-Process Pipe via AIDL

```
┌──────────────────┐                    ┌──────────────────┐
│   Client App     │                    │   Server App     │
│   (Process 1)    │                    │   (Process 2)    │
│                  │  Call getData()    │                  │
│                  │──── Binder ───────►│  Creates pipe()  │
│                  │◄─── readEnd ───────│  Returns readEnd │
│  Read from       │                    │  Write to        │
│  readEnd stream  │◄════ DATA ═════════│  writeEnd stream │
└──────────────────┘   (via pipe)       └──────────────────┘
```

**AIDL Interface**

```aidl
// IDataService.aidl
interface IDataService {
    ParcelFileDescriptor getData();
}
```

**Server**

```kotlin
class DataService : Service() {

    private val binder = object : IDataService.Stub() {
        override fun getData(): ParcelFileDescriptor {
            val pipe     = ParcelFileDescriptor.createReliablePipe()
            val readEnd  = pipe[0]
            val writeEnd = pipe[1]

            Thread {
                try {
                    val os = ParcelFileDescriptor.AutoCloseOutputStream(writeEnd)
                    for (i in 1..1000) {
                        os.write("Chunk $i of data\n".toByteArray())
                        Thread.sleep(10)
                    }
                    os.close()
                } catch (e: Exception) {
                    writeEnd.closeWithError(e.message)
                }
            }.start()

            return readEnd
        }
    }

    override fun onBind(intent: Intent) = binder
}
```

**Client**

```kotlin
private fun readFromService(service: IDataService) {
    val readEnd = service.data

    Thread {
        val input  = ParcelFileDescriptor.AutoCloseInputStream(readEnd)
        val reader = input.bufferedReader()

        var line: String?
        while (reader.readLine().also { line = it } != null) {
            Log.d("Client", "Received: $line")
        }

        reader.close()
        readEnd.checkError()
    }.start()
}
```

## ✅ When to Use Pipes

### 1. Large File / Data Streaming

```
Problem: Binder has 1MB transaction limit

Without Pipe (WRONG for large data):
  App A ──── Binder 💥 ────► App B
  (500MB video)  TransactionTooLargeException!

With Pipe (CORRECT):
  App A ──── Binder (just sends pipe fd) ────► App B
  App A ════ data stream (via pipe) ══════════► App B gets 500MB ✅
```

```kotlin
// ✅ GOOD: Streaming large PDF via ContentProvider pipe
class PdfProvider : ContentProvider() {
    override fun openFile(uri: Uri, mode: String): ParcelFileDescriptor {
        val pipe = ParcelFileDescriptor.createReliablePipe()

        Thread {
            val out = ParcelFileDescriptor.AutoCloseOutputStream(pipe[1])
            getLargePdfFile().inputStream().copyTo(out)  // Stream 100MB PDF
            out.close()
        }.start()

        return pipe[0]
    }
}
```

### 2. Parent-Child Process Communication

```
Android Zygote Model:

        Zygote Process
        ┌─────────────────────────────┐
        │  pipe(fd)                   │
        │  fork() ───────────────────► App Process
        │  Parent writes config ──────► Child reads config via pipe
        └─────────────────────────────┘

✅ Perfect use case: related processes, one-way setup data
```

```kotlin
// ✅ GOOD: Parent sends config to child process
fun startChildProcess(): Process {
    val process = Runtime.getRuntime().exec(
        arrayOf("/system/bin/my_native_worker")
    )
    // process.outputStream IS a pipe to child's stdin
    val writer = process.outputStream.bufferedWriter()
    writer.write("""{"config": "value", "timeout": 30}""")
    writer.close()

    // process.inputStream IS a pipe from child's stdout
    val result = process.inputStream.bufferedReader().readText()
    return process
}
```

### 3. Capturing Command / Process Output

```
Runtime.exec() uses pipes internally:

  Your App ◄══ stdout (pipe) ══ Shell Command ("logcat", "ps", "dumpsys")
  Your App ◄══ stderr (pipe) ══ Shell Command
```

```kotlin
// ✅ GOOD: Capturing logcat output via pipe
fun captureLogs(): String {
    val process = Runtime.getRuntime().exec(arrayOf("logcat", "-d", "-t", "100"))
    return process.inputStream.bufferedReader().readText()
}

// ✅ GOOD: Running shell command and getting result
fun getRunningProcesses(): List<String> {
    val process = Runtime.getRuntime().exec("ps -A")
    return process.inputStream.bufferedReader().readLines()
}
```

## ❌ When NOT to Use Pipes

### ❌ 1. Small / Simple Data Exchange

```
❌ BAD: Using pipe for simple messages
  App A creates pipe → writes "true" → App B gets "true"
  So much overhead just to send a boolean!

✅ USE INSTEAD: Intent, Broadcast, SharedPreferences, Binder
```

```kotlin
// ❌ BAD: Pipe for simple flag
val pipe = ParcelFileDescriptor.createPipe()
val out  = ParcelFileDescriptor.AutoCloseOutputStream(pipe[1])
out.write("true".toByteArray())  // Overkill!

// ✅ GOOD: Use Intent instead
val intent = Intent("com.example.ACTION_UPDATE")
intent.putExtra("flag", true)
sendBroadcast(intent)

// ✅ OR: Use SharedPreferences
prefs.edit().putBoolean("flag", true).apply()
```

### ❌ 2. Unrelated Processes (without Named Pipe)

```
❌ BAD: Anonymous pipe between unrelated apps

  App A (Package 1)              App B (Package 2)
  pipe(fd)                       How do I get fd[0] = 3?
  fd[0] = 3          ❌           IMPOSSIBLE — no shared process space!
  fd[1] = 4        IMPOSSIBLE

✅ USE INSTEAD: Named Pipe (FIFO), Socket, Binder
```

### ❌ 3. Bidirectional Communication (gets complex)

```
❌ BAD: Two-way chat using pipes
  App A: pipe1[1] write ════════════► pipe1[0] read :App B
  App A: pipe2[0] read  ◄════════════ pipe2[1] write:App B

  Complexity: 4 file descriptors, easy to deadlock, hard to synchronize

  DEADLOCK SCENARIO:
  A writes to pipe1 (full, blocks)
  B writes to pipe2 (full, blocks)
  Both waiting for other to read → DEADLOCK! 💀

✅ USE INSTEAD: Binder (AIDL), Socket (handles bidirectional natively)
```

### ❌ 4. Multiple Readers / Writers

```
❌ BAD: Multiple processes reading from same pipe
  Writer writes "HELLO"
  Reader1 gets "HEL"
  Reader2 gets "LO"
  Data split unpredictably!

✅ USE INSTEAD: Message Queue, Broadcast, EventBus, SharedMemory
```

### ❌ 5. Persistent Data Storage

```
❌ BAD: Using pipe as data store
  • Pipe data lives ONLY in kernel memory
  • App closes → Pipe destroyed
  • Device reboots → Pipe gone
  • Data NOT on disk
  • Writer faster than reader → Buffer fills (64KB) → Writer BLOCKS

✅ USE INSTEAD: Room DB, File, SharedPreferences, ContentProvider
```

### ❌ 6. Random Access Data

```
❌ BAD: Seeking / Random access via pipe
  Pipe is SEQUENTIAL (FIFO)
  Data: [A][B][C][D][E]
  Read A? → Gone forever, can't go back
  lseek() on pipe → FAILS ❌ ("Illegal seek" error)

// ❌ This will FAIL on a pipe:
Os.lseek(fd, 0, OsConstants.SEEK_SET)  // ERROR!

✅ USE INSTEAD: File, MemoryMappedFile, SharedMemory
```

### ❌ 7. High-Frequency Small Messages

```
❌ BAD: Thousands of tiny pipe writes per second
  Each write() = System call overhead
  1000 writes/sec × syscall overhead = significant CPU waste

  Sensor at 1000Hz → 1000 syscalls/sec → HIGH CPU!

✅ USE INSTEAD: SharedMemory (zero-copy, no syscall per access),
               Batch the writes
```

## Golden Rules Summary

```
┌─────────────────────────────────────────────────────────┐
│                                                         │
│   ✅ USE PIPE WHEN:                                     │
│   ══════════════════                                    │
│   • Data is a continuous BYTE STREAM                    │
│   • Data size is LARGE (>1MB)                           │
│   • Flow is ONE DIRECTION                               │
│   • Processes are PARENT ↔ CHILD                       │
│   • Capturing PROCESS OUTPUT                            │
│   • FIFO ordering is needed                             │
│   • ContentProvider FILE streaming                      │
│                                                         │
├─────────────────────────────────────────────────────────┤
│                                                         │
│   ❌ AVOID PIPE WHEN:                                   │
│   ═══════════════════                                   │
│   • Data is SMALL (use Intent/Binder)                   │
│   • Need TWO-WAY communication (use Socket/Binder)      │
│   • Multiple READERS needed (use Broadcast)             │
│   • Need DATA PERSISTENCE (use DB/File)                 │
│   • Need RANDOM ACCESS (use File/MemMap)                │
│   • Very HIGH FREQUENCY messages (use SharedMemory)     │
│   • Unrelated processes, anonymous pipe (use Socket)    │
│                                                         │
└─────────────────────────────────────────────────────────┘
```
