# Signal IPC in Android — Detailed Explanation

## What is a Signal?

A **Signal** is a software interrupt sent to a process to notify it that a significant event has occurred. It's one of the oldest forms of IPC inherited from Unix/Linux.

> Think of it like a doorbell — it interrupts whatever you're doing and tells you "something happened, deal with it!"

## Signal Lifecycle — Step by Step

```
┌─────────────────────────────────────────────────────────────┐
│                  SIGNAL LIFECYCLE                            │
│                                                             │
│  Step 1: GENERATION                                         │
│  Signal is created by:                                      │
│  • Kernel (hardware fault)                                  │
│  • Another process (kill())                                 │
│  • Process itself (raise())                                 │
│           │                                                 │
│           ▼                                                 │
│  Step 2: DELIVERY                                           │
│  Kernel delivers signal to target process                   │
│  (signal stays "pending" until process is scheduled)        │
│           │                                                 │
│           ▼                                                 │
│  Step 3: PROCESSING — three options:                        │
│  ┌─────────────────────────┐                               │
│  │ 1. Default Action        │ Usually kills process         │
│  │ 2. Custom Handler        │ Your own code runs            │
│  │ 3. Ignore Signal         │ Signal is discarded           │
│  └─────────────────────────┘                               │
└─────────────────────────────────────────────────────────────┘
```

```
              Signal Arrives at Process
                        │
            ┌───────────┼───────────┐
            ▼           ▼           ▼
     ┌──────────┐ ┌──────────┐ ┌──────────┐

     │ ACTION   │ │ HANDLER  │ │  SIGNAL  │
     ├──────────┤ ├──────────┤ ├──────────┤
     │ Usually  │ │ Your own │ │ Signal   │

     └──────────┘ └──────────┘ └──────────┘
```

## Code Examples

### Example 1: Sending a Signal (`kill()`)

```c
// sender_process.c
#include <stdio.h>
#include <signal.h>
#include <unistd.h>

int main() {
    pid_t target_pid = 1234;

    int result = kill(target_pid, SIGTERM);

    if (result == 0)
        printf("Signal sent successfully!\n");
    else
        printf("Failed to send signal!\n");

    return 0;
}
```

```
┌──────────────┐    kill(1234, SIGTERM)    ┌──────────────┐
│  Sender      │ ────────────────────────► │  Process     │
│  Process     │       SIGTERM (15)        │  PID: 1234   │
└──────────────┘                           └──────────────┘
```

### Example 2: Handling a Signal (`signal()`)

```c
// receiver_process.c
#include <stdio.h>
#include <signal.h>
#include <unistd.h>

void my_signal_handler(int signum) {
    printf("Caught signal %d!\n", signum);
    printf("Performing cleanup before exiting...\n");
}

int main() {
    signal(SIGTERM, my_signal_handler);  // Custom handler
    signal(SIGINT,  SIG_IGN);           // Ignore Ctrl+C

    printf("Process PID: %d\n", getpid());
    printf("Waiting for signals...\n");

    while (1) {
        sleep(1);
        printf("Working...\n");
    }
    return 0;
}
```

### Example 3: Using `sigaction()` (Modern & Recommended)

```c
#include <stdio.h>
#include <signal.h>
#include <string.h>
#include <unistd.h>

void handler(int sig, siginfo_t *info, void *context) {
    printf("Signal %d received from process %d\n", sig, info->si_pid);
}

int main() {
    struct sigaction sa;
    memset(&sa, 0, sizeof(sa));

    sa.sa_sigaction = handler;
    sa.sa_flags     = SA_SIGINFO;  // Use sa_sigaction instead of sa_handler

    sigaction(SIGUSR1, &sa, NULL);

    printf("My PID: %d, waiting for SIGUSR1...\n", getpid());

    while (1) pause();  // Wait for any signal
    return 0;
}
```

### Example 4: Process Sending Signal to Itself

```c
#include <stdio.h>
#include <signal.h>
#include <unistd.h>

void alarm_handler(int signum) {
    printf("⏰ ALARM! Time's up!\n");
}

int main() {
    signal(SIGALRM, alarm_handler);

    printf("Setting alarm for 5 seconds...\n");
    alarm(5);  // Sends SIGALRM to itself after 5 seconds

    printf("Doing some work...\n");
    pause();   // Wait for the alarm

    printf("Continuing after alarm.\n");
    return 0;
}
```

## Using Signals via ADB

```bash
# List all processes
adb shell ps

# Send SIGTERM (graceful shutdown)
adb shell kill -15 <PID>

# Send SIGKILL (force kill)
adb shell kill -9 <PID>

# Send SIGQUIT (thread dump — useful for debugging ANR)
adb shell kill -3 <PID>

# Send SIGUSR1 (user-defined signal)
adb shell kill -10 <PID>

# Kill an app by package name (internally uses SIGKILL)
adb shell am force-stop com.example.myapp
```

## Signal Masking (Blocking Signals)

```
┌─────────────────────────────────────────────────────────────┐
│                  SIGNAL MASKING                             │
│                                                             │
│   Normal ──► Block SIGINT ──► Critical ──► Unblock SIGINT  │
│   Code       (mask signal)    Section       (deliver now!)  │
│                                                             │
│               SIGINT arrives here                           │
│               ↓ (queued, not delivered)                     │
│                                                             │
│   ⚠️ SIGKILL and SIGSTOP CANNOT be blocked!               │
└─────────────────────────────────────────────────────────────┘
```

```c
#include <signal.h>

void critical_section() {
    sigset_t block_set, old_set;

    sigemptyset(&block_set);
    sigaddset(&block_set, SIGINT);

    sigprocmask(SIG_BLOCK, &block_set, &old_set);  // Block SIGINT

    // ---- CRITICAL SECTION ----
    printf("Doing critical work...\n");  // SIGINT won't interrupt this
    // ---- END CRITICAL SECTION ----

    sigprocmask(SIG_SETMASK, &old_set, NULL);  // Restore — pending SIGINT delivered now
}
```

## Android Java Layer — Signal Handling

```java
public class MyApplication extends Application {

    @Override
    public void onCreate() {
        super.onCreate();

        // Register a shutdown hook (handles SIGTERM)
        Runtime.getRuntime().addShutdownHook(new Thread() {
            @Override
            public void run() {
                Log.d("Signal", "Process is being terminated!");
                // Save data, close connections, etc.
            }
        });

        // Handle uncaught exceptions (related to SIGSEGV, SIGABRT)
        Thread.setDefaultUncaughtExceptionHandler(
            new Thread.UncaughtExceptionHandler() {
                @Override
                public void uncaughtException(Thread t, Throwable e) {
                    Log.e("Crash", "Uncaught exception in " + t.getName(), e);
                }
            }
        );
    }
}
```

## Important Signal Rules

```
┌─────────────────────────────────────────────────────────────┐
│                    SIGNAL RULES                             │
│                                                             │
│  ✅ CAN DO:                                                │
│     • Catch and handle most signals                         │
│     • Ignore most signals                                   │
│     • Block/mask most signals temporarily                   │
│     • Send signals to processes you own                     │
│     • Send signals as root to any process                   │
│                                                             │
│  ❌ CANNOT DO:                                              │
│     • Catch SIGKILL (9)  — always kills                     │
│     • Catch SIGSTOP (19) — always stops                     │
│     • Ignore SIGKILL or SIGSTOP                             │
│     • Send signals to processes without permission          │
│     • Send data along with signals (only signal number)     │
│     • Guarantee signal delivery order                       │
│     • Queue multiple identical signals (may merge)          │
└─────────────────────────────────────────────────────────────┘
```

## Internal Flow — How Kernel Delivers Signals

```
Process A calls: kill(pid_B, SIGUSR1)
      │
      ▼
┌──────────────────────────────────────────────┐
│              KERNEL SPACE                     │
│                                               │
│  1. Validate permissions                      │
│     (Can Process A send to Process B?)        │
│              │                                │
│              ▼                                │
│  2. Find Process B's task_struct              │
│              │                                │
│              ▼                                │
│  3. Add signal to Process B's pending queue   │
│     ┌───┬───┬───┬───┬───┐                   │
│     │ 10│   │   │   │   │  pending signals   │
│     └───┴───┴───┴───┴───┘                   │
│              │                                │
│              ▼                                │
│  4. Check if signal is blocked (masked)       │
│     • If blocked → stays in pending queue     │
│     • If not blocked → proceed                │
│              │                                │
│              ▼                                │
│  5. Wake up Process B (if sleeping)           │
└──────────────┼───────────────────────────────┘
               ▼
┌──────────────────────────────────────────────┐
│            PROCESS B (User Space)             │
│                                               │
│  6. Before returning to user mode,            │
│     kernel checks pending signals             │
│              │                                │
│              ▼                                │
│  7. Signal Handler executes                   │
│     void handler(int sig) { ... }             │
│              │                                │
│              ▼                                │
│  8. Process resumes normal execution          │
└──────────────────────────────────────────────┘
```

## Real Android Scenarios

### Scenario 1: Native Crash Handling

```
App does:  int *ptr = NULL; *ptr = 42;
                 │
                 ▼
   CPU raises hardware fault (Memory Access Violation)
                 │
                 ▼
   Kernel converts to SIGSEGV and sends to the process
                 │
                 ▼
   Android's crash handler (debuggerd) catches it
                 │
                 ▼
   Tombstone file generated: /data/tombstones/tombstone_00
                 │
                 ▼
   "App has stopped" dialog shown to user
```

### Scenario 2: Zygote and Child Process Management

```
┌──────────┐         fork()          ┌──────────┐
│          │ ─────────────────────►  │  App     │
│  Zygote  │                         │ Process  │
│          │◄────── SIGCHLD ──────── │ (child)  │
│          │   (child terminated)    └──────────┘
└──────────┘
      │
      ▼
Zygote's SIGCHLD handler:
• Calls waitpid() to collect exit status
• Prevents zombie processes
• Notifies system_server
```

## Summary

```
┌─────────────────────────────────────────────────────────────┐
│                     KEY TAKEAWAYS                           │
│                                                             │
│  1. Signals = Asynchronous notifications to processes       │
│                                                             │
│  2. Only carry signal NUMBER (no data payload)              │
│                                                             │
│  3. SIGKILL (9) & SIGSTOP (19) = Uncatchable               │
│                                                             │
│  4. Android uses signals for:                               │
│     • Killing apps (SIGKILL via LMK)                       │
│     • ANR detection (SIGQUIT for thread dumps)              │
│     • Crash handling (SIGSEGV, SIGABRT)                     │
│     • Child process management (SIGCHLD)                    │
│                                                             │
│  5. Signals are LIGHTWEIGHT but LIMITED                     │
│     (no complex data transfer)                              │
│                                                             │
│  6. Binder is preferred for most Android IPC               │
│     Signals are used for system-level notifications         │
└─────────────────────────────────────────────────────────────┘
```
