# Socket IPC in Android — Complete Guide

## What is Socket IPC?

Socket IPC allows two or more processes (or apps) to communicate using sockets — just like how computers communicate over a network, but here it happens within the same device.

```
┌─────────────────────────────────────────────────┐
│                ANDROID DEVICE                    │
│                                                  │
│  ┌──────────────┐         ┌──────────────┐      │
│  │   Process A   │◄──────►│   Process B   │      │
│  │  (Client App) │ Socket │ (Server App)  │      │
│  └──────────────┘  IPC   └──────────────┘      │
└─────────────────────────────────────────────────┘
```

## Code Example 1: Network Socket (TCP)

### Server Side

```java
public class SocketServerService extends Service {

    private ServerSocket serverSocket;
    private boolean isRunning = true;

    @Override
    public int onStartCommand(Intent intent, int flags, int startId) {
        new Thread(() -> {
            try {
                serverSocket = new ServerSocket(8080);
                Log.d("Server", "Server started on port 8080");

                while (isRunning) {
                    Socket clientSocket = serverSocket.accept();
                    Log.d("Server", "Client connected!");
                    handleClient(clientSocket);
                }
            } catch (IOException e) {
                e.printStackTrace();
            }
        }).start();
        return START_STICKY;
    }

    private void handleClient(Socket clientSocket) {
        new Thread(() -> {
            try {
                BufferedReader input = new BufferedReader(
                        new InputStreamReader(clientSocket.getInputStream()));
                PrintWriter output = new PrintWriter(
                        clientSocket.getOutputStream(), true);

                String message = input.readLine();
                Log.d("Server", "Received: " + message);

                output.println("Hello from Server! Got: " + message);
                clientSocket.close();
            } catch (IOException e) {
                e.printStackTrace();
            }
        }).start();
    }

    @Override
    public void onDestroy() {
        isRunning = false;
        try { serverSocket.close(); } catch (IOException e) { e.printStackTrace(); }
    }

    @Override public IBinder onBind(Intent intent) { return null; }
}
```

### LocalSocket Server

```java
public class LocalSocketServer extends Service {

    private LocalServerSocket serverSocket;
    private boolean isRunning = true;

    @Override
    public int onStartCommand(Intent intent, int flags, int startId) {
        new Thread(() -> {
            try {
                serverSocket = new LocalServerSocket("my_app_socket");
                Log.d("LocalServer", "Local server started");

                while (isRunning) {
                    LocalSocket clientSocket = serverSocket.accept();
                    handleLocalClient(clientSocket);
                }
            } catch (IOException e) {
                e.printStackTrace();
            }
        }).start();
        return START_STICKY;
    }

    private void handleLocalClient(LocalSocket clientSocket) {
        new Thread(() -> {
            try {
                InputStream input = clientSocket.getInputStream();
                byte[] buffer = new byte[1024];
                int bytesRead = input.read(buffer);
                String message = new String(buffer, 0, bytesRead);
                Log.d("LocalServer", "Received: " + message);

                OutputStream output = clientSocket.getOutputStream();
                output.write(("Server received: " + message).getBytes());
                output.flush();

                clientSocket.close();
            } catch (IOException e) {
                e.printStackTrace();
            }
        }).start();
    }

    @Override public IBinder onBind(Intent intent) { return null; }
}
```

### LocalSocket Client

```java
public class LocalSocketClient {

    public void sendMessage(String message) {
        new Thread(() -> {
            try {
                LocalSocket socket = new LocalSocket();
                LocalSocketAddress address = new LocalSocketAddress(
                        "my_app_socket",
                        LocalSocketAddress.Namespace.ABSTRACT);
                socket.connect(address);

                OutputStream output = socket.getOutputStream();
                output.write(message.getBytes());
                output.flush();

                InputStream input = socket.getInputStream();
                byte[] buffer = new byte[1024];
                int bytesRead = input.read(buffer);
                Log.d("LocalClient", "Response: " + new String(buffer, 0, bytesRead));

                socket.close();
            } catch (IOException e) {
                e.printStackTrace();
            }
        }).start();
    }
}
```

## Advanced: Thread Pool Server

```java
public class ThreadPoolSocketServer extends Service {

    private ExecutorService threadPool;
    private ServerSocket serverSocket;

    @Override
    public void onCreate() {
        super.onCreate();
        threadPool = Executors.newFixedThreadPool(10);
    }

    @Override
    public int onStartCommand(Intent intent, int flags, int startId) {
        new Thread(() -> {
            try {
                serverSocket = new ServerSocket(9090);
                while (!Thread.interrupted()) {
                    Socket client = serverSocket.accept();
                    threadPool.submit(new ClientHandler(client));
                }
            } catch (IOException e) {
                e.printStackTrace();
            }
        }).start();
        return START_STICKY;
    }

    private static class ClientHandler implements Runnable {
        private final Socket clientSocket;

        ClientHandler(Socket socket) { this.clientSocket = socket; }

        @Override
        public void run() {
            try {
                BufferedReader in  = new BufferedReader(
                        new InputStreamReader(clientSocket.getInputStream()));
                PrintWriter    out = new PrintWriter(
                        clientSocket.getOutputStream(), true);

                String line;
                while ((line = in.readLine()) != null) {
                    out.println("Processed: " + line + " at " + System.currentTimeMillis());
                    if ("bye".equalsIgnoreCase(line)) break;
                }
                clientSocket.close();
            } catch (IOException e) {
                e.printStackTrace();
            }
        }
    }

    @Override public IBinder onBind(Intent intent) { return null; }
}
```

## When to Use Socket IPC

```
┌─────────────────────────────────────────┐
│           USE SOCKET IPC WHEN:          │
│                                         │
│  ✅ Need continuous data streaming      │
│  ✅ Communicating with native daemons   │
│  ✅ Need bi-directional communication   │
│  ✅ Cross-platform compatibility needed │
│  ✅ Large data transfer                 │
│  ✅ Real-time communication             │
│  ✅ Communication with non-Android proc │
│                                         │
│           AVOID SOCKET IPC WHEN:        │
│                                         │
│  ❌ Simple one-way messages (use Intent)│
│  ❌ RPC-style calls (use Binder/AIDL)  │
│  ❌ Sharing database (use ContentProv.) │
│  ❌ Same process communication          │
└─────────────────────────────────────────┘
```

## 1. Zygote Socket — App Process Forking

### What is Zygote?

```
┌─────────────────────────────────────────────────────────────────┐
│                    ZYGOTE EXPLAINED                              │
│                                                                  │
│  Zygote is the "mother process" of all Android apps.            │
│  Every app is FORKED from Zygote to save startup time.          │
│                                                                  │
│  • Pre-loaded Android Framework classes                          │
│  • Pre-initialized ART runtime                                   │
│  • Listens on /dev/socket/zygote                                │
│  • Listens on /dev/socket/zygote_secondary (32-bit)             │
└─────────────────────────────────────────────────────────────────┘
```

### How App Launch Works via Zygote Socket

```
   ActivityManagerService (system_server)       Zygote Process
   ════════════════════════════════════         (/dev/socket/zygote)

   User taps app icon
         │
         ▼
   startProcess Request
         │
         │  ① Connect to zygote socket
         │──────────────────────────────────────────────────────►
         │                                                ┌───────┐
         │                                                │Accept │
         │                                                └───┬───┘
         │  ② Send spawn command (JSON/Args)                  │
         │──────────────────────────────────────────────────► │
         │                                                ┌───▼───┐
         │                                                │fork() │
         │                                                │ new   │
         │                                                │process│
         │                                                └───┬───┘
         │  ③ Receive new process PID                         │
         │◄────────────────────────────────────────────────── │
         │
   AMS tracks new app PID              New App Process (Fork of Zygote)
```


### AOSP Code (Simplified)

```java
// frameworks/base/core/java/android/os/ZygoteProcess.java

public class ZygoteProcess {

    private static final String ZYGOTE_SOCKET = "zygote";
    private static final String ZYGOTE_SECONDARY_SOCKET = "zygote_secondary";

    public final Process.ProcessStartResult start(
            final String processClass, final String niceName,
            int uid, int gid, int[] gids, ...) {

        ZygoteState state = openZygoteSocketIfNeeded(abi);
        return zygoteSendArgsAndGetResult(state, argsForZygote);
    }

    private ZygoteState openZygoteSocketIfNeeded(String abi) {
        return ZygoteState.connect(
            new LocalSocketAddress(ZYGOTE_SOCKET,
                LocalSocketAddress.Namespace.RESERVED)
        );
    }
}
```

```java
// frameworks/base/core/java/com/android/internal/os/ZygoteServer.java

class ZygoteServer {

    private LocalServerSocket mZygoteSocket;

    ZygoteServer(boolean isPrimaryZygote) {
        if (isPrimaryZygote) {
            mZygoteSocket = Zygote.createManagedSocketFromInitSocket(
                Zygote.PRIMARY_SOCKET_NAME   // "zygote"
            );
        } else {
            mZygoteSocket = Zygote.createManagedSocketFromInitSocket(
                Zygote.SECONDARY_SOCKET_NAME // "zygote_secondary"
            );
        }
    }

    Runnable runSelectLoop(String abiList) {
        while (true) {
            ZygoteConnection connection = acceptCommandPeer(abiList);
            connection.processOneCommand(this);  // Handle fork request from AMS
        }
    }
}
```

# 🔑 `android_get_control_socket()` — Complete Explanation

---

## What is it in One Line?

`android_get_control_socket()` retrieves a **pre-created socket file descriptor** that the `init` process already created for your daemon — so the daemon never has to create the socket itself.

---

## The Problem it Solves

### Without it — the painful way

```
Your daemon must:
  1. Run as ROOT to create files in /dev/socket/
  2. Call socket() itself
  3. Call bind() itself
  4. Set file permissions (chmod)
  5. Set file ownership (chown)
  6. Handle "address already in use" on restart
  7. Clean up stale socket files

Problems:
  ❌ Daemon needs root privileges
  ❌ Security risk
  ❌ More code = more bugs
  ❌ Race condition — socket may not be ready when needed
```

### With it — the AOSP way

```
init does all the privileged work:
  ✅ Creates the socket (running as root)
  ✅ Binds to /dev/socket/<name>
  ✅ Sets correct permissions and ownership

Your daemon just does:
  int fd = android_get_control_socket("my_daemon");
  listen(fd, 4);   ← that's it!

Benefits:
  ✅ Daemon runs as non-root (safer!)
  ✅ Much less code
  ✅ Socket is ready before the daemon even starts
  ✅ Consistent with every other AOSP daemon
```

---

## How it Works — Boot Sequence

```
1.  Kernel boots
    ↓
2.  init starts (running as ROOT)
    ↓
3.  init reads /init.rc and device .rc files
    ↓
4.  init sees: socket my_daemon stream 660 system system
    ↓
5.  init calls socket() + bind()
    → creates /dev/socket/my_daemon
    ↓
6.  init sets permissions (660) and ownership (system:system)
    ↓
7.  init stores the fd in an environment variable:
    ANDROID_SOCKET_my_daemon = "5"
    ↓
8.  init forks + execs your daemon
    → daemon inherits all environment variables
    → daemon inherits all open file descriptors
    ↓
9.  Daemon calls:
    android_get_control_socket("my_daemon")
    ↓
10. Function reads ANDROID_SOCKET_my_daemon → fd = 5
    ↓
11. Daemon calls listen(fd, 4)
    Done — ready to accept connections
```

---

## The Source Code

```c
// system/core/libcutils/sockets.cpp

int android_get_control_socket(const char* name) {

    // Build env variable name: "ANDROID_SOCKET_" + name
    char key[64];
    snprintf(key, sizeof(key), "ANDROID_SOCKET_%s", name);
    // key = "ANDROID_SOCKET_my_daemon"

    // Read the value init set before starting the daemon
    const char* val = getenv(key);
    if (val == NULL) {
        return -1;   // socket not in .rc, or not started by init
    }

    // Convert "5" → 5 and return the fd
    return atoi(val);

    // That's it — essentially getenv() + atoi()
    // The real work was done by init before this call
}
```

## What `init` Does Internally

```c
// Simplified from system/core/init/service.cpp
// This runs when init sees "socket my_daemon stream 660 system system"

void init_create_socket(const char* name, int type,
                        mode_t permissions, uid_t uid, gid_t gid) {

    // init runs as root — can create files anywhere
    int fd = socket(AF_UNIX, type, 0);

    char path[128];
    snprintf(path, sizeof(path), "/dev/socket/%s", name);

    unlink(path);   // clean up stale file from previous run

    struct sockaddr_un addr;
    memset(&addr, 0, sizeof(addr));
    addr.sun_family = AF_UNIX;
    strncpy(addr.sun_path, path, sizeof(addr.sun_path) - 1);

    bind(fd, (struct sockaddr*)&addr, sizeof(addr));

    chmod(path, permissions);   // 0660
    chown(path, uid, gid);      // system:system

    // Store fd in env so the daemon can retrieve it
    char key[64], val[16];
    snprintf(key, sizeof(key), "ANDROID_SOCKET_%s", name);
    snprintf(val, sizeof(val), "%d", fd);
    setenv(key, val, 1);
    // ANDROID_SOCKET_my_daemon=5

    // When init forks the daemon:
    //   → env variables are inherited
    //   → open fds are inherited
    //   → daemon gets fd=5 pointing to the socket
}
```

```rc
    socket my_daemon  stream  660     system  system
```


### Daemon code

```c
// my_daemon/main.c
// Notice: NO socket(), NO bind() anywhere

#include <stdio.h>
#include <string.h>
#include <unistd.h>
#include <sys/socket.h>
#include <cutils/sockets.h>
#include <android/log.h>

#define LOG_TAG "my_daemon"
#define LOGI(...) __android_log_print(ANDROID_LOG_INFO,  LOG_TAG, __VA_ARGS__)
#define LOGE(...) __android_log_print(ANDROID_LOG_ERROR, LOG_TAG, __VA_ARGS__)

int main() {
    // Step 1: get the fd init already created
    // Name must EXACTLY match the .rc socket declaration
    int server_fd = android_get_control_socket("my_daemon");
    if (server_fd < 0) {
        LOGE("Failed — check .rc file and that daemon was started by init");
        return 1;
    }
    LOGI("Got socket fd=%d", server_fd);
    // /dev/socket/my_daemon already exists — we didn't create it!

    // Step 2: start listening
    if (listen(server_fd, 4) < 0) {
        LOGE("listen() failed");
        return 1;
    }
    LOGI("Listening on /dev/socket/my_daemon");

    // Step 3: main loop
    while (1) {
        int client_fd = accept(server_fd, NULL, NULL);
        if (client_fd < 0) { LOGE("accept() failed"); continue; }

        LOGI("Client connected!");

        char buf[256];
        memset(buf, 0, sizeof(buf));
        int n = read(client_fd, buf, sizeof(buf) - 1);
        if (n > 0) {
            LOGI("Received: %s", buf);
            write(client_fd, "OK", 2);
        }
        close(client_fd);
    }
    return 0;
}
```

# 🔌 When to Use Socket IPC Over Other IPC Mechanisms in AOSP

---

## IPC Options in AOSP

| Mechanism | Primary Use |
|-----------|------------|
| **Binder** | Most common — Java/C++ framework services |
| **Socket** | Native daemons, streaming data, kernel events |
| **Shared Memory** | Large data, zero-copy transfer |
| **Pipe** | Simple one-way, parent-child |
| **Signal** | Simple notifications only |

---

## Quick Comparison

| Feature | Socket | Binder | Shared Mem | Pipe | Signal |
|---------|--------|--------|-----------|------|--------|
| Cross-language (C++↔Java) | ✅ | ⚠️ needs AIDL | ⚠️ manual | ✅ | ✅ |
| Streaming / large data | ✅ | ❌ 1 MB limit | ✅ zero-copy | ✅ slow | ❌ |
| Kernel ↔ userspace | ✅ Netlink | ❌ | ❌ | ❌ | ✅ limited |
| Works without Android fwk | ✅ | ❌ needs ServiceMgr | ❌ | ⚠️ one-way | ✅ |
| Bidirectional | ✅ | ✅ | ✅ manual | ❌ | ❌ |
| Easy to use | ⚠️ manual protocol | ✅ AIDL gen | ❌ complex | ✅ | ✅ |
| Security | ✅ SELinux + perms | ✅ UID/PID check | ⚠️ harder | ✅ | ⚠️ can be faked |

## 7 Solid Reasons to Choose Socket

---

### 1. No Android Framework Dependency

**Problem:** Binder requires `ServiceManager`, which starts **after** early daemons.

```
Boot timeline:
  100ms  → init starts
  200ms  → vold starts       ← EARLY boot daemon
  500ms  → ServiceManager    ← Binder becomes available
  2000ms → system_server
  3000ms → ActivityManager ready
```

`vold` starts at 200ms — `ServiceManager` isn't alive yet. Binder registration would fail or hang.

```c
// ❌ WRONG — ServiceManager may not exist yet
void setup_binder() {
    sp<IServiceManager> sm = defaultServiceManager();  // FAILS at early boot
    sm->addService(String16("vold"), new VoldService());
}

// ✅ CORRECT — socket works immediately, no dependencies
int main() {
    int fd = android_get_control_socket("vold");
    listen(fd, 4);   // ready at any boot stage
}
```

---

### 2. Cross-Language Communication (C++ ↔ Java) Without AIDL

Sockets speak plain bytes — any language can read and write them.

```c
// C++ daemon (vold) — just write a string
void send_response(int fd, int code, const char* message) {
    char buf[512];
    snprintf(buf, sizeof(buf), "%d %s\n", code, message);
    write(fd, buf, strlen(buf));
}

send_response(client_fd, 200, "Volume emulated mounted");
send_response(client_fd, 630, "Volume state changed usb 2");  // async event
```

```java
// Java service (StorageManagerService) — just read a string
BufferedReader reader = new BufferedReader(
    new InputStreamReader(socket.getInputStream()));

String line  = reader.readLine();       // "200 Volume emulated mounted"
int    code  = Integer.parseInt(line.split(" ", 3)[0]);  // 200
```

Compare with Binder:
- ❌ Needs `IVold.aidl`
- ❌ Needs generated stubs in C++ and Java
- ❌ C++ daemon must link `libbinder`

### 3. Kernel ↔ Userspace Communication (Netlink)

**Only Netlink sockets can receive events directly from the Linux kernel.** Binder, pipes, and shared memory cannot cross the kernel/userspace boundary for event delivery.

```
  KERNEL
  ┌────────────────────────────────────────────┐
  │  Network Driver  Battery Driver  USB Driver │
  │  "Interface up"  "20% battery"  "USB plug" │
  └──────────────────────┬─────────────────────┘
                         │ Netlink Socket ONLY
  USER SPACE             │
  ┌──────────────────────▼─────────────────────┐
  │   netd (network)   ueventd (hw)   healthd  │
  └────────────────────────────────────────────┘
```

```c
// ueventd — real file: system/core/init/ueventd.cpp
// There is NO OTHER WAY to receive hardware plug events

int open_uevent_socket() {
    int sock = socket(AF_NETLINK, SOCK_DGRAM, NETLINK_KOBJECT_UEVENT);

    struct sockaddr_nl addr = {0};
    addr.nl_family = AF_NETLINK;
    addr.nl_groups = 1;   // all uevent groups
    bind(sock, (struct sockaddr*)&addr, sizeof(addr));
    return sock;
}

void listen_for_hardware_events(int sock) {
    char buffer[4096];
    while (true) {
        recv(sock, buffer, sizeof(buffer), 0);
        // "add@/devices/platform/usb/usb1"    → USB plugged in
        // "remove@/devices/platform/usb/usb1" → USB removed
        // "change@/class/power_supply/battery" → battery changed
        parse_and_handle_uevent(buffer);
    }
}
```

### 4. Streaming Large / Continuous Data

Binder has a hard transaction limit of **~1 MB**. Sockets have no such limit.

```
What Binder can't stream:
  ❌ Camera video  (30fps × 4K)
  ❌ Audio stream  (continuous)
  ❌ Log stream    (never-ending)
  ❌ Firmware OTA  (100 MB+)
```

```c
// logcat — streams logs continuously from logd via socket
void stream_logs() {
    int fd = socket_local_client("logdr",
                                 ANDROID_SOCKET_NAMESPACE_RESERVED,
                                 SOCK_SEQPACKET);

    const char* cmd = "stream lids=0,1,2,3,4,5";
    write(fd, cmd, strlen(cmd));

        struct logger_entry entry;
        int n = read(fd, &entry, sizeof(entry));

}
```

With Binder you would need:
- ❌ Repeated polling (expensive)
- ❌ Manual chunking to stay under 1 MB
- ❌ Complex reassembly logic

### 6. Fine-Grained Access Control With `SO_PEERCRED`

Sockets offer three independent security layers:

```
Layer 1 — Filesystem permissions
  srw-rw---- root install /dev/socket/installd
  Only root and 'install' group can even open the socket

Layer 2 — SELinux policy
  Even with permissions, SELinux can block specific processes

Layer 3 — SO_PEERCRED in daemon code
  Daemon verifies the UID/PID of the connecting process
  This comes from the KERNEL — cannot be faked by the client
```

```c
void verify_client(int client_fd) {
    struct ucred cred;
    socklen_t len = sizeof(cred);

    getsockopt(client_fd, SOL_SOCKET, SO_PEERCRED, &cred, &len);

    printf("PID=%d  UID=%d  GID=%d\n", cred.pid, cred.uid, cred.gid);

    // UID 1000 = system (system_server runs as this)
    if (cred.uid != 1000) {
        write(client_fd, "403 Forbidden", 13);
        close(client_fd);
        return;
    }

    handle_request(client_fd);   // only system_server gets through
}
// Even if a malicious app gets the socket path,
// the kernel-provided UID will expose it and the daemon rejects it.
```

# 📍 Socket Addresses in AOSP — Complete Guide

---

## What is a Socket Address?

A socket address is like a **home address** — if a process wants to connect to your socket, it needs to know where to find it.

```
Real world:   "123 Main Street, New York"  → find a house
Socket world: "/dev/socket/vold"           → find a Unix socket
              "192.168.1.100:8080"         → find a TCP socket
              "NETLINK_ROUTE group 1"      → find a Netlink socket
```

### Why it's needed

```
Without address:
  Process A creates a socket...
  Process B: "WHERE IS Process A's socket?" → cannot connect!

With address:
  Process A binds socket to "/dev/socket/myservice"
  Process B: connect("/dev/socket/myservice") → connected ✅
```

---

## Address Structures in C

Every socket type has its own address structure, but all are cast to the generic `struct sockaddr*` when passed to `bind()` / `connect()`.

```c
// Generic base type — always used in bind/connect calls
struct sockaddr {
    sa_family_t sa_family;    // AF_UNIX, AF_INET, AF_NETLINK, ...
    char        sa_data[14];  // actual address data
};

// Unix Domain Socket
struct sockaddr_un {
    sa_family_t sun_family;    // AF_UNIX
    char        sun_path[108]; // file path or abstract name
};

// TCP / UDP (IPv4)
struct sockaddr_in {
    sa_family_t    sin_family; // AF_INET
    in_port_t      sin_port;   // port number (e.g. 8080)
    struct in_addr sin_addr;   // IP address (e.g. 192.168.1.1)
};

// Netlink
struct sockaddr_nl {
    sa_family_t    nl_family;  // AF_NETLINK
    unsigned short nl_pad;     // unused
    pid_t          nl_pid;     // our PID, or 0 to address the kernel
    __u32          nl_groups;  // event groups to subscribe to
};
```

---

## Type 1 — Unix Domain Socket Address

**Address = a file path** (or an abstract name in kernel memory)

```
File-based:  "/dev/socket/vold"       → visible in filesystem
Abstract:    "\0my_abstract_socket"   → starts with null byte, no file
```

### Server — filesystem socket

```c
#include <sys/socket.h>
#include <sys/un.h>
#include <string.h>
#include <unistd.h>

int fd = socket(AF_UNIX, SOCK_STREAM, 0);

struct sockaddr_un addr;
memset(&addr, 0, sizeof(addr));          // always clear first
addr.sun_family = AF_UNIX;
strncpy(addr.sun_path, "/dev/socket/my_daemon", sizeof(addr.sun_path) - 1);

unlink("/dev/socket/my_daemon");         // remove stale file from previous run

bind(fd, (struct sockaddr*)&addr, sizeof(addr));
// After bind:  ls -la /dev/socket/
// srw-rw---- 1 system system ... my_daemon
//  ↑ 's' prefix = socket file

listen(fd, 4);
```

### Server — abstract socket (no file created)

```c
int fd = socket(AF_UNIX, SOCK_STREAM, 0);

struct sockaddr_un addr;
memset(&addr, 0, sizeof(addr));
addr.sun_family = AF_UNIX;
addr.sun_path[0] = '\0';                                      // null byte = abstract
strncpy(addr.sun_path + 1, "my_abstract_socket", sizeof(addr.sun_path) - 2);

// Size = sizeof(family) + 1 (null) + strlen(name)
socklen_t len = sizeof(addr.sun_family) + 1 + strlen("my_abstract_socket");

bind(fd, (struct sockaddr*)&addr, len);
// No file created — lives only in kernel memory
// Disappears when the socket is closed
```

### Client — connecting by address

```c
int fd = socket(AF_UNIX, SOCK_STREAM, 0);

struct sockaddr_un server_addr;
memset(&server_addr, 0, sizeof(server_addr));
server_addr.sun_family = AF_UNIX;
strncpy(server_addr.sun_path, "/dev/socket/my_daemon",
        sizeof(server_addr.sun_path) - 1);   // must match server's path

int result = connect(fd, (struct sockaddr*)&server_addr, sizeof(server_addr));

if (result == 0) {
    write(fd, "hello", 5);
} else {
    perror("connect failed");
    // ENOENT         = socket file doesn't exist (server not running)
    // ECONNREFUSED   = server not listening
}
close(fd);
```

## Type 2 — TCP Socket Address (IP + Port)

**Address = IP address + port number**

```
IP address  = which machine    (192.168.1.100  or  127.0.0.1)
Port number = which service    (5555 = ADB,  8080 = HTTP,  53 = DNS)
Together:   "192.168.1.100:5555"
```

### Server

```c
#include <sys/socket.h>
#include <netinet/in.h>
#include <arpa/inet.h>

int fd = socket(AF_INET, SOCK_STREAM, 0);

struct sockaddr_in addr;
memset(&addr, 0, sizeof(addr));
addr.sin_family      = AF_INET;
addr.sin_port        = htons(5555);    // htons() converts to network byte order — always required
addr.sin_addr.s_addr = INADDR_ANY;     // accept connections on all network interfaces

int reuse = 1;
setsockopt(fd, SOL_SOCKET, SO_REUSEADDR, &reuse, sizeof(reuse));  // allow fast restart

bind(fd, (struct sockaddr*)&addr, sizeof(addr));
listen(fd, 4);

// In accept() you can see who connected:
struct sockaddr_in client_addr;
socklen_t client_len = sizeof(client_addr);
int client_fd = accept(fd, (struct sockaddr*)&client_addr, &client_len);

char client_ip[INET_ADDRSTRLEN];
inet_ntop(AF_INET, &client_addr.sin_addr, client_ip, sizeof(client_ip));
printf("Connection from %s:%d\n", client_ip, ntohs(client_addr.sin_port));
// "Connection from 192.168.1.50:43821"
```

### Client

```c
int fd = socket(AF_INET, SOCK_STREAM, 0);

struct sockaddr_in server_addr;
memset(&server_addr, 0, sizeof(server_addr));
server_addr.sin_family      = AF_INET;
server_addr.sin_port        = htons(5555);
server_addr.sin_addr.s_addr = inet_addr("192.168.1.100");
// Localhost (same machine): inet_addr("127.0.0.1")

int result = connect(fd, (struct sockaddr*)&server_addr, sizeof(server_addr));
if (result == 0) {
    write(fd, "ADB_CONNECT", 11);
} else {
    perror("connect failed");
    // ECONNREFUSED = nothing listening on that port
    // ETIMEDOUT    = IP unreachable or firewall blocking
    // ENETUNREACH  = no network route to host
}
close(fd);
```

> **`127.0.0.1` (loopback):** connects to the same machine only — external hosts cannot reach it.

## Type 3 — Netlink Socket Address

**Address = process ID + event group subscriptions**

Used exclusively for **kernel ↔ userspace** communication. Binder and pipes cannot do this.

```
nl_pid    = who you are (your PID), or 0 when addressing the kernel
nl_groups = which kernel event groups to subscribe to (one bit per group)
```

### Receiving kernel events

```c
#include <sys/socket.h>
#include <linux/netlink.h>
#include <linux/rtnetlink.h>

// NETLINK_ROUTE = receive routing / network change events
int fd = socket(AF_NETLINK, SOCK_DGRAM, NETLINK_ROUTE);

struct sockaddr_nl addr;
memset(&addr, 0, sizeof(addr));
addr.nl_family = AF_NETLINK;
addr.nl_pid    = getpid();          // our PID = our "address"
addr.nl_groups = RTMGRP_LINK        // network interface up/down
               | RTMGRP_IPV4_IFADDR // IPv4 address assigned/removed
               | RTMGRP_IPV4_ROUTE; // route changes

bind(fd, (struct sockaddr*)&addr, sizeof(addr));

char buffer[4096];
while (1) {
    int len = recv(fd, buffer, sizeof(buffer), 0);   // kernel sends events here
    struct nlmsghdr* nlh = (struct nlmsghdr*)buffer;

    if (nlh->nlmsg_type == RTM_NEWLINK)
        printf("Network interface changed\n");   // WiFi connected/disconnected

    if (nlh->nlmsg_type == RTM_NEWADDR)
        printf("IP address assigned\n");         // DHCP gave us an IP
}
```

### Sending a request to the kernel

```c
int fd = socket(AF_NETLINK, SOCK_DGRAM, NETLINK_ROUTE);

// Our address (to receive the reply)
struct sockaddr_nl our_addr = {0};
our_addr.nl_family = AF_NETLINK;
our_addr.nl_pid    = getpid();
bind(fd, (struct sockaddr*)&our_addr, sizeof(our_addr));

// Kernel's address — nl_pid = 0 means "the kernel"
struct sockaddr_nl kernel_addr = {0};
kernel_addr.nl_family = AF_NETLINK;
kernel_addr.nl_pid    = 0;         // ← 0 = kernel

// Build request for routing table
struct { struct nlmsghdr hdr; struct rtmsg rt; } request;
memset(&request, 0, sizeof(request));
request.hdr.nlmsg_len   = sizeof(request);
request.hdr.nlmsg_type  = RTM_GETROUTE;
request.hdr.nlmsg_flags = NLM_F_REQUEST | NLM_F_DUMP;
request.hdr.nlmsg_pid   = getpid();
request.rt.rtm_family   = AF_INET;

sendto(fd, &request, sizeof(request), 0,
       (struct sockaddr*)&kernel_addr, sizeof(kernel_addr));

char response[8192];
recv(fd, response, sizeof(response), 0);
printf("Got routing table from kernel\n");
close(fd);
```

## All Three Types — Side by Side

```c
// ── Unix Domain ─────────────────────────────────────────────
struct sockaddr_un unix_addr;
memset(&unix_addr, 0, sizeof(unix_addr));
unix_addr.sun_family = AF_UNIX;
strcpy(unix_addr.sun_path, "/dev/socket/vold");
// Address = file path   |   Scope = same device

// ── TCP / UDP ────────────────────────────────────────────────
struct sockaddr_in tcp_addr;
memset(&tcp_addr, 0, sizeof(tcp_addr));
tcp_addr.sin_family      = AF_INET;
tcp_addr.sin_port        = htons(5555);
tcp_addr.sin_addr.s_addr = INADDR_ANY;
// Address = IP + port   |   Scope = over network

// ── Netlink ──────────────────────────────────────────────────
struct sockaddr_nl nl_addr;
memset(&nl_addr, 0, sizeof(nl_addr));
nl_addr.nl_family = AF_NETLINK;
nl_addr.nl_pid    = getpid();
nl_addr.nl_groups = RTMGRP_LINK;
// Address = PID + groups  |  Scope = kernel ↔ userspace

// All three use the same bind() pattern — cast to sockaddr*:
int fd1 = socket(AF_UNIX,    SOCK_STREAM, 0);
int fd2 = socket(AF_INET,    SOCK_STREAM, 0);
int fd3 = socket(AF_NETLINK, SOCK_DGRAM,  NETLINK_ROUTE);

bind(fd1, (struct sockaddr*)&unix_addr, sizeof(unix_addr));
bind(fd2, (struct sockaddr*)&tcp_addr,  sizeof(tcp_addr));
bind(fd3, (struct sockaddr*)&nl_addr,   sizeof(nl_addr));
//         ↑ always cast to (struct sockaddr*)
//           kernel reads sa_family to determine the real type
```

---

## Summary

| | Unix Domain | TCP / UDP | Netlink |
|-|-------------|-----------|---------|
| **Address is** | File path (or abstract name) | IP + Port | PID + event groups |
| **Scope** | Same device only | Over network | Kernel ↔ userspace |
| **Socket file created?** | ✅ (filesystem) / ❌ (abstract) | ❌ | ❌ |
| **AOSP examples** | `vold`, `netd`, `zygote`, `installd` | `adbd` (port 5555) | `ueventd`, `netd`, `healthd` |

```
Server: bind(fd, &address, size)    → "I live at this address"
Client: connect(fd, &address, size) → "I want to talk to this address"
```

## 1. What We Are Building

A real-time device health monitoring system:

- Monitors battery, CPU, memory, and temperature continuously
- Native C++ daemon reads hardware data directly from the kernel
- Streams data to a Java framework service via Unix domain socket
- Java service exposes data to apps via Binder
- Kernel sends hardware alerts directly via Netlink socket

## 3. Why NOT AIDL Between Daemon and Service?

This is the key design decision. Here's why socket beats AIDL at this layer:

### Reason 1 — Daemon Starts Before Binder Exists

```
Boot order:
  Kernel
    ↓
  init
    ↓
  health_monitor_daemon   ← starts HERE ✅
    ↓
  ServiceManager          ← starts LATER ❌
    ↓
  system_server (Java)
```

AIDL/Binder requires `ServiceManager`. But when the daemon starts, `ServiceManager` doesn't exist yet. Socket has **no dependency** — it works the moment the process starts.

### Reason 2 — Continuous Streaming

The daemon sends data every 2 seconds:

```
HEALTH|85|35.0|Discharging|Good|...
HEALTH|84|35.1|Discharging|Good|...
HEALTH|83|35.2|Discharging|Good|...
```

Binder is **request-response** based — you must call a method every time:

```
getHealth()   getHealth()   getHealth()   ← inefficient
```

With a socket, the daemon just keeps writing and Java just keeps reading over one persistent connection — ideal for streaming.

### Reason 3 — Kernel Communication Requires Sockets

The daemon already uses a **Netlink socket** to receive thermal/battery events from the kernel. Binder **cannot** talk to kernel drivers. Only sockets can.

### Reason 4 — Cross-Language Simplicity

```
With AIDL (C++ ↔ Java):           With Socket:
  → Write .aidl file                → Send plain text
  → Generate Binder stubs           → Java splits string
  → Link libbinder in native        → Done ✅
  → More complexity
```

### When Should You Use AIDL?

| Use AIDL when | Use Socket when |
|---------------|----------------|
| Java ↔ Java services | C++ daemon ↔ Java service |
| Framework service ↔ App | Early boot (before ServiceManager) |
| Clear get/set API | Continuous streaming |
| Not streaming large data | Kernel communication needed |

```
Daemon ↔ Service  → Socket  ✅
Service ↔ App     → AIDL    ✅
```

## 5. Step 2 — Native C++ Daemon

```cpp
// device/mycompany/mydevice/health_monitor_daemon/main.cpp

#define LOG_TAG "HealthMonDaemon"

#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <unistd.h>
#include <errno.h>
#include <pthread.h>
#include <sys/socket.h>
#include <sys/un.h>
#include <linux/netlink.h>
#include <cutils/sockets.h>
#include <log/log.h>

// ── Sysfs paths (kernel exposes hardware info here) ──────────────────
#define BATTERY_CAPACITY  "/sys/class/power_supply/battery/capacity"
#define BATTERY_TEMP      "/sys/class/power_supply/battery/temp"
#define BATTERY_STATUS    "/sys/class/power_supply/battery/status"
#define BATTERY_HEALTH    "/sys/class/power_supply/battery/health"
#define CPU_TEMP          "/sys/class/thermal/thermal_zone0/temp"
#define CPU_FREQ          "/sys/devices/system/cpu/cpu0/cpufreq/scaling_cur_freq"
#define MEM_INFO          "/proc/meminfo"

// ── Health data structure ─────────────────────────────────────────────
typedef struct {
    int   battery_percent;
    int   battery_temp;        // tenths of °C  (350 = 35.0°C)
    char  battery_status[32];
    char  battery_health[32];
    int   cpu_temp;            // millidegrees  (45000 = 45°C)
    long  cpu_freq_khz;
    long  mem_total_kb;
    long  mem_available_kb;
    int   is_critical;
} HealthData;

// ── Global state ──────────────────────────────────────────────────────
#define MAX_CLIENTS 8
static int g_server_fd  = -1;
static int g_netlink_fd = -1;
static int g_client_fds[MAX_CLIENTS];
static pthread_mutex_t g_clients_mutex = PTHREAD_MUTEX_INITIALIZER;

// ── Sysfs helpers ─────────────────────────────────────────────────────
static int read_sysfs_int(const char* path, int* val) {
    FILE* fp = fopen(path, "r");
    if (!fp) { ALOGW("Cannot open %s", path); return -1; }
    int r = fscanf(fp, "%d", val);
    fclose(fp); return (r == 1) ? 0 : -1;
}

static int read_sysfs_string(const char* path, char* buf, int size) {
    FILE* fp = fopen(path, "r");
    if (!fp) return -1;
    if (!fgets(buf, size, fp)) { fclose(fp); return -1; }
    int len = strlen(buf);
    if (len > 0 && buf[len-1] == '\n') buf[len-1] = '\0';
    fclose(fp); return 0;
}

static int read_sysfs_long(const char* path, long* val) {
    FILE* fp = fopen(path, "r");
    if (!fp) return -1;
    int r = fscanf(fp, "%ld", val);
    fclose(fp); return (r == 1) ? 0 : -1;
}

static void read_memory_info(long* total_kb, long* available_kb) {
    *total_kb = *available_kb = 0;
    FILE* fp = fopen(MEM_INFO, "r");
    if (!fp) return;
    char line[256];
    while (fgets(line, sizeof(line), fp)) {
        long v;
        if      (sscanf(line, "MemTotal: %ld kB",     &v) == 1) *total_kb     = v;
        else if (sscanf(line, "MemAvailable: %ld kB", &v) == 1) *available_kb = v;
        if (*total_kb && *available_kb) break;
    }
    fclose(fp);
}

// ── Collect all hardware values ───────────────────────────────────────
static void collect_health_data(HealthData* d) {
    memset(d, 0, sizeof(HealthData));
    read_sysfs_int(BATTERY_CAPACITY, &d->battery_percent);
    read_sysfs_int(BATTERY_TEMP,     &d->battery_temp);
    read_sysfs_string(BATTERY_STATUS, d->battery_status, sizeof(d->battery_status));
    read_sysfs_string(BATTERY_HEALTH, d->battery_health, sizeof(d->battery_health));
    read_sysfs_int(CPU_TEMP,  &d->cpu_temp);
    read_sysfs_long(CPU_FREQ, &d->cpu_freq_khz);
    read_memory_info(&d->mem_total_kb, &d->mem_available_kb);

    float cpu_c = d->cpu_temp / 1000.0f;
    d->is_critical = (d->battery_percent < 5) || (cpu_c > 90.0f) ||
                     (strcmp(d->battery_health, "Overheat") == 0);
}

// ── Format as text (Java parses with split("|")) ──────────────────────
static int format_health_data(const HealthData* d, char* buf, int size) {
    // "HEALTH|pct|temp|status|health|cpu_temp|cpu_freq|mem_total|mem_avail|critical\n"
    return snprintf(buf, size,
        "HEALTH|%d|%d|%s|%s|%d|%ld|%ld|%ld|%d\n",
        d->battery_percent, d->battery_temp,
        d->battery_status,  d->battery_health,
        d->cpu_temp, d->cpu_freq_khz,
        d->mem_total_kb, d->mem_available_kb, d->is_critical);
}

// ── Send to all connected Java clients ───────────────────────────────
static void broadcast_to_clients(const char* data, int len) {
    pthread_mutex_lock(&g_clients_mutex);
    for (int i = 0; i < MAX_CLIENTS; i++) {
        if (g_client_fds[i] < 0) continue;
        ssize_t sent = send(g_client_fds[i], data, len, MSG_NOSIGNAL);
        if (sent < 0) {
            ALOGI("Client %d disconnected", g_client_fds[i]);
            close(g_client_fds[i]);
            g_client_fds[i] = -1;
        }
    }
    pthread_mutex_unlock(&g_clients_mutex);
}

// ── Periodic data collection (every 2 seconds) ───────────────────────
static void* data_collection_thread(void* arg) {
    char buf[512]; HealthData data;
    while (1) {
        collect_health_data(&data);
        int len = format_health_data(&data, buf, sizeof(buf));
        if (len > 0) broadcast_to_clients(buf, len);
        sleep(2);
    }
    return NULL;
}

// ── Netlink thread — receives CRITICAL alerts from kernel ─────────────
// This is the ONLY way to get kernel thermal/battery push events.
static void* netlink_thread(void* arg) {
    g_netlink_fd = socket(AF_NETLINK, SOCK_DGRAM, NETLINK_KOBJECT_UEVENT);
    if (g_netlink_fd < 0) { ALOGE("Netlink socket failed"); return NULL; }

    struct sockaddr_nl nl = {0};
    nl.nl_family = AF_NETLINK;
    nl.nl_pid    = getpid();
    nl.nl_groups = 1;
    bind(g_netlink_fd, (struct sockaddr*)&nl, sizeof(nl));

    char buf[4096]; int cpu_temp; int battery_pct;
    while (1) {
        int len = recv(g_netlink_fd, buf, sizeof(buf) - 1, 0);
        if (len <= 0) continue;
        buf[len] = '\0';

        if (strstr(buf, "thermal")) {
            read_sysfs_int(CPU_TEMP, &cpu_temp);
            char alert[256];
            int n = snprintf(alert, sizeof(alert),
                "ALERT|THERMAL|%.1f|KERNEL_EVENT\n", cpu_temp / 1000.0f);
            broadcast_to_clients(alert, n);
            ALOGW("Thermal alert: %.1f°C", cpu_temp / 1000.0f);
        }

        if (strstr(buf, "power_supply")) {
            read_sysfs_int(BATTERY_CAPACITY, &battery_pct);
            if (battery_pct <= 5) {
                char alert[128];
                int n = snprintf(alert, sizeof(alert),
                    "ALERT|BATTERY_CRITICAL|%d|KERNEL_EVENT\n", battery_pct);
                broadcast_to_clients(alert, n);
            }
        }
    }
    return NULL;
}

// ── Handle a single Java client ───────────────────────────────────────
static void* client_handler_thread(void* arg) {
    int client_fd = *(int*)arg; free(arg);
    ALOGI("Client connected (fd=%d)", client_fd);

    // Add to broadcast list
    pthread_mutex_lock(&g_clients_mutex);
    int added = 0;
    for (int i = 0; i < MAX_CLIENTS; i++) {
        if (g_client_fds[i] < 0) { g_client_fds[i] = client_fd; added = 1; break; }
    }
    pthread_mutex_unlock(&g_clients_mutex);

    if (!added) {
        write(client_fd, "ERROR|MAX_CLIENTS\n", 18);
        close(client_fd); return NULL;
    }

    // Send an immediate snapshot — client doesn't wait 2 seconds
    HealthData data; char buf[512];
    collect_health_data(&data);
    int len = format_health_data(&data, buf, sizeof(buf));
    send(client_fd, buf, len, MSG_NOSIGNAL);

    // Handle on-demand commands from Java service
    char cmd[64];
    while (1) {
        memset(cmd, 0, sizeof(cmd));
        int n = read(client_fd, cmd, sizeof(cmd) - 1);
        if (n <= 0) break;
        cmd[n] = '\0';

        if      (strncmp(cmd, "GET_NOW", 7) == 0) {
            collect_health_data(&data);
            len = format_health_data(&data, buf, sizeof(buf));
            send(client_fd, buf, len, MSG_NOSIGNAL);
        }
        else if (strncmp(cmd, "PING", 4) == 0)
            send(client_fd, "PONG\n", 5, MSG_NOSIGNAL);
        else
            send(client_fd, "ERROR|UNKNOWN_CMD\n", 18, MSG_NOSIGNAL);
    }

    pthread_mutex_lock(&g_clients_mutex);
    for (int i = 0; i < MAX_CLIENTS; i++)
        if (g_client_fds[i] == client_fd) { g_client_fds[i] = -1; break; }
    pthread_mutex_unlock(&g_clients_mutex);

    close(client_fd);
    return NULL;
}

// ── main ──────────────────────────────────────────────────────────────
int main() {
    ALOGI("=== health_monitor_daemon starting ===");

    for (int i = 0; i < MAX_CLIENTS; i++) g_client_fds[i] = -1;

    // init already created the socket — just retrieve the fd
    g_server_fd = android_get_control_socket("healthd_mon");
    if (g_server_fd < 0) { ALOGE("Cannot get control socket"); return 1; }

    listen(g_server_fd, MAX_CLIENTS);
    ALOGI("Listening on /dev/socket/healthd_mon");

    pthread_t tid;
    pthread_create(&tid, NULL, netlink_thread,         NULL);
    pthread_create(&tid, NULL, data_collection_thread, NULL);

    while (1) {
        int client_fd = accept(g_server_fd, NULL, NULL);
        if (client_fd < 0) { if (errno == EINTR) continue; continue; }

        // Verify caller is system (UID 1000) or root (UID 0)
        struct ucred cred; socklen_t clen = sizeof(cred);
        if (getsockopt(client_fd, SOL_SOCKET, SO_PEERCRED, &cred, &clen) == 0) {
            if (cred.uid != 1000 && cred.uid != 0) {
                ALOGW("Rejected UID %d", cred.uid);
                write(client_fd, "ERROR|FORBIDDEN\n", 16);
                close(client_fd); continue;
            }
        }

        int* fd_ptr = (int*)malloc(sizeof(int)); *fd_ptr = client_fd;
        pthread_t ctid;
        pthread_create(&ctid, NULL, client_handler_thread, fd_ptr);
        pthread_detach(ctid);
    }
    return 0;
}
```

```java
// frameworks/base/services/core/java/com/android/server/HealthMonitorService.java

package com.android.server;

import android.content.Context;
import android.net.LocalSocket;
import android.net.LocalSocketAddress;
import android.os.Handler;
import android.os.HandlerThread;
import android.os.RemoteCallbackList;
import android.os.RemoteException;
import android.util.Slog;

import java.io.BufferedReader;
import java.io.IOException;
import java.io.InputStreamReader;
import java.io.OutputStream;

public class HealthMonitorService extends IHealthMonitor.Stub {

    private static final String TAG         = "HealthMonitorService";
    private static final String SOCKET_NAME = "healthd_mon";

    private volatile HealthInfo mLatestHealth = new HealthInfo();
    private volatile boolean    mIsCritical   = false;

    private LocalSocket    mSocket;
    private OutputStream   mOutputStream;
    private BufferedReader mReader;
    private boolean        mConnected = false;

    private final RemoteCallbackList<IHealthCallback> mCallbacks =
            new RemoteCallbackList<>();

    private final HandlerThread mSocketThread;
    private final Handler       mSocketHandler;

    // ── Data model ────────────────────────────────────────────────────
    public static class HealthInfo {
        public int     batteryPercent   = 0;
        public float   batteryTempC     = 0f;
        public String  batteryStatus    = "Unknown";
        public String  batteryHealth    = "Unknown";
        public float   cpuTempC         = 0f;
        public long    cpuFreqKhz       = 0;
        public long    memTotalKb       = 0;
        public long    memAvailableKb   = 0;
        public boolean isCritical       = false;
        public long    lastUpdateTimeMs = 0;
    }

    public HealthMonitorService(Context context) {
        mSocketThread = new HandlerThread("HealthMonSocket");
        mSocketThread.start();
        mSocketHandler = new Handler(mSocketThread.getLooper());
        mSocketHandler.post(this::connectToDaemon);
    }

    // ── Connect to native daemon via Unix domain socket ───────────────
    private void connectToDaemon() {
        while (!mConnected) {
            try {
                mSocket = new LocalSocket();
                mSocket.connect(new LocalSocketAddress(
                    SOCKET_NAME, LocalSocketAddress.Namespace.RESERVED));

                mOutputStream = mSocket.getOutputStream();
                mReader = new BufferedReader(
                    new InputStreamReader(mSocket.getInputStream()));

                mConnected = true;
                Slog.i(TAG, "Connected to daemon");
                readStreamFromDaemon();

            } catch (IOException e) {
                Slog.w(TAG, "Cannot connect, retrying in 3s: " + e.getMessage());
                mConnected = false;
                try { Thread.sleep(3000); } catch (InterruptedException ignored) {}
            }
        }
    }

    // ── Read continuous stream ────────────────────────────────────────
    // Daemon sends every 2s:  "HEALTH|85|350|Discharging|Good|45000|..."
    // Kernel alert (instant): "ALERT|THERMAL|95.5|KERNEL_EVENT"
    private void readStreamFromDaemon() {
        try {
            String line;
            while ((line = mReader.readLine()) != null) {
                if      (line.startsWith("HEALTH|")) parseHealthData(line);
                else if (line.startsWith("ALERT|"))  parseAlert(line);
            }
        } catch (IOException e) {
            Slog.e(TAG, "Lost connection: " + e.getMessage());
        }
        mConnected = false;
        mSocketHandler.postDelayed(this::connectToDaemon, 2000);
    }

    // ── Parse "HEALTH|pct|temp|status|health|cpu_temp|freq|mem_total|mem_avail|critical" ──
    private void parseHealthData(String line) {
        try {
            String[] p = line.split("\\|");
            if (p.length < 10) return;

            HealthInfo info       = new HealthInfo();
            info.batteryPercent   = Integer.parseInt(p[1]);
            info.batteryTempC     = Integer.parseInt(p[2]) / 10.0f;
            info.batteryStatus    = p[3];
            info.batteryHealth    = p[4];
            info.cpuTempC         = Integer.parseInt(p[5]) / 1000.0f;
            info.cpuFreqKhz       = Long.parseLong(p[6]);
            info.memTotalKb       = Long.parseLong(p[7]);
            info.memAvailableKb   = Long.parseLong(p[8]);
            info.isCritical       = p[9].equals("1");
            info.lastUpdateTimeMs = System.currentTimeMillis();

            mLatestHealth = info;
            mIsCritical   = info.isCritical;
            notifyCallbacks(info, null);

        } catch (Exception e) {
            Slog.e(TAG, "Parse error: " + e.getMessage());
        }
    }

    // ── Parse "ALERT|THERMAL|95.5|KERNEL_EVENT" ──────────────────────
    private void parseAlert(String line) {
        String[] p = line.split("\\|");
        if (p.length < 3) return;
        Slog.w(TAG, "CRITICAL ALERT: " + p[1] + " = " + p[2]);
        notifyCallbacks(mLatestHealth, p[1] + ":" + p[2]);
    }

    private void notifyCallbacks(HealthInfo info, String alert) {
        int count = mCallbacks.beginBroadcast();
        for (int i = 0; i < count; i++) {
            try {
                IHealthCallback cb = mCallbacks.getBroadcastItem(i);
                if (alert != null) cb.onCriticalAlert(alert);
                else cb.onHealthUpdate(info.batteryPercent, info.batteryTempC,
                                       info.batteryStatus,  info.cpuTempC,
                                       info.memAvailableKb);
            } catch (RemoteException ignored) {}
        }
        mCallbacks.finishBroadcast();
    }

    // ── Binder API (called by apps) ───────────────────────────────────
    @Override public int    getBatteryPercent()      { return mLatestHealth.batteryPercent; }
    @Override public float  getBatteryTemperature()  { return mLatestHealth.batteryTempC; }
    @Override public String getBatteryStatus()       { return mLatestHealth.batteryStatus; }
    @Override public float  getCpuTemperature()      { return mLatestHealth.cpuTempC; }
    @Override public long   getAvailableMemoryKb()   { return mLatestHealth.memAvailableKb; }
    @Override public boolean isCritical()            { return mIsCritical; }

    @Override
    public void requestImmediateUpdate() {
        if (!mConnected) return;
        mSocketHandler.post(() -> {
            try { mOutputStream.write("GET_NOW\n".getBytes()); mOutputStream.flush(); }
            catch (IOException e) { Slog.e(TAG, "GET_NOW failed: " + e.getMessage()); }
        });
    }

    @Override public void registerCallback(IHealthCallback cb)   { if (cb != null) mCallbacks.register(cb); }
    @Override public void unregisterCallback(IHealthCallback cb) { if (cb != null) mCallbacks.unregister(cb); }
}
```

```java
// frameworks/base/core/java/android/os/IHealthMonitor.aidl
package android.os;
import android.os.IHealthCallback;

interface IHealthMonitor {
    int     getBatteryPercent();
    float   getBatteryTemperature();
    String  getBatteryStatus();
```

## 9. Why Socket is the Right Choice Here

| Layer | Mechanism | Why |
|-------|-----------|-----|
| Kernel → Daemon | **Netlink Socket** | Only way to receive kernel push events. Binder cannot reach kernel space. |
| Daemon → Java Service | **Unix Domain Socket** | Daemon starts before `ServiceManager`. Streams 2s data continuously. Simple text protocol across C++ and Java. |
| Java Service → Apps | **Binder / AIDL** | Apps are Java — Binder is natural. Well-defined get/set API. Built-in UID permission checking. Apps don't need raw streams. |

### Data flow

```
Linux Kernel
     │ Netlink Socket — only option for kernel push events
     ▼
Native C++ Daemon  (health_monitor_daemon)
     │ Unix Domain Socket — early boot + streaming
     ▼
Java Framework Service  (HealthMonitorService)
     │ Binder / AIDL — best fit for Java app communication
     ▼
Android App  (Settings / DeviceHealthActivity)
```

---

# ❓ Why NOT Use AIDL Between the Daemon and the Service?

> ✅ Because AIDL (Binder) is **not suitable** for this layer.

---

## 1. The Daemon Starts at Early Boot

```
Boot order:
  Kernel
    ↓
  init
    ↓
  health_monitor_daemon   ← starts HERE ✅
    ↓
  ServiceManager          ← starts LATER ❌
    ↓
  system_server (Java)
```

**❌ Problem:** Binder/AIDL needs `ServiceManager`. But when the daemon starts, `ServiceManager` isn't alive yet — AIDL would fail or hang.

**✅ Socket:** Has no dependency on `ServiceManager`. Works the moment the process starts.

---

## 2. Continuous Streaming Data

The daemon sends data every 2 seconds:

```
HEALTH|85|35.0|Good|...
HEALTH|84|35.1|Good|...
HEALTH|83|35.2|Good|...
```

**❌ Binder** is request-response based — you must call a method every time:

```
getHealth()
getHealth()
getHealth()   ← inefficient polling
```

**✅ Socket** keeps one open connection. Daemon just keeps writing, Java just keeps reading. Much simpler for streaming.

---

## 3. Kernel Communication

The daemon uses a **Netlink socket** to receive thermal and battery events directly from the kernel. Binder **cannot** talk to kernel drivers — only sockets can. The daemon is already socket-based by necessity.

---

## 4. Cross-Language Simplicity

| | With AIDL | With Socket |
|-|-----------|------------|
| Interface file | Need `.aidl` file | ❌ Not needed |
| Generated code | Need Binder stubs | ❌ Not needed |
| Native linking | Need `libbinder` | ❌ Not needed |
| Data exchange | Method calls | Just send text, Java splits string |

---

## ✅ When SHOULD You Use AIDL?

Use AIDL when:
- Java ↔ Java services
- Framework service ↔ App
- Clear get/set API methods
- **Not** streaming large data
- **Not** early boot

```
Daemon ↔ Service  →  Socket  ✅
Service ↔ App     →  AIDL    ✅
```

---

## What About Modern AIDL HALs? (Android 11+)

You might ask: *"But Camera, Audio, and Fingerprint HALs all use AIDL now — why not here?"*

### HALs Start Later Than This Daemon

| | Health Monitor Daemon | AIDL HAL |
|-|----------------------|----------|
| **Start time** | Early boot (Stage 2) — needs nothing | Mid-boot (Stage 4) — needs `ServiceManager` |
| **Data type** | Continuous raw streams | Structured API calls |
| **Kernel comm** | ✅ Netlink (direct kernel) | ❌ Cannot reach kernel |
| **Complexity** | Low — simple text/bytes | High — auto-generated code |

### "Stable AIDL" Was Invented for HALs

In the past, HALs used **HIDL** (a socket-like IPC) because standard Binder was unstable for hardware. Google created **Stable AIDL** specifically to replace HIDL.

Modern HALs (Camera, Audio, Fingerprint) now use AIDL because it's easier for developers — but they **rely on `ServiceManager` being ready**, which means they can only start mid-boot or later.

---

## Final Summary

```
✅ Use AIDL (Binder) when:
   → Java ↔ Java communication
   → ServiceManager is already running
   → You want a standard, structured Android API
   → HAL replacements (Stable AIDL)

✅ Use Socket when:
   → Early boot (Binder isn't ready yet)
   → Recovery mode (Binder isn't there at all)
   → Netlink (talking directly to the Linux kernel)
   → Streaming raw continuous data (logs, sensor bursts)
```

> **Rule of thumb:** If it *can* be an AIDL HAL, it usually *should* be today. But sockets remain the essential **low-level / emergency tool** for when AIDL starts too late or is simply too heavy.

# 📡 Netlink Socket — Simple & Short

---

## What is Netlink?

Netlink is a special socket used to communicate **directly between the Linux kernel and userspace programs**.

```
App / Daemon  ←→  Kernel
        (via Netlink socket)
```

**Why it exists:**

```
Normal socket:  Process A  ↔  Process B   (userspace only)
Netlink:        Process    ↔  Kernel      (crosses the boundary)

Binder  ❌ cannot talk to kernel
Pipe    ❌ cannot talk to kernel
Netlink ✅ only option
```

---

## What It's Used For

| Event | Netlink Type |
|-------|-------------|
| WiFi on/off, IP assigned | `NETLINK_ROUTE` |
| USB plug / unplug | `NETLINK_KOBJECT_UEVENT` |
| Battery state change | `NETLINK_KOBJECT_UEVENT` |
| CPU overheat / thermal alerts | `NETLINK_KOBJECT_UEVENT` |
| Routing table updates | `NETLINK_ROUTE` |
| Custom kernel subsystems | `NETLINK_GENERIC` |

---

## Example 1 — WiFi Connected (New IP Assigned)

```
Kernel detects: "New IP address assigned"
  ↓
Kernel sends Netlink message: RTM_NEWADDR
  ↓
netd receives it via Netlink socket
  ↓
netd informs ConnectivityService
```

```c
int sock = socket(AF_NETLINK, SOCK_DGRAM, NETLINK_ROUTE);
//                ^kernel comm  ^datagram   ^network events

recv(sock, buffer, sizeof(buffer), 0);
// kernel sends RTM_NEWADDR when a new IP is assigned
```

---

## Example 2 — USB Plugged In

```
Kernel detects hardware change
  ↓
Kernel sends uevent: "add@/devices/platform/usb/usb1"
  ↓
ueventd receives it
  ↓
Creates device node in /dev, notifies system
```

```c
int sock = socket(AF_NETLINK, SOCK_DGRAM, NETLINK_KOBJECT_UEVENT);

recv(sock, buffer, sizeof(buffer), 0);
// buffer = "add@/devices/platform/usb/usb1"
```

---

## Example 3 — CPU Overheating

```
CPU reaches 95°C
  ↓
Kernel thermal driver fires:
"change@/devices/virtual/thermal/thermal_zone0"
  ↓
Daemon receives it via Netlink
  ↓
Sends alert to framework / throttles CPU / initiates shutdown
```

---

## Visual

```
┌──────────────────────────────┐
│         Linux Kernel          │
│   Battery   USB   Network     │
└──────────────┬───────────────┘
               │  Netlink Socket
               ▼
┌──────────────────────────────┐
│  Android Daemon               │
│  netd / ueventd / healthd     │
└──────────────────────────────┘
```

---

## Netlink vs Unix Domain Socket

| Feature | Netlink Socket | Unix Domain Socket |
|---------|---------------|-------------------|
| **Who talks to whom** | Process ↔ **Kernel** | Process ↔ **Process** |
| **Domain** | `AF_NETLINK` | `AF_UNIX` |
| **Address** | Process ID (PID) | File path (`/dev/socket/vold`) |
| **Main purpose** | Receive hardware/network events from kernel | IPC between userspace processes |
| **AOSP examples** | `ueventd` (USB), `netd` (routes) | `zygote`, `vold`, `installd` |

### Memory trick

> **Unix Domain Socket** = phone call between two friends (Process A ↔ Process B)
>
> **Netlink Socket** = radio broadcast from the government (Kernel) to the citizens (your daemon)

### One-line code comparison

```c
// Unix Domain Socket — process to process
int fd = socket(AF_UNIX, SOCK_STREAM, 0);
//              ^local only, connects to a file path

// Netlink Socket — kernel to process
int fd = socket(AF_NETLINK, SOCK_DGRAM, NETLINK_KOBJECT_UEVENT);
//              ^kernel comm, connects to kernel ID (0)
```

---

## Key Interview Takeaway

**Q: "Can I use a Unix Domain Socket to detect a USB plug-in?"**

**A:** No. Unix Domain Sockets are only for two userspace processes to communicate. To receive hardware events from the kernel, you **must** use a Netlink socket — there is no other way.

---

## In One Line

> Netlink is a special Linux socket that lets Android daemons receive **real-time events directly from the kernel** — hardware changes, network updates, and thermal alerts that no other IPC mechanism can deliver.

### Q1. What is a Socket in Android / AOSP?

A socket is a **communication endpoint** that allows two processes to exchange data.

| Use case | Example |
|----------|---------|
| Native daemon ↔ Java service | `vold` ↔ `StorageManagerService` |
| Kernel ↔ userspace | Netlink in `ueventd` |
| Network communication | ADB over WiFi |

> **Analogy:** Socket = phone · Address = phone number · `connect()` = dial · `write()` = talk · `read()` = listen · `close()` = hang up

---

### Q2. What are the socket types used in AOSP?

| Type | Domain | Used For | AOSP Example |
|------|--------|----------|-------------|
| Unix Domain | `AF_UNIX` | Process ↔ Process (same device) | `vold`, `zygote`, `installd` |
| TCP / UDP | `AF_INET` | Network communication | ADB over WiFi (port 5555) |
| Netlink | `AF_NETLINK` | Kernel ↔ Userspace | `ueventd`, `netd` |

---

### Q3. What is `android_get_control_socket()`? Why does it exist?

An AOSP helper that retrieves a **pre-created socket fd** that `init` already set up — so the daemon never needs root to create it.

```
Without it:
  → Daemon needs ROOT to create /dev/socket/
  → Must call socket() + bind() + chmod() + chown()
  → Security risk, more code, more bugs

With it:
  → init creates socket as root before daemon starts
  → Daemon runs as non-root (safer)
  → 1 line to get the socket fd
```

```c
int fd = android_get_control_socket("vold");
listen(fd, 4);   // no socket() or bind() needed
```

**How it works internally:**

```c
// init sets:  ANDROID_SOCKET_vold = 5

const char* val = getenv("ANDROID_SOCKET_vold");
return atoi(val);   // returns 5
```

### Q4. Unix Domain Socket vs TCP Socket

| Feature | Unix Domain Socket | TCP Socket |
|---------|-------------------|------------|
| Scope | Same device only | Over network |
| Address | File path | IP + Port |
| Speed | Faster | Slower |
| Domain | `AF_UNIX` | `AF_INET` |
| AOSP examples | `vold`, `zygote` | ADB, HTTP |

### Q5. What is a Netlink socket? Give a real example.

Netlink is a special socket for **Linux Kernel ↔ Userspace** communication.

```
Normal socket:  Process A ↔ Process B   (userspace only)
Netlink:        Process   ↔ Kernel      (crosses the boundary)

```

```
3. ueventd receives it via Netlink
```

## 🟡 Intermediate Level

---

### Q6. When should you use Socket over Binder in AOSP?

**Use Socket when:**

| Scenario | Why |
|----------|-----|
| Early boot daemon | Starts before `ServiceManager` — Binder not ready |
| Kernel communication | Netlink is the only option; Binder cannot reach kernel |
| Streaming data | Binder has ~1 MB limit; socket has none (e.g. `logcat`) |
| C++ daemon ↔ Java service | No AIDL needed; simple text protocol |
| Recovery mode | No Android framework — socket still works |

**Use Binder when:**
- Java service ↔ Java service
- Well-defined get/set API
- App ↔ System service
- Not streaming large data

---

### Q7. Early boot daemons use sockets, but modern HALs use AIDL. Is that a contradiction?

**No — they start at different boot stages.**

```
Early boot  (~200ms)  → vold, netd, ueventd start
                        ServiceManager NOT ready → MUST use Socket

Mid boot    (~500ms)  → ServiceManager starts
                        Binder becomes available

Late boot   (~2000ms) → system_server starts
                        AIDL HALs register via ServiceManager
```

> Early boot daemons → Socket ✅ | Modern AIDL HALs → Start after `ServiceManager` ✅ — no contradiction.

---

### Q8. What is `SO_PEERCRED`? Why is it useful in AOSP?

`SO_PEERCRED` is a socket option that reveals **who is connecting** to your socket — their PID, UID, and GID — directly from the kernel.

```c
struct ucred cred;
socklen_t len = sizeof(cred);
getsockopt(client_fd, SOL_SOCKET, SO_PEERCRED, &cred, &len);

// Only allow system_server (UID 1000)
if (cred.uid != 1000) {
    write(client_fd, "ERROR|FORBIDDEN\n", 16);
    close(client_fd);
    return;
}
```

> **Key point:** The UID comes from the **kernel** — it cannot be faked by the client. This makes it a secure identity check.

---

### Q9. What are the three socket namespaces in Android?

| Namespace | File Created? | Who Creates | AOSP Usage |
|-----------|--------------|-------------|-----------|
| `RESERVED` | ✅ `/dev/socket/<name>` | `init` (root) | `vold`, `netd`, `zygote` |
| `ABSTRACT` | ❌ Kernel memory only | Any process | Java `LocalSocket` |
| `FILESYSTEM` | ✅ Custom path | Any (with permission) | Custom daemons |

```java
// RESERVED — /dev/socket/vold
new LocalSocketAddress("vold", Namespace.RESERVED);

// ABSTRACT — no file, disappears on close
new LocalSocketAddress("my_socket", Namespace.ABSTRACT);

// FILESYSTEM — actual file at the path
new LocalSocketAddress("/data/misc/my_socket", Namespace.FILESYSTEM);
```

## 🔴 Advanced Level

### Q11. Explain the complete flow: Java service ↔ Native daemon via socket

```
Step 1 — .rc file defines the socket
  service my_daemon /system/bin/my_daemon
      socket my_daemon stream 660 system system

Step 2 — init creates the socket (as root)
  socket() + bind() → /dev/socket/my_daemon
  Sets env: ANDROID_SOCKET_my_daemon = 5

Step 3 — Daemon retrieves the fd
  int fd = android_get_control_socket("my_daemon");
  listen(fd, 4);

Step 4 — Java service connects
  socket.connect(new LocalSocketAddress("my_daemon", Namespace.RESERVED));

Step 5 — Daemon streams data every 2 seconds
  write(client_fd, "HEALTH|85|35.0|Good\n", 20);

Step 6 — Java reads continuously
  String line = reader.readLine();   // "HEALTH|85|35.0|Good"
  // Parse, store, expose to apps via Binder
```

---

### Q12. Why does `logcat` use socket and not Binder to collect logs?

**Three reasons:**

| Reason | Detail |
|--------|--------|
| **Streaming** | Logs are continuous — millions of lines. Binder's 1 MB limit would be hit immediately. Socket has no limit. |
| **Works everywhere** | Every process — including early boot daemons — can write to `logd`'s socket. Binder isn't available at early boot. |
| **Performance** | Binder has per-call overhead. With a socket: connect once, write forever. |

```
Any process
    │ write to /dev/socket/logdw
    ▼
logd  (ring buffer)
    │ read from /dev/socket/logdr
    ▼
logcat → your terminal
```

---

### Q13. What happens if the socket is NOT defined in `.rc` but you call `android_get_control_socket()`?

```c
int fd = android_get_control_socket("my_daemon");
// fd = -1  ← fails silently

// Why:
const char* val = getenv("ANDROID_SOCKET_my_daemon");
// val = NULL  (env var was never set by init)
// returns -1

// Causes:
// → socket not in .rc file
// → daemon started manually, not by init
// → wrong socket name (typo)

// Always check:
if (fd < 0) {
    ALOGE("Socket not found — check .rc file");
    return 1;
}
```

---

### Q14. Can two processes connect to the same Unix Domain Socket simultaneously?

**Yes** — that's exactly what `listen()` + `accept()` are for.

```c
listen(server_fd, 4);   // 4 = max pending queue

while (true) {
    int client_fd = accept(server_fd, NULL, NULL);
    // Each accept() returns a NEW fd for that client
    pthread_create(..., handle_client, &client_fd);
}
```

```
/dev/socket/my_daemon
  ├── Client 1  (fd=5)  ← accepted
  ├── Client 2  (fd=6)  ← accepted
  ├── Client 3  (fd=7)  ← accepted
  └── Client 4          ← waiting in backlog
```

> **Real AOSP example:** `logd` simultaneously accepts connections from `system_server`, every app process, and `logcat`.

---

### Q15. If a daemon crashes and restarts, what happens to the socket?

| | `.rc` + `android_get_control_socket()` | Manual `socket()` + `bind()` |
|-|---------------------------------------|------------------------------|
| Socket file after crash | Still exists (init created it) | Still exists |
| Daemon restarts and gets fd | ✅ `android_get_control_socket()` works immediately | ❌ `bind()` fails with `EADDRINUSE` |
| Fix required | None — just call `listen()` again | Must call `unlink()` before `bind()` |
| Clients can reconnect | ✅ Automatically | ❌ Needs extra restart logic |

> This is another reason AOSP always uses the `init.rc` + `android_get_control_socket()` pattern.
