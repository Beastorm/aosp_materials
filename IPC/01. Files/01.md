# 📁 File-Based IPC in AOSP — Complete Guide

---

## 🔷 What is File-Based IPC?

| Term | Meaning |
|------|---------|
| **IPC** | Inter-Process Communication — ways for two different processes to exchange data |
| **File-Based IPC** | Using files on the filesystem as the communication medium |

> Think of it like a **shared notebook**: one process writes a message, another reads it.

```
┌─────────────┐                     ┌──────────────┐
│  Process A  │ ──── writes ──────► │  Shared File │
│  (Writer)   │                     │  (on disk)   │
└─────────────┘                     └──────┬───────┘
                                           │ reads
                                    ┌──────▼───────┐
                                    │  Process B   │
                                    │  (Reader)    │
                                    └──────────────┘
```

---

## 🗂️ Types of File-Based IPC

```
File-Based IPC
├── 1. 📄 Regular Files         (simple read/write)
├── 2. 💾 Shared Memory         (ashmem / memfd)
├── 3. 🔧 Named Pipes           (FIFOs)
├── 4. 🔌 Unix Domain Sockets   (socket files)
├── 5. 📊 Virtual Filesystems   (procfs / sysfs / debugfs)
├── 6. ⚙️  System Properties    (global key-value store)
└── 7. 🗺️  Memory-Mapped Files  (mmap)
```

## 1. 📄 Regular Files (Simple Read/Write)

**Concept:** One process writes data to a file; another reads it. The simplest form of IPC.

```
Process A            File System           Process B
┌──────────┐  write  ┌──────────┐  read   ┌──────────┐
│  Writer  │ ──────► │ /data/   │ ──────► │  Reader  │
└──────────┘         │  myfile  │         └──────────┘
                     └──────────┘
```

### Writer (C)

```c
// writer.c
#include <stdio.h>
#include <fcntl.h>
#include <unistd.h>
#include <string.h>

int main() {
    const char *filepath = "/data/local/tmp/ipc_file.txt";
    const char *message  = "Hello from Process A!";

    int fd = open(filepath, O_WRONLY | O_CREAT | O_TRUNC, 0666);
    if (fd < 0) { perror("open failed"); return 1; }

    write(fd, message, strlen(message));
    close(fd);
    printf("Writer: Message written successfully\n");
    return 0;
}
```

### Reader (C)

```c
// reader.c
#include <stdio.h>
#include <fcntl.h>
#include <unistd.h>

int main() {
    const char *filepath = "/data/local/tmp/ipc_file.txt";
    char buffer[256] = {0};

    int fd = open(filepath, O_RDONLY);
    if (fd < 0) { perror("open failed"); return 1; }

    ssize_t bytes_read = read(fd, buffer, sizeof(buffer) - 1);
    close(fd);
    printf("Reader: Got message = '%s' (%zd bytes)\n", buffer, bytes_read);
    return 0;
}
```

### Android.bp

```json
cc_binary { name: "ipc_writer", srcs: ["writer.c"], cflags: ["-Wall"] }
cc_binary { name: "ipc_reader", srcs: ["reader.c"], cflags: ["-Wall"] }
```

### 📌 Real AOSP Examples

```
/data/system/packages.xml     ← PackageManagerService writes package info
/data/system/users/0/         ← User settings stored as XML
/data/misc/wifi/              ← WiFi configuration files
```

### ✅ Pros / ❌ Cons

| ✅ Pros | ❌ Cons |
|--------|--------|
| Very simple to implement | Slow (disk I/O) |
| Persistent (survives reboot) | No notification on change |
| | Race conditions possible |
| | Needs file locking for safety |

## 2. 💾 Shared Memory (ashmem / memfd)

**Concept:** Processes share a region of **RAM** — no disk I/O, extremely fast.

```
           RAM (Physical Memory)
    ┌──────────────────────────┐
    │   Shared Memory Region   │
    │   ┌──────────────────┐   │
    │   │  "Hello World"   │   │
    │   └──────────────────┘   │
    └──────────┬──────┬────────┘
               │      │
        mmap() │      │ mmap()
               │      │
    ┌──────────▼┐    ┌▼──────────┐
    │ Process A │    │ Process B │
    │ (Writer)  │    │ (Reader)  │
    └───────────┘    └───────────┘
```

> **ashmem** = Android Shared Memory — Android's custom shared memory driver at `/dev/ashmem`

### Process A — Creator & Writer (C)

```c
#include <stdio.h>
#include <string.h>
#include <fcntl.h>
#include <unistd.h>
#include <sys/mman.h>
#include <sys/ioctl.h>
#include <linux/ashmem.h>

#define ASHMEM_DEVICE "/dev/ashmem"
#define SHM_SIZE 4096

int main() {
    int fd = open(ASHMEM_DEVICE, O_RDWR);
    if (fd < 0) { perror("Failed to open ashmem"); return 1; }

    ioctl(fd, ASHMEM_SET_NAME, "my_shared_region");  // Name the region
    ioctl(fd, ASHMEM_SET_SIZE, SHM_SIZE);             // Set size

    char *shared_mem = (char *)mmap(NULL, SHM_SIZE,
                                    PROT_READ | PROT_WRITE,
                                    MAP_SHARED, fd, 0);
    if (shared_mem == MAP_FAILED) { perror("mmap failed"); close(fd); return 1; }

    strcpy(shared_mem, "Hello from Process A via ashmem!");
    printf("Writer: fd=%d (pass this to Process B via Binder)\n", fd);

    sleep(60);  // Keep alive while Process B reads

    munmap(shared_mem, SHM_SIZE);
    close(fd);
    return 0;
}
```

### Process B — Reader (C)

```c
// fd is received from Process A via Binder
int main(int argc, char *argv[]) {
    int fd = atoi(argv[1]);

    char *shared_mem = (char *)mmap(NULL, SHM_SIZE, PROT_READ, MAP_SHARED, fd, 0);
    if (shared_mem == MAP_FAILED) { perror("mmap failed"); return 1; }

    printf("Reader: Got message = '%s'\n", shared_mem);

    munmap(shared_mem, SHM_SIZE);
    close(fd);
    return 0;
}
```

### Passing fd via Binder (Java)


### Modern Alternative: `memfd` (Android 10+)

```c
#include <sys/mman.h>
#include <linux/memfd.h>
#include <sys/syscall.h>

int create_memfd_shared_memory() {
    int fd = syscall(__NR_memfd_create, "my_memfd", MFD_ALLOW_SEALING);
    if (fd < 0) { perror("memfd_create"); return -1; }

    ftruncate(fd, 4096);

    char *ptr = mmap(NULL, 4096, PROT_READ | PROT_WRITE, MAP_SHARED, fd, 0);
    strcpy(ptr, "Data via memfd!");
    return fd;  // Pass to another process via Binder/socket
}
```

## 3. 🔧 Named Pipes (FIFOs)

**Concept:** A special file acting as a **one-way pipe**. Data flows through the kernel buffer — never stored on disk.

```
Process A ──── write ────► [ FIFO ] ──── read ────► Process B
                         /tmp/myfifo
                       (special file)
```

### Characteristics

| Property | Value |
|----------|-------|
| Storage | Data lives in kernel buffer, **not on disk** |
| Direction | **Unidirectional** |
| Order | First-In-First-Out |
| Blocking | Reader **blocks** until writer connects (and vice versa) |

### Create the FIFO

```c
#include <sys/stat.h>
mkfifo("/data/local/tmp/my_pipe", 0666);
```

### Writer (C)

```c
// fifo_writer.c
int main() {
    const char *fifo_path = "/data/local/tmp/my_pipe";
    const char *messages[] = {
        "Message 1: Battery level is 85%",
        "Message 2: WiFi connected",
        "Message 3: Screen brightness changed",
    };

    printf("Writer: Opening FIFO (blocks until reader connects)...\n");
    int fd = open(fifo_path, O_WRONLY);  // Blocks until reader opens

    for (int i = 0; i < 3; i++) {
        write(fd, messages[i], strlen(messages[i]) + 1);
        printf("Writer: Sent '%s'\n", messages[i]);
        sleep(1);
    }

    close(fd);
    return 0;
}
```

### Reader (C)

```c
// fifo_reader.c
int main() {
    const char *fifo_path = "/data/local/tmp/my_pipe";
    char buffer[256];

    printf("Reader: Opening FIFO (blocks until writer connects)...\n");
    int fd = open(fifo_path, O_RDONLY);  // Blocks until writer opens

    ssize_t bytes;
    while ((bytes = read(fd, buffer, sizeof(buffer))) > 0)
        printf("Reader: Received '%s' (%zd bytes)\n", buffer, bytes);

    close(fd);
    printf("Reader: Writer disconnected\n");
    return 0;
}
```

### ⏱️ Blocking Timeline

```
Reader: open(FIFO, O_RDONLY)
        │
        │  ← BLOCKS (waiting for writer)
        │
Writer: open(FIFO, O_WRONLY)
        │
        ├─────── Both unblock! Connection established ───────┤
        │                                                     │
Writer: write("Hello")                          Reader: read() → "Hello"
Writer: write("World")                          Reader: read() → "World"
Writer: close()
                                                Reader: read() → 0 (EOF)
```

## 4. 🔌 Unix Domain Sockets

**Concept:** A socket file on the filesystem allowing **bidirectional** communication between processes on the same machine.

```
┌───────────┐     ┌─────────────────────┐     ┌───────────┐
│  Client   │◄───►│    Socket File      │◄───►│  Server   │
│  Process  │     │  /dev/socket/xyz    │     │  Process  │
└───────────┘     └─────────────────────┘     └───────────┘
                      (Bidirectional!)
```

### 📌 AOSP Socket Map

```
/dev/socket/zygote           ← App launching (Zygote)
/dev/socket/property_service ← System property writes
/dev/socket/logd             ← Logging daemon
/dev/socket/logdr            ← Log reader
/dev/socket/logdw            ← Log writer
/dev/socket/netd             ← Network daemon
/dev/socket/vold             ← Volume daemon
/dev/socket/installd         ← Package installer
/dev/socket/lmkd             ← Low Memory Killer daemon
/dev/socket/tombstoned_*     ← Crash dump service
```

### Architecture

```
                 ┌──────────────────────┐
                 │    Android Init       │
                 │   (creates sockets)   │
                 └──────────┬───────────┘
                            │ Creates /dev/socket/*
          ┌─────────────────┼──────────────────┐
          ▼                 ▼                  ▼
  ┌──────────────┐  ┌──────────────┐  ┌──────────────┐
  │    zygote    │  │     logd     │  │     netd     │
  │  (listening) │  │  (listening) │  │  (listening) │
  └──────┬───────┘  └──────┬───────┘  └──────┬───────┘
         │                 │                  │
  ┌──────▼───────┐  ┌──────▼───────┐  ┌──────▼───────┐
  │ system_server│  │    logcat    │  │  ConnService │
  │   (client)   │  │   (client)   │  │   (client)   │
  └──────────────┘  └──────────────┘  └──────────────┘
```

### Server (C)

```c
// socket_server.c
#include <stdio.h>
#include <string.h>
#include <unistd.h>
#include <sys/socket.h>
#include <sys/un.h>

#define SOCKET_PATH "/dev/socket/my_service"
#define BUFFER_SIZE 256

int main() {
    int server_fd, client_fd;
    struct sockaddr_un addr;
    char buffer[BUFFER_SIZE];

    server_fd = socket(AF_UNIX, SOCK_STREAM, 0);

    memset(&addr, 0, sizeof(addr));
    addr.sun_family = AF_UNIX;
    strncpy(addr.sun_path, SOCKET_PATH, sizeof(addr.sun_path) - 1);

    unlink(SOCKET_PATH);
    bind(server_fd, (struct sockaddr *)&addr, sizeof(addr));
    listen(server_fd, 5);
    printf("Server: Listening on %s\n", SOCKET_PATH);

    while (1) {
        client_fd = accept(server_fd, NULL, NULL);
        ssize_t n = read(client_fd, buffer, BUFFER_SIZE - 1);
        buffer[n] = '\0';
        printf("Server: Received '%s'\n", buffer);

        const char *response = "OK: Message received!";
        write(client_fd, response, strlen(response));
        close(client_fd);
    }

    close(server_fd);
    unlink(SOCKET_PATH);
    return 0;
}
```

### Client (C)

```c
// socket_client.c
int main() {
    int fd;
    struct sockaddr_un addr;
    char buffer[BUFFER_SIZE];

    fd = socket(AF_UNIX, SOCK_STREAM, 0);

    memset(&addr, 0, sizeof(addr));
    addr.sun_family = AF_UNIX;
    strncpy(addr.sun_path, SOCKET_PATH, sizeof(addr.sun_path) - 1);

    connect(fd, (struct sockaddr *)&addr, sizeof(addr));

    const char *message = "Hello Server! Set brightness to 50%";
    write(fd, message, strlen(message));

    ssize_t n = read(fd, buffer, BUFFER_SIZE - 1);
    buffer[n] = '\0';
    printf("Client: Got response '%s'\n", buffer);

    close(fd);
    return 0;
}
```

### init.rc Socket Declaration

```rc
# In init.rc or service-specific .rc file
service my_daemon /system/bin/my_daemon
    class  main
    user   system
    group  system
    socket my_service stream 0666 system system
    #      ^name       ^type  ^perm ^user  ^group
```

> `init` will: create `/dev/socket/my_service`, set permissions, and pass the fd to `my_daemon` at startup.

## 5. 📊 Virtual Filesystems (procfs / sysfs / debugfs)

**Concept:** No data stored on disk — these are **windows into the kernel**, exposing live system state as readable (and sometimes writable) files.

```
                        KERNEL
  ┌─────────────┐   ┌─────────────┐   ┌─────────────┐
  │  Process     │   │   Device    │   │   Debug     │
  │  Info        │   │   Drivers   │   │   Info      │
  └──────┬───────┘   └──────┬──────┘   └──────┬──────┘
         │                  │                  │
    ┌────▼────┐       ┌──────▼────┐     ┌──────▼─────┐
    │ /proc/  │       │  /sys/    │     │ /sys/kernel│
    │ (procfs)│       │  (sysfs)  │     │   /debug/  │
    └────▲────┘       └──────▲────┘     └──────▲─────┘
         │                   │                  │
         └───────────────────┴──────────────────┘
                    Userspace reads/writes
                    these like normal files
```

### /proc — Key Files

```
/proc/meminfo              ← Memory stats (used by ActivityManager)
/proc/stat                 ← CPU statistics
/proc/[pid]/oom_adj        ← OOM killer priority (used by LMKD)
/proc/[pid]/oom_score_adj  ← OOM score adjustment
/proc/[pid]/maps           ← Memory mappings
/proc/[pid]/status         ← Process state, name, threads
/proc/[pid]/cmdline        ← Launch command
/proc/binder/stats         ← Binder transaction stats
/proc/binder/transactions  ← Active Binder transactions
```

### Reading procfs (C)

```c
#include <stdio.h>

int main() {
    FILE *f;
    char buffer[1024];

    f = fopen("/proc/meminfo", "r");
    while (fgets(buffer, sizeof(buffer), f)) printf("%s", buffer);
    fclose(f);

    f = fopen("/proc/1/status", "r");   // init process
    while (fgets(buffer, sizeof(buffer), f)) printf("%s", buffer);
    fclose(f);

    return 0;
}
```

### /sys — Key Files

```
/sys/class/power_supply/battery/
├── capacity          ← Battery % (0–100)
├── status            ← "Charging" / "Discharging" / "Full"
├── health            ← "Good" / "Overheat"
├── voltage_now       ← Voltage in microvolts
└── temp              ← Temperature

/sys/class/backlight/panel0-backlight/
└── brightness        ← Screen brightness (read/write)

/sys/class/leds/
├── red/brightness    ← LED control
├── green/brightness

```

### Read/Write sysfs (C)

```c
#include <stdio.h>
#include <fcntl.h>
#include <unistd.h>
#include <string.h>

int set_brightness(int level) {
    const char *path = "/sys/class/backlight/panel0-backlight/brightness";
    char value[16];
    int fd = open(path, O_WRONLY);
    if (fd < 0) return -1;
    snprintf(value, sizeof(value), "%d", level);
    write(fd, value, strlen(value));
    close(fd);
    return 0;
}

int get_battery_level() {
    const char *path = "/sys/class/power_supply/battery/capacity";
    char buffer[16];
    int fd = open(path, O_RDONLY);
    if (fd < 0) return -1;
    read(fd, buffer, sizeof(buffer));
    close(fd);
    return atoi(buffer);
}
```

## 6. ⚙️ System Properties

**Concept:** A **global key-value store** backed by shared memory. Any process can read; only privileged processes can write.

```
┌──────────────┐  setprop()  ┌──────────────────┐  getprop()  ┌──────────────┐
│  Process A   │ ──────────► │  Property Store  │ ◄────────── │  Process B   │
│  (writer)    │             │  (shared memory) │             │  (reader)    │
└──────────────┘             │ /dev/__properties│             └──────────────┘
```

### Architecture

```
┌──────────────────────────────────────────────────────┐
│                    Property System                    │
│                                                       │
│  ┌────────────────┐    ┌─────────────────────────┐   │
│  │  init (PID 1)  │───►│  /dev/__properties__/   │   │
│  │  (prop service)│    │  ├── properties_serial  │   │
│  └────────┬───────┘    │  ├── property_info      │   │
│           │            │  └── persistent/         │   │
│    socket: property     └───────────┬─────────────┘   │
│    _service             direct mmap │                  │
│           │                         │                  │
│  ┌────────▼────────┐         ┌──────▼──────┐          │
│  │  Privileged      │         │ Any process │          │
│  │  processes SET   │         │  can READ   │          │
│  └──────────────────┘         └─────────────┘          │
└──────────────────────────────────────────────────────┘
```

## 7. 🗺️ Memory-Mapped Files (mmap)

**Concept:** Map a file directly into virtual memory — reading/writing memory = reading/writing the file. When two processes `mmap` the same file, they **share the same memory**.

```
    Process A Virtual Memory          Physical File
  ┌────────────────────┐          ┌──────────────────┐
  │ ┌────────────────┐ │  mmap   │ /data/shared.dat │
  │ │  mapped region │◄├─────────┤►                 │
  │ └────────────────┘ │         └──────────┬───────┘
  └────────────────────┘                    │
                                   mmap     │
  ┌────────────────────┐                    │
  │ ┌────────────────┐ │                    │
  │ │  mapped region │◄├────────────────────┘
  │ └────────────────┘ │
  └────────────────────┘ Process B
        Both see the SAME data!
```

### Writer (C)

```c
// mmap_writer.c
#include <stdio.h>
#include <string.h>
#include <fcntl.h>
#include <unistd.h>
#include <sys/mman.h>

#define FILE_PATH "/data/local/tmp/mmap_shared.dat"
#define FILE_SIZE 4096

typedef struct {
    int  counter;
    char message[256];
    int  ready;   // 0 = not ready, 1 = data available
} SharedData;

int main() {
    int fd = open(FILE_PATH, O_RDWR | O_CREAT, 0666);
    ftruncate(fd, FILE_SIZE);

    SharedData *data = (SharedData *)mmap(NULL, FILE_SIZE,
                                          PROT_READ | PROT_WRITE,
                                          MAP_SHARED, fd, 0);
    close(fd);  // fd can be closed after mmap

    if (data == MAP_FAILED) { perror("mmap"); return 1; }

    data->counter = 42;
    strcpy(data->message, "Hello from mmap writer!");
    data->ready = 1;

    msync(data, FILE_SIZE, MS_SYNC);  // Flush to file
    printf("Writer: counter=%d, message='%s'\n", data->counter, data->message);

    munmap(data, FILE_SIZE);
    return 0;
}
```

### Reader (C)

```c
// mmap_reader.c
int main() {
    int fd = open(FILE_PATH, O_RDONLY);
```

## 🔐 File Locking

When multiple processes share the same file, use advisory locks to prevent race conditions:

```c
#include <fcntl.h>
#include <unistd.h>

void safe_file_write(const char *path, const char *data) {
    int fd = open(path, O_WRONLY | O_CREAT, 0666);

    struct flock lock = {
        .l_type   = F_WRLCK,    // Exclusive write lock
        .l_whence = SEEK_SET,
        .l_start  = 0,
        .l_len    = 0           // Lock entire file
    };
    fcntl(fd, F_SETLKW, &lock); // Blocking wait for lock

    // ── CRITICAL SECTION ──────────────────────
    write(fd, data, strlen(data));
    // ──────────────────────────────────────────

    lock.l_type = F_UNLCK;
    fcntl(fd, F_SETLK, &lock);  // Release lock
    close(fd);
}
```

### ⏱️ Locking Timeline

```
Process A: [─── LOCK ───][   WRITE   ][── UNLOCK ──]
                                        │
Process B:      [WAITING............][─── LOCK ───][   WRITE   ][── UNLOCK ──]
                (blocked on F_SETLKW)
```

## 🔔 inotify — File Change Notifications

Watch for file changes to make file-based IPC **reactive** (no polling needed):

```c
#include <stdio.h>
#include <sys/inotify.h>
#include <unistd.h>

int main() {
    int inotify_fd = inotify_init();
    int wd = inotify_add_watch(inotify_fd,
                                "/data/local/tmp/",
                                IN_CREATE | IN_MODIFY | IN_DELETE);

    printf("Watching /data/local/tmp/ for changes...\n");

    char buffer[4096];
    while (1) {
        int length = read(inotify_fd, buffer, sizeof(buffer));  // blocking
        int i = 0;
        while (i < length) {
            struct inotify_event *event = (struct inotify_event *)&buffer[i];
            if (event->mask & IN_CREATE)  printf("CREATED:  %s\n", event->name);
            if (event->mask & IN_MODIFY)  printf("MODIFIED: %s\n", event->name);
            if (event->mask & IN_DELETE)  printf("DELETED:  %s\n", event->name);
            i += sizeof(struct inotify_event) + event->len;
        }
    }
    close(inotify_fd);
    return 0;
}
```

# 🎫 File Descriptors (fd) — Complete Guide

---

## 🤔 What is a File Descriptor?

> **fd = a token number the kernel gives you when you open a resource.**
> You use that number for all future operations — no need to remember paths, positions, or details.

### Real-World Analogy

```
You check your coat at a restaurant.
Staff hands you a token → "47"

You don't carry the coat.
You just show "47" whenever you need it.

File Descriptor works the same way:

  Program: "Open /data/music.mp3"
  Kernel:  "OK — here's token number 3"
  Program: Uses "3" for all reads, writes, seeks, and close
```

---

## 🗂️ The fd Table

When you call `open()`, the kernel creates an entry in your process's **fd table** and returns the index:

```
Your Program                  KERNEL                     Actual File
────────────                ────────                    ───────────

open("/data/music.mp3") ──► Creates table entry    /data/music.mp3
                                    │                       │
                            ┌───────▼──────────┐           │
                            │    fd Table       │           │
                            │  ┌─────┬────────┐│           │
                            │  │ fd  │ Target ││           │
                            │  ├─────┼────────┤│           │
                            │  │  0  │ stdin  ││           │
                            │  │  1  │ stdout ││           │
                            │  │  2  │ stderr ││           │
                            │  │  3  │ ───────┼┼──────────►│
                            │  └─────┴────────┘│
                            └──────────────────┘
                                    │
◄─────────── returns 3 ─────────────┘

read(3, buffer, 100)  ← read from music.mp3
write(3, data, 50)    ← write to music.mp3
close(3)              ← release the token
```

## 0️⃣1️⃣2️⃣ The Three Built-in fds

Every process starts with these three already open:

| fd | Name | Purpose |
|----|------|---------|
| `0` | **stdin** | Read user keyboard input |
| `1` | **stdout** | Print normal output |
| `2` | **stderr** | Print errors |
| `3+` | **yours** | Your files, sockets, pipes, etc. |

```c
printf("Hello");           // uses fd=1 (stdout) internally
fprintf(stderr, "Error!"); // uses fd=2 (stderr) internally
scanf("%d", &x);           // uses fd=0 (stdin)  internally

int fd = open("file.txt", O_RDONLY);
// fd = 3  ← first available slot
```

## 💻 Code Examples

### Example 1 — Open, Write, Close

```c
#include <stdio.h>
#include <fcntl.h>
#include <unistd.h>

int main() {
    // Step 1: open → get fd
    int fd = open("/data/local/tmp/hello.txt", O_WRONLY | O_CREAT, 0666);
    printf("fd = %d\n", fd);  // fd = 3

    // Step 2: use fd
    write(fd, "Hello World!", 12);

    // Step 3: close → release the slot
    close(fd);
    return 0;
}
```

```
Step 1: open()  → kernel creates entry → returns 3
Step 2: write(3, ...) → kernel looks up fd=3 → finds file → writes
Step 3: close(3) → kernel frees slot → fd=3 available again
```

## 🔑 fd is NOT Just for Files

This is the key insight — **fd works for everything** in Linux/Android:

| Type | How to Get It |
|------|--------------|
| 📄 Regular Files | `open("file.txt")` |
| 📁 Directories | `open("/data/")` |

| 💾 Devices | `open("/dev/video0")` |

| ⏰ Timers | `timerfd_create(...)` |

```c
read(pipe_fd[0], buffer, size);
read(device_fd,  buffer, size);
```

> **Linux philosophy: "Everything is a file"** — one uniform interface for all I/O.

## 💡 Why fd Exists

### 1 — Automatic Position Tracking

```c
// ❌ Without fd (hypothetical nightmare):
read("/data/music.mp3", buf, 100, position=0);    // caller tracks position
read("/data/music.mp3", buf, 100, position=100);
read("/data/music.mp3", buf, 100, position=200);

// ✅ With fd:
int fd = open("/data/music.mp3", O_RDONLY);  // once

read(fd, buf, 100);  // reads pos 0,   auto-advances
read(fd, buf, 100);  // reads pos 100, auto-advances
read(fd, buf, 100);  // reads pos 200, auto-advances
```

### 2 — Kernel Manages Everything

```
The kernel automatically handles:
  ✅ Current read/write position
  ✅ File locking
  ✅ Permission checks
  ✅ I/O buffering for performance
  ✅ Concurrent access from multiple processes
  ✅ Cleanup when a process dies

You just say: read(3, buf, 100)
Kernel does all the hard work.
```

### 3 — IPC via fd Sharing (The Magic)

```
Process A creates a shared memory fd
         │
         │  sends fd to Process B (via Binder / socket)
         ▼
Process B uses the same underlying resource

❌ Without fd sharing → must copy data to disk (slow)
✅ With fd sharing    → zero-copy, direct RAM access (fast)
```

### Sending fd via Unix Socket (SCM_RIGHTS)

```c
// ── SENDER ────────────────────────────────────────────────
void send_fd(int socket, int fd_to_send) {
    struct msghdr msg = {0};
    char buf[CMSG_SPACE(sizeof(int))];

    struct iovec io = { .iov_base = "FD", .iov_len = 2 };
    msg.msg_iov        = &io;
    msg.msg_iovlen     = 1;
    msg.msg_control    = buf;
    msg.msg_controllen = sizeof(buf);

    struct cmsghdr *cmsg  = CMSG_FIRSTHDR(&msg);
    cmsg->cmsg_level      = SOL_SOCKET;
    cmsg->cmsg_type       = SCM_RIGHTS;         // "I'm sending an fd"
    cmsg->cmsg_len        = CMSG_LEN(sizeof(int));
    *((int *)CMSG_DATA(cmsg)) = fd_to_send;

    sendmsg(socket, &msg, 0);
    printf("Sender: sent fd=%d\n", fd_to_send);
}
```

```c
// ── RECEIVER ──────────────────────────────────────────────
int receive_fd(int socket) {
    struct msghdr msg = {0};
    char buf[CMSG_SPACE(sizeof(int))];
    char data[10];

    struct iovec io = { .iov_base = data, .iov_len = sizeof(data) };
    msg.msg_iov        = &io;
    msg.msg_iovlen     = 1;
    msg.msg_control    = buf;
    msg.msg_controllen = sizeof(buf);

    recvmsg(socket, &msg, 0);

    struct cmsghdr *cmsg = CMSG_FIRSTHDR(&msg);
    int received_fd = *((int *)CMSG_DATA(cmsg));

    printf("Receiver: got fd=%d\n", received_fd);  // different number!
    return received_fd;
}

// Receiver reads the file WITHOUT knowing its path:
char buffer[100] = {0};
read(fd, buffer, sizeof(buffer));
printf("Read: '%s'\n", buffer);  // "Hello from sender!"
```

> **Key point:** Sender has `fd=3`, receiver gets `fd=7` — different numbers, **same underlying resource**.

## ⚠️ fd Leaks — What Happens If You Don't Close

```c
// ❌ BAD — fd leak on early return
void bad_function() {
    int fd = open("file.txt", O_RDONLY);

    if (something_failed) {
        return;   // ← fd=3 NEVER closed!
    }

    close(fd);
}

// Call 1000 times...
for (int i = 0; i < 1000; i++) bad_function();
```

```
After 1000 calls:
┌────┬──────────┐
│  0 │  stdin   │
│  1 │  stdout  │
│  2 │  stderr  │
│  3 │  file.txt│ ← leaked
│  4 │  file.txt│ ← leaked
│  5 │  file.txt│ ← leaked
│ ...│   ...    │
│1024│  file.txt│ ← LIMIT HIT!
└────┴──────────┘

Next open() → FAILS: "Too many open files"
Process may CRASH.
```

```c
// ✅ GOOD — always close
int fd = open("file.txt", O_RDONLY);
if (fd < 0) { /* handle error */ return; }

// ... do work ...

close(fd);
fd = -1;    // mark invalid — prevents accidental reuse
```

## 📋 Summary

| Topic | Key Point |
|-------|-----------|
| **What is fd?** | A small integer (3, 4, 5…) representing an open kernel resource |
| **How to get one** | `open()`, `socket()`, `pipe()`, `timerfd_create()`, etc. |
| **What to do with it** | `read(fd,…)` · `write(fd,…)` · `close(fd)` |
| **Built-in fds** | `0`=stdin · `1`=stdout · `2`=stderr |
| **fd is process-local** | `fd=3` in Process A ≠ `fd=3` in Process B (but can point to same resource) |
| **IPC superpower** | Share an fd between processes → zero-copy access to same RAM |
| **Java equivalent** | `ParcelFileDescriptor` — wraps fd for safe Binder transfer |
| **Golden rule** | **Always `close(fd)` when done** — leaks crash processes |
